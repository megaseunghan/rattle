# Rattle 앱 문구 기준 (UX 라이팅)

2026-11-17 사용자 확정. 기준 원문은 토스플레이스 UX 라이팅 가이드다: https://docs.tossplace.com/guide/front-integration/plugin/design/ux-writing.html
이 파일은 그 기준을 Rattle에 맞춰 옮긴 요약이다. 판단이 갈리면 원문을 다시 읽는다.

## 적용 범위

- 적용: 앱 화면에 보이는 모든 문구(제목, 본문, 버튼, 안내, 오류, 빈 상태, 확인창, 알림), 시안과 명세에 적는 화면 문구.
- 제외: 약관, 개인정보처리방침 등 법적 문서(`app/legal/`, 방침 보완안). 코드 주석·내부 문서·작업 보고.
- 루트 `AGENTS.md`의 「사용자 문구」 규칙(내부 오류 원문·외부 도구 이름을 보여주지 않는다)은 그대로 함께 지킨다.

## 읽는 사람

Rattle을 보는 사람은 사장님, 관리자, 파트타이머다. 바쁜 영업 중에 같은 화면을 하루에도 여러 번 본다. **여러 번 봐도 헷갈리지 않는 문구**가 기준이다. 매장폰 스캐너처럼 서서 한 번 보고 지나가는 화면은 **3초 안에 읽히는 문구**가 기준이다.

## 규칙

| 규칙 | 이렇게 쓰지 않는다 | 이렇게 쓴다 |
|---|---|---|
| 모든 문구는 해요체 | 저장이 완료되었습니다 / 확인 바랍니다 | 저장했어요 / 확인해주세요 |
| 사용자가 한 일을 능동형으로 | 요청이 접수되었어요 | 요청했어요 |
| 완료 제목은 명사로 끝내지 않는다 | 출근 완료 | 출근했어요 |
| 안 되는 것만 말하지 않고 할 수 있는 일을 알려준다 | 승인 권한이 없어요 | 사장님에게 요청해주세요 |
| 오류는 코드·시스템 용어를 빼고 다음 행동을 말한다 | 네트워크 오류 / 저장 실패 | 인터넷이 불안정해요. 잠시 후 다시 해주세요 |
| 지나친 경어를 쓰지 않는다 | 삭제하시겠어요? / 등록되어 계신가요? | 삭제할까요? / 등록했나요? |
| 명사를 세 개 이상 잇지 않고 동사로 푼다 | 출퇴근 기록 정정 요청 내역 | 정정 요청한 기록 |
| 버튼은 누르면 일어나는 일을 쓴다 | 확인 / 조회 | 정정 요청하기 / 기록 보기 |
| 한 화면의 버튼은 형태를 통일한다 | 승인하기 / 반려 / 기록 조회 | 승인하기 / 반려하기 / 기록 보기 |
| 확인창의 왼쪽 버튼은 `닫기` | 취소 | 닫기 |
| 거절 선택지도 편하게 고를 수 있게 | 등록하기 / 등록 포기하기 | 등록하기 / 다음에 할게요 |
| 같은 대상은 한 가지 말로 | 휴대전화 / 전화번호 / 핸드폰 | 휴대폰 번호 |
| 금액 | ₩10,000 / 10,000 원 | 10,000원 |
| 날짜 | 9/1 (월) | 9월 1일(월) |
| 순서를 기호로 쓰지 않는다 | 요청 → 승인 | 요청하면 사장님이 승인해요 |
| 이모지를 쓰지 않는다 | | |

- 사람을 부를 때는 `사장님`, `[이름]님`을 쓴다. `고객님`, `사용자`를 쓰지 않는다.
- 장소는 `매장`으로 쓴다.
- 확인창에서 `취소`는 "하던 작업이 취소된다"로 읽힐 수 있다. 하던 작업을 실제로 취소하는 버튼이 아니면 `닫기`를 쓴다.

## Rattle에서 특히 조심할 것

- 저장 여부를 모르는 상태를 성공이나 실패로 쓰지 않는다. 예: "저장됐는지 확인하고 있어요".
- 삭제처럼 되돌릴 수 없는 일은 무엇이 함께 지워지는지와 되돌릴 수 있는 기한을 말한다.
- 금액·날짜·시간은 표기 규칙을 따르되 숫자 서체 토큰(Geist)은 `DESIGN.md`를 따른다.
- 기존 화면의 문구를 이 기준으로 바꾸는 일은 과제로 지정됐을 때만 한다. 지나가다 고치지 않는다.
