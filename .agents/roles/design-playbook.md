# Rattle 화면 설계 플레이북 (사용자 확정 취향 · 2026-11-20)

시안·앱 화면을 만들 때 **처음부터 이 기준으로** 만든다. `DESIGN.md`(토큰·컴포넌트)와 충돌하면 이 문서가 화면 구성 기준이고, 색·서체·간격 값은 `DESIGN.md` 토큰을 쓴다. 새 피드백이 확정되면 이 문서에 한 줄로 추가한다.

## 1. 전체 인상
- **모던하고 실용적**: 넉넉한 여백(카드 안쪽·섹션 사이), 둥근 모서리, 큰 제목, 옅은 그림자, 얇은 구분선, 관련 정보는 카드로 묶기.
- **내용이 먼저 보인다**: 상단 컨트롤은 압축하고 목록·내역이 첫 화면에 최소 2건 보이게(375×720 기준, 측정값 기록).
- 장식·과장·가짜 성과 지표 금지. 미완성 기능은 숨긴다('준비 중' 노출 금지).

## 2. 글은 최소로
- 상시 설명 문장 금지. 라벨·숫자·상태로 말한다. 꼭 필요하면 **한 줄**.
- 계산 기준 등 부연은 짧은 라벨(예: '기간 합계') + ⓘ 눌러 펼치는 도움말로.
- 오류·확인 필요처럼 **사용자가 행동해야 하는 안내만** 화면에 남긴다. 해요체, `ux-writing.md` 준수.
- 기능 원리 설명(예: OCR이 어떻게 읽었는지) 대신 **결과를 바로 보여준다**(예: 인식 결과를 '항목 | 금액' 표로).

## 3. 필터·탐색
- **1단 주 필터**: 카테고리 칩. 더 크게(약 52px 높이·16px 글자)로 주 필터임을 드러낸다.
- **2단 보조 필터**: 거래처·기간·확인 필요 등은 **탭 인디케이터 한 줄**(약 44px), 같은 높이·기준선. 건수는 라벨 옆 작은 숫자 배지(두 줄로 떨어지지 않게).
- 보조 탭을 누르면 **바로 아래에 인라인 펼침**(모달·바텀시트 금지), 펼친 상태에서도 아래 내역이 보이고 선택 즉시 반영.
- 날짜는 **캘린더 대신 기간 선택**: 빠른 범위(오늘·어제·이번 주·지난주·이번 달·지난달) + 직접 기간(숫자 입력 자동 정리).
- 불필요한 '전체' 칩 금지. 해제는 선택 칩 재탭 또는 X.
- 1단과 2단 사이만 얇은 구분선. 2단 아래 전체 폭 선은 두지 않는다. 선택 인디케이터 밑줄은 유지.
- 선택된 조건은 결과가 0건이어도 화면에 남긴다(숨은 필터 금지).

## 4. 입력 화면
- 시작할 때 **방식을 먼저 고른다**(예: 매입 [품목별 | 금액별]). 사진은 증빙 첨부(앨범·촬영·파일).
- **한 화면 폼 + 하단 고정 합계·저장**. 단계 쪼개기 최소화.
- 금액이 기준값: 수량·단위는 선택 입력, 수량을 바꿔도 금액은 유지(단가만 재계산).
- 드롭다운은 기존 값 선택 + 그 자리에서 새로 만들기(예: 거래처).
- 키보드가 입력란·검색 결과·저장 버튼을 가리지 않는다. 뒤로가기·이탈 시 입력 보존·확인.
- 저장 후에는 들어온 화면으로 자연스럽게 돌아가고 목록만 갱신(앱 재시작처럼 보이는 전환 금지).

## 5. 기록·일정 성격의 데이터
- 월 단위 한 번 입력보다 **일 단위 입력 + 누락·중복 방지**(미입력 표시·바로 입력, 같은 날 재입력은 수정으로 유도, 휴무·0원 확인 구분). 미입력을 0원으로 합산하지 않는다.

## 6. 미디어
- 사진 크게 보기는 위·아래 스와이프나 바깥 탭으로 닫힌다(확대 중에는 닫히지 않음).

## 7. 진행 방식 (매번 동일)
1. 새 화면·큰 변경은 사용자가 말하지 않아도 **시안 먼저**(상태별 넘겨보기 포함) → UI-UX 검토 → 사용자 확인.
2. 사용자에게는 **이 플레이북을 이미 반영한 시안**을 보여준다. 첫 시안부터 위 항목 체크리스트를 design-state에 표시.
3. 확정 시안대로 구현 → **시뮬레이터에서 실제 흐름을 끝까지 눌러 녹화·스크린샷**으로 확인 → 그 뒤에만 실기기 설치 요청.
4. 사용자 확인은 '시안 확인'과 '최종 앱 확인' 두 번만.
