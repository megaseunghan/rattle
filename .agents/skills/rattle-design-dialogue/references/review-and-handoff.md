# Rattle 디자인 검토 기준

해당 흐름의 상태 설계, 수치 표현, 인터랙션 또는 최종 감사를 할 때 읽는다. 모든 화면에 모든 항목을 억지로 추가하지 않는다.

## 상태의 의미

| 상태 | 검토할 경계 |
|---|---|
| 최초 로딩 | 자료가 아직 없음. 저장된 0원이나 성공 상태를 꾸며내지 않음 |
| 실제 빈 자료 | 조회 성공 후 자료 없음. 오류·권한 거절과 구분 |
| 0원 | 확인된 실제 수치. 자료 없음/미확인으로 바꾸지 않음 |
| 일부 미확인 | 확인된 항목은 유지하고 계산 불가 항목과 이유를 구분 |
| 최초 조회 실패 | 기존 자료가 없는 오류·재시도. 잘못된 금액·이익률을 노출하지 않음 |
| 백그라운드 갱신 | 선택 항목과 유효한 기존 값을 보존하고 갱신 중임을 구분 |
| 갱신 실패 | 기존 자료의 의미를 유지하며 실패·재시도 표시. 블러 등 표현은 해당 시안의 승인에 따름 |
| 재시도·완료 | 중복 실행과 오래된 응답/애니메이션 차단, 최종 값·선택·위치 일치 |
| 권한 없음 | 빈 자료로 위장하거나 개발 미리보기로 실제 권한 검증을 대체하지 않음 |

## 수치·차트

- 날짜 범위·누적/일별·비율의 분모를 정의한다. 같은 화면의 비교는 같은 기준으로 읽히게 하고, 다른 기준을 쓰면 구분한다.
- 전월 미존재, 전월 0원, 전월 조회 실패는 다르다. 퍼센트 칸을 유지하더라도 계산 불가는 `—%` 등으로 표시하고 0%·무한대·가짜 수치를 만들지 않는다.
- 보기 좋게 축을 조정해도 두 시리즈는 같은 축을 쓴다. 축 단위를 금액과 혼동하지 않도록 하고 음수를 잘라내지 않는다.
- 시안의 가상 일별 기록을 실제 인건비 배분·매출 집계로 이식하지 않는다. 실제 일별 데이터의 가용성을 확인한 뒤 연결한다.
- 강한 스무딩은 추세 표현임을 구분한다. 선택 금액·증감·접근성 설명은 실제 관측값을 사용하고, 장식 곡선을 정확한 일별 기록이라고 설명하지 않는다.
- 숫자 롤링은 최종 값, 쉼표·부호·통화 위치, 빠른 재선택, 음수·자리 수 변화·미확인 값을 확인한다. 종료 시 일반 텍스트로 바꿔 수평 위치가 튀지 않게 한다.

## 터치·모션·가독성

- 슬라이드 선택 배경의 **현재 위치**와 글자 대비를 확인한다. 도착 전 흰 글자가 흰 바탕에 먼저 나타나는지 중간 프레임도 본다.
- 터치 팝오버는 가장자리·손가락·강조점을 피하는지, 누름/이동/해제/취소와 스크롤이 충돌하지 않는지 확인한다. 키보드 대체와 접근성 이름도 검토한다.
- 본문은 4.5:1, 큰 글자·의미 있는 그래프선·포커스는 3:1 이상을 기준으로 실제 배경과 계산한다. 색 이외에도 부호·라벨·선 형태로 의미를 전달한다.
- 승인된 글래스·면적·슬라이드 자체를 AI Slop으로 판정하지 않는다. 불필요한 중첩·대비 손실·지나친 일렁임이 실제로 있는지 본다.
- `prefers-reduced-motion`과 투명도 줄이기/지원 불가 대체를 관련 환경에서 확인한다. 보조기술 확인 없이 전체 접근성 통과라고 하지 않는다.
- 네이티브 햅틱은 최초 누름/날짜 변경 등 발생 조건을 결정 파일에 기록한다. 웹 데모로 진동 구현을 완료했다고 보고하지 않는다.

## Nielsen H1~H10의 Rattle 적용

1. **상태 가시성:** 최초 로딩·갱신·저장/조회 성공·실패가 구분되는가.
2. **현실과 일치:** 매장 업무 용어·날짜·금액·계산 기준이 맞는가.
3. **사용자 제어:** 닫기·뒤로·선택 해제·취소·작성값 보존이 있는가.
4. **일관성:** 기존 공통 토큰·역할·같은 기능의 표현이 맞는가.
5. **오류 예방:** 중복 클릭·잘못된 기간·지연 응답·미확인 금액을 막는가.
6. **기억 부담 감소:** 선택 상태와 비교 대상이 보이는가.
7. **효율:** 모바일에서 잦은 업무가 적은 조작으로 가능한가.
8. **간결함:** 판단에 필요 없는 설명·장식·반복 위계가 없는가.
9. **오류 진단·복구:** 실패 원인·기존 값의 유효성·재시도를 이해할 수 있는가.
10. **도움말:** 필요할 때 부족한 자료·다음 조치를 짧게 확인할 수 있는가.

검토 기록은 영향을 받은 원칙과 실제 근거만 요약한다. 해당 없는 항목은 이유를 남기고, 10개를 매 턴 사용자에게 긴 표로 제시하지 않는다.

## 확정 인수인계

한 개의 `design-state.md`에 다음을 합쳐 갱신한다. 고정 날짜·샘플 금액은 실제 구현 계약과 분리한다.

- 목표와 대상 화면 ID, 현재 소스 기준 및 기존 변경
- 확정한 배치·문구·색·동작·상태, 미결정 사항
- 산출물 위치·링크·실행 방법, 임시 파일 여부
- 검증 명령/방법·환경·결과, 관찰한 한계
- 앱 반영 여부, 실제 데이터 계약·네이티브 전용 미구현 항목

사용자가 더 수정할 것이 없다고 했고 필수 결정과 검증이 끝났다면 종료한다. 이 시점의 “다음”은 새 디자인 질문을 지어내는 것이 아니라, 시안 확정 결과와 남아 있는 구현 경계를 알리는 것이다.
