## Android 빌드 기준

- 로컬 feature/operations-workflows / HEAD 679c07593f8f8acd41528d94883a01202bcb7677 + 기존 다수 dirty 및 untracked 변경.
- 기존 Medium_Phone / sdk_gphone16k_arm64 / Android API 37 에뮬레이터. 최초 이 에뮬레이터에 Rattle 설치 없음.
- 표준 Gradle 9 실행은 Foojay 0.5.0의 IBM_SEMERU 참조로 실패. 이번 캡처 빌드는 /private/tmp/rattle-android-capture.init.gradle의 beforeSettings plugin resolutionStrategy로 Foojay 1.0.0을 지정한다. node_modules·Gradle wrapper·앱 의존성 버전은 수정하지 않았다. 이 설정은 임시 실행 파일이므로 기본 명령의 영구 수정이 아니다.
- 실행 명령: ./gradlew :app:assembleRelease -PreactNativeArchitectures=arm64-v8a --init-script /private/tmp/rattle-android-capture.init.gradle --console=plain
- 빌드 로그: /private/tmp/rattle-android-capture-build.log. API·인증정보 값은 공유하지 않는다.
- 에뮬레이터 실제 해상도 조회: 1080×2400. 소개 PNG는 원본 화면을 축소 배치한 1080×1920의 9:16 캔버스로 준비했다.
- CUA에서 실행 중인 Qt 에뮬레이터를 앱 이름·실행 경로로 선택할 수 없어, 사용자에게 ADB 기반 화면 이동·캡처 사용 선택을 요청했다. 답변 전에는 ADB UI 입력을 하지 않았다.

첫 Release 빌드는 15분 2초에 성공했고 에뮬레이터 설치 Success를 확인했다. 산출물 SHA-256 1adb254d92a5073babf66fa7908b25001f4f3a50ebe1fe14726cd8134dde0c0c. 그러나 생성된 Android 네이티브 설정이 오래되어 applicationId가 com.rattle이며 OAuth 복귀용 rattle scheme이 없었다. 첫 APK를 스토어용 빌드 또는 화면 검증 완료로 취급하지 않는다. 초기 설치 여부는 com.seunghan.rattle만 확인했으므로 com.rattle 기존 자료 여부는 미확인이다. 기존 com.rattle 앱/자료를 삭제하지 않는다.

android/는 .gitignore로 제외된 생성물이다. android/app/build.gradle의 applicationId만 com.seunghan.rattle로 맞추고 namespace와 Kotlin 패키지 com.rattle은 유지했다.
