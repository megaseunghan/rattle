# 직원 급여 변경·파트타이머 일별 근무 적용 안내

## 상태

앱 코드·SQL 구현 및 로컬 테스트 완료. 원격 SQL 미적용, 수정 앱 실기기 미배포.
시뮬레이터 제어가 `Sky Computer Use native pipe startup failed`로 실패하여 이번 새 급여 UI의 네이티브 전후 조작은 미검증이다. 기존 설치본에 새 기능이 반영됐다고 간주하지 않는다.

## Supabase에서 SQL 적용을 진행해줘

SQL Editor에서 아래 순서대로 전체 실행한다.

1. `supabase/migrations/20261027010000_wage_effective_baselines.sql`
2. `supabase/migrations/20261027011000_daily_work_snapshots.sql`

두 파일 모두 아직 원격 미적용이다. 적용 뒤 새 앱 빌드·설치와 실제 계정/화면 검증이 필요하다. 앱보다 서버를 먼저 적용한다. 기존 출퇴근 기능을 다시 만들지 않는다.

첫 파일은 입사일 최초 급여가 없으면 가장 이른 급여 이력을 입사일에 보완하고, 이력이 전혀 없으면 등록된 현재 급여를 최초 조건으로 보관한다. 기존 월 급여 명세 금액은 수정하지 않는다. 이는 이번 사용자 승인에 따른 새 정책이다. 입사일이 없는 기존 직원은 등록일 기준으로 임시 계산하며 직원 정보에서 입사일 보완을 안내한다.

## 반영 내용

- 직원: 최초 급여는 입사일부터 적용, 이후 금액·비과세·변경일을 이력으로 보존. 별도 급여 조건 확인 단계를 제거하고 급여 변경으로 통합.
- 신규 월 명세에 날짜별 월급·비과세·적용 계수를 스냅샷으로 저장. 현재 월 누적은 오늘까지 계산하며 과거 명세는 원본 금액 유지. 기존 명세는 현재 월에 한해 일수 비례 추정임을 구분.
- 이미 작성된 월 명세를 다른 관리자의 신규 계산으로 덮어쓰지 않도록 신규 저장 중복 거절.
- 파트타이머: 날짜별 실근무 분(0~1440)을 입력. 저장 시 해당 날짜의 시급과 `round(분 × 시급 / 60)`을 기록. 월 세전액은 일별 반올림 금액의 합계.
- 이후 시급 변경은 이미 저장된 날의 시급을 덮어쓰지 않음. 시간 수정에도 당시 시급 유지. 작성·수정·확인 이력 보존.
- 직원 제출 → 관리자 확인/반려 → 월 급여 반영 → 정산 확정 구분. 관리자의 직접 입력은 확인 완료로 저장. 근무 기록 변경은 정산 확정을 해제하되 기존 월 명세 금액은 명시적으로 반영하기 전까지 유지.
- 기존 월 총시간 제출은 원본 유지, 임의로 날짜별 분할하지 않음.
- 고용형태가 바뀌었거나 퇴사·계정 연결이 해제된 직원의 저장 명세도 합계에 한 번만 포함.

## 검증

전체 Jest 77 suites / 465 tests 통과 후, 최종 고용형태 전환 중복 합산 보완의 관련 2 suites / 23 tests 추가 통과. TypeScript·diff 검사 통과.
기존 SQL 검사와 신규 정규직 SQL·일별 SQL(30개), 실제 구성원 권한 함수 기반 통합 SQL(42개) 로컬 PGlite 검사 통과. 코드 리뷰와 보안 리뷰 승인. 원격 DB/실제 JWT/동시 트랜잭션·실기기 조작 검증을 대체하지 않는다.
