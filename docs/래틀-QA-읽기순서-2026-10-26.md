# 래틀 화면 명세·E2E 검증 산출물

1. [전체 화면 기능 명세](전체화면-기능명세-2026-10-26.md): 41개 라우트, 화면 ID, 권한·입력·상태·부작용.
2. [E2E 시나리오](E2E-시나리오-2026-10-26.md): 화면별 정상흐름과 중복·취소·중단·통신·역순응답·권한 변형.
3. [QA 실행 결과](QA-실행결과-2026-10-26.md): 실제 통과/실패/미실행/차단, 테스트 데이터, 플랫폼·빌드 한계.
4. [프론트·UX 검토](프론트UX-검토-2026-10-26.md), [서버·DB 검토](서버DB-검토-2026-10-26.md): 독립 에이전트의 코드 근거와 불일치.

기계 판독 목록은 `screen-manifest-2026-10-26.json`, 증거 요약은 `qa-evidence/2026-10-26/`다. 새 테스트는 `__tests__/hooks/useConfirmLeave.test.ts`이며 네이티브 E2E가 아닌 navigation 계약 테스트다.

저장소 루트에서 명세 누락 확인:

```sh
node scripts/validate-screen-coverage.mjs
```

앱이 실제 DB로 연결되는 E2E는 실행 보고서의 재개 조건을 충족한 뒤 전용 QA 매장에서만 진행한다.

5. [네이티브 실제 실행 기록](네이티브-E2E-기록-2026-10-26.md): 전용 QA 데이터와 화면별 정상/오류/취소 검증 결과.
