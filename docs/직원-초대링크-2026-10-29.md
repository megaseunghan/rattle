# 직원 참여코드 전환

> 적용 상태 · 2026-10-29: 사용자가 `20261029010000_store_invites.sql`과 `20261029011000_store_invite_codes.sql`을 Supabase에 적용했다고 알렸다. 설치된 앱에서 참여코드 발급/조회 RPC의 실제 동작을 확인했다. 원격 함수 본문 전체 대조는 미실행이다.

관리자는 멤버 관리에서 참여코드를 공유한다. 기본 공유 메뉴에서 카카오톡 채팅방 등을 직접 선택한다. 앱이 자동 발송하지 않는다. 유효한 코드를 재사용하고, 만료되면 새 코드를 발급한다. 코드는 발급 후 7일간 유효하다.

직원은 래틀 앱의 **기존 매장 참여**에서 16자리 코드를 입력한다. 하이픈은 생략할 수 있다. 서버가 매장명을 확인한 뒤 온보딩 질문을 시작한다. 제출은 승인 대기로만 저장되며 관리자 최종 합류 전에는 직원 기록·급여에 반영되지 않는다.

`docs/invite.html`은 링크를 앱에 전달하려던 웹 안내 페이지였다. 코드 입력 방식에는 필요 없어 삭제했다. 기존 링크 RPC는 설치된 구형 앱과의 호환을 위해 유지한다.

## 적용·검증

1. 기존 초대 링크 SQL 적용 후 `supabase/migrations/20261029011000_store_invite_codes.sql`을 적용한다.
2. 새 앱을 빌드·설치한다. SQL 적용 전에는 코드 RPC가 없어 생성·조회가 실패한다.
3. 관리자 계정에서 코드 공유 → 다른 직원 계정에서 코드 입력·매장명 확인 → 신청 → 관리자 최종 합류를 확인한다. 만료·취소 코드와 비관리자 발급도 확인한다.

사업자번호는 참여 입력에 요구하지 않으며 Toss POS 연결용 매장 정보로는 남는다.
