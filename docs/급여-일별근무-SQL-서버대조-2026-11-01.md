## 2번으로 넘기는 권한 확인 사항

- **우선 확인: 급여 이력의 잔여 TRUNCATE ACL.** `employee_wage_history`의 원격 ACL은 anon/authenticated에 `rDxtm`을 부여하고 있다. `D`는 TRUNCATE이며 위 INSERT/UPDATE/DELETE 회수 확인과는 별개다. 따라서 이 테이블 전체를 “직접 쓰기 불가” 또는 “자료 보존 권한 검증 완료”로 표현하지 않는다. 외부 실행 가능성은 미검증이며, 삭제 명령으로 시험하지 않는다. 2번에서 노출 경로와 잔여 권한을 검토하고 필요한 회수 변경을 별도 승인 범위로 준비한다.

- `validate_regular_snapshot()`는 로컬에 EXECUTE 회수문이 없고 현재 anon/authenticated EXECUTE가 true다. 반환형이 trigger인 내부 함수이며 이 플래그만으로 일반 업무 RPC처럼 실행 가능하거나 취약하다고 판정하지 않는다. 2번에서 노출 의도·직접 호출 거부를 확인하고 필요하면 권한 최소화 변경을 별도로 검토한다.
- `employee_wage_history`는 anon SELECT ACL이 true지만 RLS가 활성이다. ACL만으로 실제 급여 조회 허용이라고 판정할 수 없다. 2번에서 정책·실제 익명/본인/타인/타매장 접근을 검사한다.
- 일반 사용자에게 EXECUTE가 있는 RPC의 내부 역할 검사와 RLS는 실제 직원 JWT로 검증하지 않았다. 관리자 연결로 메타데이터를 읽은 결과와 구분한다.

## 하지 않은 작업과 후속

- 원본 SQL 재실행, 추가 migration, 원격 권한 변경, migration 이력 수동 등록, 급여 조건/일별 기록/기존 명세 변경 없음.
- 기존 명세 금액 보존과 입사일 기준 이력 보정 DML 실행 결과는 전후 자료/업무 데이터 대조를 수행하지 않아 미검증이다.
- 역할별 권한/정상 일별 조회 및 저장/동시 변경/승인·반영·정산은 후속 검증이다.
- 기록에 없는 배포 시각이나 적용자를 추정해서 확정하지 않는다. migration 등록 정리는 실제 배포 이력과 대상 파일을 확인한 후 별도 작업으로 진행한다.
- 다음 순차 작업: **2번 — 레시피·재고·재무와 연결 급여의 실제 역할별 권한 검증.** 사용자 ‘다음’ 요청 전 자동 착수하지 않는다.
