# Rattle UX 하네스 재검증 · 2026-10-26

## 범위와 상태

사용자 요청: 기존 UX 하네스의 핵심 업무를 실제 앱에서 점검하고, UI 문제는 바로 수정해 반영한다. 추가 확인으로 **운영 자료를 변경하지 않는다**고 확정했다.

승인된 탐색·블루 배경·컴포넌트별 표면·Wanted Sans/Geist·드래그 FAB를 유지했다. 새 설계 인터뷰나 HTML 시안으로 대체하지 않고 실제 React Native 앱을 사용했다. 네이티브 화면에서의 저장 버튼은 누르지 않았다. 서버 SQL·급여·근무시간 제출·매입·재고 쓰기를 수행하지 않았다.

## 발견과 반영

| 항목 | 근거 | 반영 |
|---|---|---|
| 최종 검토의 개별 수정 후 단계 반복 | 급여 적용일 수정 후 금액 단계가 다시 나오는 것을 설치된 앱에서 재현. 매입도 코드와 실제 폼 대조 | 급여·매입에 검토 편집 상태 추가. `검토로 돌아가기`로 바로 복귀하며 최종 저장 전 전체 검증은 유지 |
| 수정 버튼이 비활성처럼 보임 | 급여 검토의 회색 텍스트 버튼을 수정 전 앱에서 관찰 | 공통 텍스트 Button을 `Colors.action`으로 변경. 보조 버튼의 실제 비활성 상태는 opacity로 구분 |
| 품목 삭제를 아이콘 이름으로 읽음 | 매입 품목 세 개의 닫기 아이콘 접근성 이름이 글리프만 노출 | 품목명을 포함한 삭제 이름, 품목 추가 이름, 유형의 라디오 선택 상태 추가 |
| 직원 제출의 키보드·필수 항목 안내 부족 | 실제 화면과 별도로 코드 대조에서 확인 | KeyboardAvoidingView와 고정 제출 영역, 필수 입력 표시, 필드 오류, 분→시간 환산 표시 |
| 재조회 중 작성값 손실 가능 | 제출 hook가 조회 시작 때 rows를 비우고, 기존 화면 effect가 latest 변경 때 입력을 재설정 | 대상 사용자·직원·월별 최초 조회에만 입력을 채움. 이후 조회·실패·복구에서 작성 중인 값 유지 |
| 제출 연타와 성공 후 재조회 실패 구분 | 저장/조회 호출 순서와 hook 반환 계약 대조 | 즉시 ref 잠금, 제출 성공 기준값 보관, 동일 내용 제출 완료 상태, refetch 성공/실패 boolean 반환과 별도 안내 |

직원 제출 폼의 키보드와 고정 버튼은 코드 반영·컴포넌트 테스트까지다. 실제 파트타이머 계정에서 입력 화면을 확인한 것으로 보고하지 않는다. VoiceOver 낭독, 큰 글자, 다른 화면 크기, Android, 실제 iPhone, TestFlight도 이번 검증에 포함하지 않았다. 소프트웨어 키보드 표시를 켜서 확인했고 하드웨어 키보드만 사용한 화면을 키보드 검증으로 세지 않았다.
