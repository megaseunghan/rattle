## 계약

- `save_daily_work(employee,date,minutes,note,revision)`는 본인 파트타이머 또는 매장 관리자만 가능. 날짜별 0~1,440 정수 분. 미래·입사 전·입사일 미등록 차단. 본인은 pending, 관리자는 approved 저장.
- 신규 날짜는 변경일 기준 급여 이력의 시급 사용. 기존 날짜의 시간 수정은 저장 당시 시급 유지. 시급을 현재값으로 다시 조인해 과거 일급을 바꾸지 않는다. 날짜별 원 단위 반올림 후 월 합산.
- `review_daily_work(id,revision,status,note)`는 관리자만 가능. pending 최신 revision만 확인/반려. 반려 사유 필수.
- 모든 일별 작성/수정/확인의 이전·이후 JSON과 계정을 별도 감사 이력에 보존. 일별 표의 직접 쓰기·삭제는 authenticated 권한에 없음.
- `apply_daily_payroll(employee,month,snapshot,calculated,revision)`는 관리자만 가능. 직원 행 잠금 → 월 명세 revision 확인 → 일별 source revision/상태/합계 대조 → 명세 갱신. 확인 대기/반려가 있으면 중단.
- 기존 월 합계 명세는 일별 기록만 입력해서 바뀌지 않는다. 사용자가 월 반영을 명시 실행할 때만 갱신하고, 기존 `payroll_work_history` 트리거가 원본을 보존한다. 일별 수정/재제출은 명세 금액을 유지하면서 정산 확정을 해제한다.
- `payroll.daily_work_snapshot`이 일별 방식의 식별자. `applied_hourly_wage`는 여러 시급을 평균 내지 않으므로 NULL. `work_source='manual'`은 기존 제약과 호환.
- `calculatePayroll`의 exact gross override(통합 담당자 변경)를 사용해 합산 세전액에 기존 공제 로직을 적용한다. 세법/보험 비율 변경은 없음.
- 직원 월 합계 제출 화면은 이력 조회 전용으로 보존. 기존 승인된 월 합계의 관리자 적용 경로는 남아 있으며 일별 급여를 구형 저장으로 덮어쓰는 서버 경로는 차단한다.
