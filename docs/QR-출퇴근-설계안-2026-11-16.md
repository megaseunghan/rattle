### 기존 정책과 맞물리는 규칙

- **16시간:** 출근 후 정확히 16시간까지 자동 퇴근 짝/근무일 귀속 범위에 포함한다. 초과 열린 근무는 이전 누락·확인 필요로 남기고 다음 스캔을 새 출근으로 판단하는 기존 경계를 유지한다. 이를 확인된 퇴근이나 16시간 인정분으로 자동 변환하지 않는다.
- **종류 변경 (2026-11-19 확정):** `change`에서 출근↔퇴근 변경을 허용한다. 재출근과 별개다. 원본 불변·요청/승인 권한은 유지하고 시간상 앞뒤 기록을 건너뛰지 않으며, 새 짝은 인접한 반대 종류·16시간 이내로 재구성한다. 같은 시각은 원본 event_order 계보로 순서를 보존한다. 시간만 바꾸는 기존 명시 짝 정책은 유지한다. 종류가 바뀐 계보의 과거 명시 짝은 새 짝을 덮어쓰지 않는다.
- **정정 승인:** 원본 불변·전후 스냅샷, 요청/승인 양쪽 순서 검증, 출근 날짜 변경 시 짝 퇴근 시각 보존·work_date 이동, 야간 종료+10분 초과 표시를 유지한다. 승인된 유효 기록의 확인 필요 해제는 원본 flags 삭제가 아니다. 여러 근무 중 정확한 대상/짝을 구분해야 한다.
- **일별 근무:** 날짜별 출퇴근 경과 분·당시 시급·세전액 스냅샷을 보존하고 `round(일별 분 × 당시 시급 / 60)`을 월 합산한다. 같은 날 여러 근무를 날짜별 합계로 다루되 중복 합산하지 않는다. 출시 전 개발 DB에는 기존 수동 제출 자료가 없으므로 전환·보존 설계 없이 새 방식으로 시작한다(QR-A03). 이는 운영 데이터 삭제나 DB 전체 초기화 실행을 뜻하지 않는다.
- **상태 분리:** 자동 기록·제출은 관리자 확인·월 급여 반영·정산 확정과 다르다. 기존 시간/금액 변경·재제출의 정산 확정 해제와 기존 월 명세 금액 보존 정책을 유지한다. 정규직은 출퇴근해도 월급 계산을 유지한다. 자동 기록 적용 대상은 앱 역할명만으로 판정하지 않고 고용형태와 연결해야 한다.
- **미입력/0분:** 퇴근 누락·인정분 미확인·조회 실패는 0분이 아니다. 서버에서 확인된 0분과 기록 없음은 따로 표시한다. 확정된 퇴근은 인건비 기록 실패·모달 닫기로 취소하지 않는다.

### 서버 계약 · QR 자동 인건비 (2026-11-18, DBA 구현)

**현재 계약(2026-11-18 추가 결정):** 조정자 인계 기준 원격은 `20261118130000_scanner_pairing.sql`까지 적용 완료이며 `20261118120000_qr_attendance_daily_work.sql`을 포함한 적용본은 보존한다(이번 원격 재조회 없음). 관리자 확인 대기를 제거하는 새 `20261118140000_attendance_auto_apply.sql`과 홈·손익 연결 `20261118150000_daily_work_labor_read_models.sql`은 로컬 구현·원격 미적용이다. 이 세 파일이 QR-A02/A04/A05의 현재 서버 기술 계약이다. 기능 화면·실서버·실제 동시 트랜잭션 검증을 뜻하지 않는다. 대상은 연결된 직원의 `employment_type=part_time`이며 **PT 점장도 포함**한다. 정규직의 월급 계산은 유지한다.

- **저장 경계:** 스캐너 퇴근/관리자 직접 기록/정정 승인 트랜잭션에서 근무별 원본 짝과 일별 기록 결과를 저장한다. 정정은 요청의 최종 승인·짝 연결 이후 재계산한다. 계산·일별 쓰기 오류는 하위 트랜잭션만 되돌리고 퇴근 원본+`failed`를 함께 커밋한다. 따라서 앱은 퇴근 저장 성공과 인건비 기록 성공을 따로 조회한다. 상위 트랜잭션 자체가 실패하면 둘 다 미저장이고, 응답 유실은 조회 전까지 **확인 중**이다.
- **멱등/동시성:** 유효 퇴근 버전 ID가 근무 원본 키, 일별 키는 직원+근무일이다. 원본 출퇴근/정정 이력은 보존한다. nonce 재시도와 새 QR의 기존60초 중복 창은 같은 punch를 반환한다. 재출근은60초 창 뒤 새 스캔으로 처리하며, 동일 직원의 스캔·정정·자동 기록 재시도는 `attendance_punch:<employee_id>` 잠금을 공유한다. 완료된 동일 원본 집합의 재시도는 일별 revision·금액·정산 상태를 바꾸지 않는다.
- **분/금액:** `floor((퇴근시각−출근시각)초/60)`을 근무별로 계산해 출근 근무일에 합산한다. 유효 시급은 기존 일별 스냅샷 우선, 없으면 해당 날짜 조건→가장 이른 조건→이력 자체가 없을 때만 직원 등록 시급이다. `round(일별 합산 분×시급/60)`을 원 단위로 기록한다. 시급 미확인은 실패이며0원/0분을 만들지 않는다. 확인된 동일 시각 짝은0분이다.
- **경계:** 정확히16시간까지 자동 퇴근, 초과 열린 근무는 새 출근·이전 누락 유지다. 일별1440분까지 허용하며 초과는 `ATTENDANCE_WORK_DAY_LIMIT` 실패로 남겨 원본을 보존한다(잘라서 성공 처리하지 않음). 같은 시각 순서는 서버 `event_order`로 구분한다. 출근일 이동으로 이전 날짜의 마지막 짝이 없어지면 이전 일별 금액·감사 이력은 보존하고 새 월 합산 원본·현재 일별 조회에서 제외한다(`ATTENDANCE_WORK_SOURCE_REMOVED`);0분 수정으로 위조하지 않는다.
- **즉시 반영/정산:** QR 퇴근이 확인되면 일별 근무는 `status=approved`, `record_source=qr_auto`, `auto_applied_at=서버 시각`으로 바로 반영한다. 직원 제출·관리자 확인 단계는 없다. `reviewed_by/review_note/submitted_by=NULL`이며 사람의 승인으로 기록하지 않는다. 전후 값·실제 실행 계정은 기존 일별 감사 이력에 남긴다. ### 서버 계약 · 로그인 없는 매장폰 등록 (2026-11-18, DBA 구현)

사용자 결정: 매장폰에는 로그인 기능·로그인/종료 버튼을 두지 않는다. 사장/점장의 **자기 앱**에서 등록 QR을 띄우고 매장폰이 스캔하여 스캐너 전용 토큰을 받는다. 등록 이후에는 누구나 해당 폰으로 직원 출퇴근 QR을 스캔할 수 있다. 해제는 자기 앱의 S46 매장폰 관리에서 원격 수행한다. 화면 구현/시안은 별도이며 아래는 로컬 서버 계약이다.

| RPC | 권한·입력 | 반환 |
|---|---|---|
| `issue_attendance_scanner_registration` | 로그인한 사장/점장만, `p_store_id: uuid`, `p_label: text`(공백 제거1~40자). 잠금 후 `get_my_store_access.can_manage_store` 재확인 | `{registration_id,store_id,expires_at,registration_qr}`. QR은 `rattle-scanner:v1.<store UUID>.<64자리 hex nonce>`,2분 유효·1회용. 같은 매장 새 발급은 이전 미사용 QR을 무효화 |
| `exchange_attendance_scanner_registration` | **로그인 불필요**(anon), `p_store_id: uuid`, `p_registration_qr: text` 전체. 별도 계정/JWT 생성 없음 | 성공 `{ok:true,scanner_id,store_id,token}`; 거절 `{ok:false,error_code}`. 교환 거절도 rate counter를 저장하기 위해 SQL 예외 대신 JSON으로 반환하므로 앱은 반드시 `ok`를 검사 |

- 발급은 매장별10분5회, 유효 형식 교환 요청은 QR에 들어 있는 실제 매장별1분20회로 제한한다. 매장 인자 바꿔 우회할 수 없으며 실패/재사용/만료도 교환 제한에 포함한다. 형식/길이 오류는 해시/DB 접근 전에 거절한다. 이는 DB의 매장 단위 제한이며 네트워크 게이트웨이의 IP별 방어를 보증하지 않는다. 공격자가 해당 매장 제한을 소진하면 정상 교환도 다음1분 창까지 기다릴 수 있다.
- nonce/스캐너 토큰은 각각256비트 난수이고 DB에는 SHA-256 해시만 저장한다. 원본 QR·토큰을 로그/오류/일반 저장소에 남기지 않는다. 등록 토큰 저장·로컬 전용 스캐너 모드 복구는 앱 담당 계약이며 계정 로그인 복구로 대체하지 않는다.
- 교환은 매장→점장 상태→등록 advisory→nonce 행 잠금 순서로 직렬화하고, 스캐너 생성과 nonce 소비를 같은 트랜잭션에 저장한다. 발급 당시 관리자라도 교환 전에 소유권/점장 지정 revision·승인 멤버·활성 직원 관계가 바뀌면 거절한다. 임의 `auth.uid` 설정이나 스캐너 JWT 승격은 하지 않는다. 같은 QR의 동시 교환은 한 번만 성공하고 나머지는 USED다(실제 다중 세션 경합 미검증).
- 기존 `register_attendance_scanner(uuid,text)`는 관리자 포함 클라이언트 호출을 차단한다(42501). 기존 스캐너 토큰은 유지하며 새 발급/교환을 통해서만 추가 등록한다. 스캐너 토큰은 해당 매장의 `attendance_scanner_status`·`punch_attendance`만 인증하며 계정·매장 관리·직원 급여 조회 권한은 주지 않는다.
- `revoke_attendance_scanner(p_scanner_id)`는 사장/점장의 기존 관리 경로를 유지한다. 원격 해제 이후 다음 status/punch 요청은 `ATTENDANCE_SCANNER_REVOKED`를 반환하므로 앱은 **등록이 해제됐어요** 상태로 전환한다. 알 수 없는 토큰은 기존 `ATTENDANCE_SCANNER_INVALID`다. 매장폰 자체에는 해제/종료 행동을 추가하지 않는다.
- 교환 응답이 유실돼도 소비된 nonce는 재사용할 수 없다. USED를 최초 등록 실패로 단정하지 말고, 관리 앱 목록에서 생성된 매장폰을 확인·해제한 뒤 새 QR로 다시 등록한다. 이미 소비한 QR로 토큰 원문을 다시 반환하지 않는다.

등록 거절 JSON의 코드는 `ATTENDANCE_SCANNER_REGISTRATION_INVALID`(형식·매장 불일치·알 수 없는/대체된 QR), `..._EXPIRED`, `..._USED`, `..._FORBIDDEN`(발급자 권한 소멸), `..._RATE_LIMIT`이다. 발급 오류는 `ATTENDANCE_AUTH_REQUIRED`, `ATTENDANCE_ADMIN_REQUIRED`/`STORE_ACCESS_DENIED`, `ATTENDANCE_SCANNER_LABEL_INVALID`, `ATTENDANCE_SCANNER_REGISTRATION_RATE_LIMIT`; 문구는 앱에서 짧게 변환한다.

**파일/검증/적용:** 새 `20261118130000_scanner_pairing.sql`을 앞 절의 `20261118120000` 다음에 적용한다. 이번 세션은 원격 미적용이고, 실패 시 전체 ROLLBACK/적용 후 새 보정 파일로 복구한다(구 관리자 로그인 등록을 되살리는 롤백 금지). `QA-SCANNER-PAIR-20261118` 가상 매장·직원/PGlite 단일 연결에서 등록·권한·매장 일치·만료·재사용·해제·실패 시 rate 저장을 검사한다. `node scripts/validate-qr-auto-work-sql.mjs`가 기존52개 및 새 매장폰51개 검사를 실행하며 `npm run test:sql`에도 포함된다. DBA 자체 검토이고 실제 다중 연결·원격·앱 UI/카메라·네트워크 수신·게이트웨이는 미검증이다.
