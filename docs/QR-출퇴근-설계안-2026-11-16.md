- 표기: **확정**(사용자 결정) / **제안**(AI 설계, 승인 대기) / **미정**(결정 필요) / **확인 필요**(외부 확인).
- 근거 자료: `reports/GPS 근태 위치기반서비스 신고 비교.md`, GPS 출퇴근 정책 초안(7-5절 센터 회신).

## 1. 확정된 결정 (2026-11-16)
| 항목 | 결정 |
|---|---|
| 방식 | **반대 방향 QR + 기기 등록 + 이상 감지**. 위치정보(GPS·Wi-Fi·비콘)는 수집하지 않는다 |
| 사진 | 사용하지 않는다 |
| 이유 | 위치정보지원센터 회신상 GPS는 단말 판정이어도 신고 대상 가능성이 높고, 사업자 미등록 상태로는 신고가 불가 |
| 네이티브 빌드 | 증빙(매입·비용 사진 첨부) 작업과 함께 한 번에 새 네이티브 빌드를 만든다 |

GPS 정책 초안의 업무 규칙(정정 요청·원본 보존, 시급 직원만 급여 반영, 분 단위 합산, 휴게 자동 차감, 스케줄 밖 근무 알림, 3년 보관 후 파기, 퇴근 누락 처리)은 **수집 방식과 무관하므로 그대로 승계**한다.

## 2. 구조 (제안)
```
[직원 폰: Rattle]            [매장 스캐너 기기: Rattle 스캐너 모드]          [서버]
 등록된 기기에서만              카메라로 직원 QR 스캔                       punch_attendance RPC
 30초마다 바뀌는 개인 QR  ──▶   (스캐너 전용 자격증명)          ──▶       토큰 검증·재사용 차단
 (출근/퇴근 선택)                                                         서버 시각으로 기록·이상 감지
```
- 출퇴근 기록은 **매장 스캐너 기기에서만** 생성된다. 직원 폰은 QR만 보여준다 → 원격 출근 불가.
- ~~대리 출근하려면 등록된 본인 폰을 매장에 가져와야 한다~~ → **정정(v2)**: 원격 출근의 수고를 높이는 수준이다. 폰 시계를 앞당겨 미리 만든 QR, 영상통화로 실시간 전달하는 QR은 기본 설계로 막지 못한다(9-1 참고). 직원끼리 짜고 하는 대리 출근은 종이 출근부 수준의 위험으로 남는다.
- 위치 측위 없음. 기록은 종이 출근부·출퇴근 기계와 같은 성격(AI 추정, 7장 확인 필요).

### 2-1. 직원 개인 QR 토큰 (제안)
- 기기 등록 시 서버가 기기별 비밀키를 발급 → 직원 폰 SecureStore에만 보관. 서버는 서버 전용 컬럼에 보관(클라이언트 조회 불가).
- QR 내용: `rattle-punch:v1.{device_id}.{window}.{intent}.{hmac}` — `window` = 30초 구간 번호, `intent` = 출근/퇴근, `hmac` = HMAC-SHA256(비밀키, device_id|window|intent) 앞 16바이트.
- 오프라인에서도 QR 생성 가능(시간 기반). 기기 시계 오차는 서버가 ±1 구간 허용.
- 서버: `(device_id, window, intent)` 1회만 사용(재사용 차단 테이블).

### 2-2. 매장 스캐너 기기 (제안)
- **관리자 로그인 세션을 매장 기기에 켜두지 않는다**(급여·계좌 노출 위험).
- 관리자가 한 번 로그인해 "이 기기를 스캐너로 등록" → 서버가 **스캐너 전용 자격증명**(해당 매장의 출퇴근 RPC만 호출 가능)을 발급하고 관리자 세션은 로그아웃.
- 스캐너 모드: 카메라 화면 + 최근 기록 몇 건(이름 일부만)만 표시. 종료·해제는 관리자 재인증.
- 스캐너 등록 해제·분실 시 관리자가 무효화.

### 2-3. 기기 등록 (제안)
- 직원 1명당 활성 기기 1대. 최초 등록은 즉시 허용, **기기 변경은 관리자 승인** 후 활성화.
- 기기 변경 직후 첫 출퇴근은 이상 감지에 표시.
- (선택, 2단계) iOS App Attest / Android Play Integrity로 변조 앱·에뮬레이터 차단.

### 2-4. 이상 감지 (제안, 수치는 임시값)
| 신호 | 처리 |
|---|---|
| 스케줄 시작 10분 전보다 이른 출근 / 종료 10분 후보다 늦은 퇴근 | 사장님 알림 (기존 결정 승계) |
| 스케줄 없는 날 출근 | 허용 + 알림 (기존 결정 승계) |
| 기기 변경 직후 첫 기록 | 확인 필요 표시 |
| 같은 직원 짧은 간격 중복 스캔 | 무시(멱등) + 기록 |
| 열린 근무 16시간 초과 | 알림, 정정 전 급여 제외 (기존 결정 승계) |
| POS 첫·마지막 결제 시각과 큰 차이 | **참고 표시만**(1단계는 알림 없음) |
- 표시된 기록만 사장님이 확인하고 나머지는 자동 인정. 정정은 원본 보존 + 이력(기존 결정).

## 4. 데이터 (제안)
- 새 테이블(기존 `attendance`는 위도·경도 NOT NULL인 GPS 구조라 재사용하지 않음, 기존 행은 보존):
  - `attendance_devices` — 직원 기기(상태: 대기/활성/해제, 비밀키는 서버 전용)
  - `attendance_scanners` — 매장 스캐너 기기와 자격증명 해시
  - `attendance_punches` — 출퇴근 원본(직원, 매장, 종류, 서버 시각, 스캐너, 직원 기기, 이상 표시)
  - `attendance_token_uses` — 재사용 차단(일정 기간 후 정리)
  - 정정은 기존 `attendance_corrections` 재사용 또는 새 이력 테이블(**미정**)
- RPC: `register_attendance_device`, `approve_attendance_device`, `register_scanner`, `punch_attendance`(스캐너 자격증명 전용), `list_attendance_review`.
- 모든 매장 참조 테이블에 삭제 대기 매장 가드(정책·트리거) 적용 — `scripts/validate-store-soft-delete-sql.mjs`의 누락 검사가 잡는다.
- 보관: 3년 후 파기(기존 결정), 매장 삭제 시 7일 유예 후 파기 흐름에 포함.

## 5. 빌드·배포 (제안)
- 직원 QR 표시는 JS만으로 가능(`react-native-svg` 이미 있음 + QR 생성 라이브러리).
- 스캐너는 카메라 필요 → `expo-camera` 추가. 증빙 브랜치의 네이티브 모듈(`expo-file-system`, `expo-image`, `expo-image-manipulator`)과 **같은 네이티브 빌드**로 묶는다.
  - 참고: 증빙 브랜치는 현재 `expo-camera`를 쓰지 않는다(사진 선택·편집 모듈). 카메라는 이 작업에서 새로 추가.
- 런타임 정책이 `appVersion`이므로 앱 버전 1.0.0 → 1.1.0(안)으로 올리고 새 빌드·심사. 이후 EAS Update는 1.1.0 런타임으로만.
- iOS 권한 문구: 카메라(“매장 출퇴근 QR을 스캔하기 위해 카메라를 사용합니다”). 위치 권한은 추가하지 않는다.

## 6. 개인정보·약관 (제안)
- 처리방침 수집 항목에 추가: 출퇴근 기록(일시·매장·스캐너 기기), 출퇴근 기기 식별자. 위치정보는 처리하지 않음을 유지.
- 처리방침 6항의 "출퇴근 기록을 새로 수집하지 않으며" 문구 수정.
- 직원 고지: 수집 목적·항목·보관 3년·열람 권한(관리자 전체, 본인 기록)·거부 시 대체 수단(관리자 수기 정정).

### 9-1. 반영한 수정
| # | 문제 | 반영 |
|---|---|---|
| C1 | 미리 만든 QR·실시간 전달을 막지 못함 | 위협 모델 정정. 구간 15초·허용 −1/+0. 미리 만든 QR 차단 여부는 결정 1 |
| C2 | 익명 로그인 스캐너는 `authenticated`에 열린 62개 RPC를 노출 | **익명 로그인 사용 안 함** |
| C3 | 비밀키 저장 위치 미정 | `private` 스키마(API 비노출) `attendance_device_secrets`에 서버 생성 32바이트 키 저장, `punch_attendance`(SECURITY DEFINER)만 읽음. 등록 응답으로 1회만 전달. PGlite에서 `pgcrypto hmac()` 동작 먼저 확인 |
| H1 | 키 백업·복원으로 기기 복제 | 키는 `WHEN_UNLOCKED_THIS_DEVICE_ONLY`로 별도 저장, 키 이름에 user·device 포함, 로그아웃 시 삭제, Android 자동 백업 제외. `device_id`는 서버 생성 UUID(하드웨어 ID 미수집) |
| H2 | 여러 매장 근무 직원 | 기기는 **사람(auth user) 기준** 등록. 스캐너 매장에서 `employees(store_id, user_id, is_active)`로 직원을 찾고 없으면 거절 |
| H3 | 스캐너 자격증명 | (권장) 무작위 스캐너 토큰, 서버엔 sha256 해시만. `punch_attendance(p_scanner_token, p_qr)`만 anon에 공개하고 함수 안에서 해제·매장 활성 확인. 해제는 `revoked_at`으로 즉시. 스캐너 경로는 로그인 없이 실행되도록 `app/_layout.tsx` 예외 처리. 결정 2 |
| H4 | 재사용 차단 테이블 정리 부담 | `attendance_token_uses` 제거. `attendance_punches UNIQUE(device_id, qr_window)` + 같은 QR 재제출은 기존 기록 반환(멱등, 응답 유실 재시도 대응) |
| H5 | 급여 연동 경로 없음 | 스캐너가 급여 테이블에 직접 쓰지 않음. 관리자 RPC `apply_punches_to_daily_work`가 근무 분 계산·시급 스냅샷·정산 확정 해제, 직접 입력값은 덮지 않고 차이만 표시. 정정 시 "다시 반영 필요" 표시 |
| H6 | 기존 `attendance_corrections`의 권한 결함(동료 사유 열람, 원본 수정 가능, 사진 컬럼) | 출퇴근 원본은 수정 불가, 정정은 `source='correction', supersedes_id` 새 기록. 요청·승인만 별도 관리(결정 4) |
| H7 | 새 테이블에 삭제 대기 매장 가드 자동 미적용 | 새 마이그레이션에서 정책·트리거 직접 추가, RPC에서 `is_store_active` 선확인, 파기 cascade를 PGlite로 검증 |
| M1 | 출근/퇴근 선택 실수 | QR에서 intent 제거, 서버가 열린 근무 유무로 판단(결정 3) |
| M2 | 날짜 귀속 | 출근 시각 KST 날짜에 귀속, 하루 여러 근무 합산, 1440분 상한 |
| M3 | 스캐너 오프라인 | 1단계 온라인 전용 + "저장 안 됨, 관리자 정정 필요" 명확 표시 |
| M4 | 운영 흐름 빈틈 | 폰 없는 직원은 관리자 직접 기록(`source=manual`, 사유 필수). "최초 등록" = 등록 이력 없음. 대기·미연결 계정 차단, 퇴사 시 기기 자동 해제, 역할 미리보기에서 QR·등록 차단, 스캐너 화면 꺼짐 방지·권한 거부 상태·성공 피드백 |
| M5 | QR만 먼저 EAS로 내보내는 위험 | 스캐너와 **같은 빌드로 함께 출시**(기능 플래그). 새 패키지: `react-native-qrcode-svg`, HMAC용 `@noble/hashes`, `expo-camera`, `expo-keep-awake`(+선택 `expo-screen-capture`, `expo-brightness`) |
| 개인정보 | | IP·기기 모델·원본 QR 문자열 미저장. POS 대조는 관리자 전용 참고값 |

### 9-2. 수정된 최소 출시 범위
- **0단계**: 위협 모델 확정(결정 1), 스캐너 방식 확정(결정 2), PGlite `pgcrypto` 확인, 센터 서면 회신, `AGENTS.md` 범위 변경 승인.
- **1차 출시**: DB(기기·스캐너·출퇴근 기록·`private` 비밀키) + RPC(등록·승인·해제·`punch_attendance`) + S43·S44(같은 네이티브 빌드) + S45 최소판(목록·직접 기록·확인 필요). **급여 반영·알림은 2차.**

- **E2E(새 ID)**: 분실·기기 변경 승인, 미리 만든 QR·캡처 시도, 스캐너 네트워크 끊김, 저장 후 응답 유실, 여러 매장 직원, 폰 없는 직원, 역할 미리보기 차단, 스캐너 해제 후 즉시 거절.

### 9-3. 사용자 결정 필요
1. 미리 만든 QR까지 막을지(직원 폰 온라인 필수, 일회용 값) / 남는 위험으로 둘지

### 9-5. 추가 설계 메모 (제안)
- **반영 주기와 손익계산서**: 출퇴근 기록은 반영 전까지 확정 인건비가 아니다. 손익계산서에는 `확정 인건비` + `미반영 출퇴근 인건비(추정, 별도 표시)`를 나눠 보여 준다(AGENTS.md "미확인 인건비를 0원으로 만들지 않는다"와 일치). 반영 주기(매일/주별/월별)는 매장 설정, 기본값 미정.
- **기기 저장 정보**: 직원 폰 = 기기 ID·비밀키(이 기기 전용 키체인)만. 스캐너 = 스캐너 토큰만. 출퇴근 기록·위치는 기기에 저장하지 않는다(화면 표시는 서버 조회).
- **GPS·QR 병행 개발**: "출근 확인 방식"을 교체 가능한 구조로 만들고 QR을 먼저 출시한다. GPS 판정 모듈은 별도 브랜치·기능 플래그로 개발하되, 사업자등록 + 위치기반서비스사업 신고 + 위치정보 동의·약관 전에는 **출시 빌드에 위치 권한·모듈을 넣지 않는다**(쓰지 않는 위치 권한 문구는 심사 리스크).
