# 급여 변경·입사일 기준·스냅샷 구현 인수인계

## 범위와 기준

- 기준 로컬 브랜치 `feature/operations-workflows`, HEAD `679c07593f8f8acd41528d94883a01202bcb7677`에 기존 미커밋 변경이 포함된 작업 공간. 원격 최신 여부는 이번 작업에서 확인하지 않았다.
- 사용자 결정: 최초 급여는 입사일부터, 이후 금액은 변경일부터 적용한다. 별도 급여 조건 확인 절차를 없애고 급여 변경 화면을 제공한다. 작성한 월 명세와 급여 이력은 후속 금액 변경으로 덮어쓰지 않는다.
- 정규직 담당: regular_wages. 통합·서비스 저장 경로·실제 앱 검증: 부모 PL. 일별 파트타이머 입력은 별도 담당.

## 구현

- `lib/utils/regularWages.ts`: 최초 이력과 입사일 사이를 최초 이력 금액으로 채우는 조회 정규화, 월별 적용 금액 스냅샷, 한국 날짜 기준 일할 누적.
- 최초 이력이 아예 없으면 현재 직원 금액이 최초 기준이다. 입사일이 없으면 직원 생성일을 사용한다. 유효한 날짜·금액도 없는 자료는 추정하지 않는다.
- 스냅샷은 `version`, `year_month`, `employment_start`, `days[{date,base_salary,non_taxable,factor}]` 구조다. 월 총액은 일별 월급/월 일수 합계를 원 단위 반올림한다.
- 이미 작성된 과거 월 급여는 원래 `gross`를 반환한다. 현재 월 새 스냅샷은 오늘까지 부분 합산한다. 구형 명세는 원본을 변경하지 않고 재직 달력일 비율로 현재 누적을 추정한다.
- `app/(tabs)/payroll.tsx`: 별도 조건 확인 경고를 제거하고 급여 변경 진입을 유지한다. 누적액을 저장된 월 전체액과 구분한다.
- `app/payroll/wage-condition.tsx`: 급여 변경 화면으로 문구 변경. 최초는 입사일, 변경은 오늘을 기본값으로 제공한다. 입사일 전 적용일과 중복 적용일은 거절한다.

## 서버 SQL (원격 미적용)

`supabase/migrations/20261027010000_wage_effective_baselines.sql`

1. `payroll.regular_wage_snapshot` 컬럼 추가.
2. 기존 입사일보다 최초 이력이 늦으면 최초 이력 금액을 입사일 기준 행으로 추가한다. 이력이 전혀 없으면 기존 직원 금액을 사용한다. 기존 이력·월 명세 금액은 수정하지 않는다.
3. 급여 변경 RPC에서 직원 행을 잠그고 최초 조건 보존 후 새 적용일을 추가한다. 인증·관리자·입사일·중복 적용일·금액을 검사한다.
4. 이력의 직접 INSERT/UPDATE/DELETE 권한은 회수하고 관리자 RPC를 사용한다. 직원 생성·합류 승인 RPC의 내부 쓰기는 유지한다.
5. 새 월 스냅샷과 월 총액의 합계를 검증한다. 손익 v2는 현재 월 누적·과거 명세 원본·미래 0원으로 집계한다. 기존 금융 공유 권한 검사를 유지한다.

적용 전 DBA 검토 필요. 적용 완료로 보고하지 않으며, 기존 광범위 테스트 SQL의 과거 '이력 없으면 항상 미확인' 기대값은 새 정책에 맞춰 유효한 급여 fixture만 갱신한다. 날짜나 금액 자체가 없는 오류를 0원으로 바꾸지 않는다.

## 검증과 통합 작업

- `__tests__/utils/regularWages.test.ts`: 최초 이력 확장, 신규 입사, 월중 인상, 저장 후 현재 급여 변경 독립성, 구형 명세 보존, 미래월 0원, 한국 자정·윤년, 잘못된 금액.
- `scripts/validate-regular-wages-sql.mjs`: PGlite 축약 스키마에서 입사일 기준 행 추가·기존 명세 보존·적용일 검증·권한 거절·스냅샷 합계·과거/현재 손익 검사. 원격 RLS/실동시성 테스트를 대신하지 않는다.
- 부모 PL 통합: 정규직 월 급여 작성 시 `getWageHistory` → `buildRegularWageSnapshot` → `regularSnapshotGross`로 계산하고 스냅샷을 저장한다. 작성된 명세를 일반 직원 수정만으로 재작성하지 않는다. 상세 손익 서비스도 같은 `accruedRegularPayroll` 규칙에 맞춘다.
- 기존 수습 계수 정책과 세액·보험 비율은 이번 변경에서 바꾸지 않았다.
- 네이티브 화면 전후·실제 직원 계정·원격 SQL 적용은 이 담당자가 실행하지 않았다.
