# Rattle 화면 문구 정리표

**상태: 검토 초안 · 앱 문구 미변경 · SQL 변경 없음**

추천은 **반복 설명 27곳 삭제 → 긴 안내·오류 100곳 정리 → 우선 수정 2곳** 순서다. 급여 계산·정산 해제·삭제 영향·입력 조건은 필요한 결과와 다음 행동을 남긴다.

## 범위와 집계

- 앱·공통 컴포넌트·훅·서비스·유틸리티의 TypeScript/TSX **135개 파일**을 정적으로 조사했다.
- 현재 라우트에서 참조하는 소스의 설명·도움말·상태·알림·오류 후보는 **232곳**이다. 같은 문구가 여러 파일에 있으면 위치별로 센다.
- 법적 고지 본문, 짧은 버튼/필드 이름, 아이콘 접근성 라벨, 단순 숫자 포맷은 일반 설명 삭제 대상에서 제외했다. 연결되지 않은 지도/격려 문구와 개발 로그 등 14곳도 집계에서 제외했다.
- 아래는 코드에서 확인한 목록이다. 모든 권한·오류 조건을 실기기에서 발생시킨 목록은 아니다. Supabase·카카오·운영체제가 만드는 동적 오류 원문은 별도로 나올 수 있다.
- `{변수}`·`{직원명}` 등의 표시는 실제 매장명·월·금액으로 바뀌는 자리다. 긴 계산식/조건문은 읽기 쉽게 풀어 적었다. 정확한 원문과 위치는 동봉 JSON/소스를 따른다.
- 같은 날짜에 검토한 새 SQL 4개에는 사용자에게 전달될 수 있는 서버 오류 문구 **37곳**이 추가로 있다. 원격 적용 여부는 별도이며 아래 부록으로 분리했다.

| 추천 | 위치 수 | 처리 |
|---|---:|---|
| 삭제 추천 | 27 | 버튼·제목·상태와 겹치는 설명 제거 |
| 짧게 수정 | 100 | 현재 상태 또는 다음 행동 중심으로 정리 |
| 수정 필수 | 2 | 출퇴근 잔재 1곳 + 내부 인증 용어 1곳 |
| 유지 | 103 | 이미 짧거나 오류·입력 조건·핵심 결과를 전달 |
| 앱 소스 합계 | **232** | 중복 문구의 위치 포함 |

## 한 번에 적용할 범위 선택

- [ ] **A. 삭제 추천 27곳**을 일괄 제거한다.
- [ ] **B. 짧게 수정 100곳**을 제안안으로 정리한다. C175는 계산 근거를 여는 도움말로 분리하는 UI 작업이므로 별도 확인한다.
- [ ] **C. 수정 필수 2곳**을 현재 기능에 맞게 고친다.
- [ ] **D. 개별 선택**: 유지할 ID / 추가로 지울 ID를 적는다.

예: `A+C 적용, C030은 유지` 또는 `C027, C064, C072만 제안대로 수정`처럼 ID로 지정하면 된다. CSV에서 기능·추천으로 필터해 검토할 수도 있다.

## 유지할 조건과 별도 검토

- 급여·금액: 자동 계산값과 실제 고지액의 구분, 정산 확정 해제, 재계산 영향, 동시 수정 충돌은 필요한 결과를 보존한다.
- 근무시간: 휴게시간 제외, 미입력/0분 구분, 입력 단위(분), 적용 시급의 자리수·월 최대 분 제한을 보존한다.
- 계정 연결: 관리자 승인, 기존 직원과 일치하지 않는 경우, 신규 직원 생성, 오연결·권한 문제를 감추지 않는다.
- 삭제·탈퇴: 어떤 대상이 없어지는지와 복구 가능 여부를 남긴다.
- C056(급여 명세서의 과세 기준 설명)은 숫자 항목이 이미 충분히 보이는지 확인한 뒤 축약한다. 세무·보험 규칙을 새로 판단하거나 바꾸는 작업이 아니다.
- C175는 계산 설명을 숨길 위치가 필요하므로 문장만 일괄 삭제하는 항목에서 분리한다.
- C032는 현재 앱의 월별 수기 근무 분 입력과 불일치한다. C011은 내부 인증 용어를 사용자 행동 안내로 바꾸는 항목이다.

## 공통 오류 표시에서 같이 정리할 점

`lib/utils/error.ts`는 서버/라이브러리의 `error.message`를 우선 표시하고, 메시지가 없을 때만 fallback을 쓴다. 따라서 화면에 적힌 기본 문구만 줄여도 실제 서버 오류는 길거나 영어로 보일 수 있다.

적용 단계에서는 사용자에게는 `무엇이 실패했는지 + 다음 행동`을 짧게 표시하고, 원인 분석에 필요한 원문은 진단 정보로 남기는 방식을 권한다. 입력 조건·충돌·권한 오류는 서로 구분해야 한다.
