# 퇴사 직원 선택 승인

> **현재 상태 · 2026-10-23:** 선행 승인 후보 함수와 최신 온보딩 승인 함수의 원격 본문 일치를 확인했다. 이미 존재해 해당 파일을 재실행하지 않았다. 아래 미적용 서술은 당시 기록이다. 최신 근거는 [SQL 원격 적용 확인](SQL-원격적용-확인-2026-10-23.md)을 따른다.

2026-10-22 온보딩 확장 적용 후에는 관리자가 세부내역을 확인·수정하고 최종 합류로 확정한다. 기존 기록·과거 급여 명세는 유지하되 현재 조건은 관리자 확정본을 반영한다. `직원-합류-온보딩-2026-10-22.md`를 우선 따른다.

## 동작

멤버 관리에서 승인할 때 겹치는 재직 직원 없이 퇴사 기록이 있으면 선택 화면을 연다. 이름·연락처·입사일·등록일을 확인한 뒤 아래 중 하나를 선택하고 최종 확인한다.

- 이 직원으로 재입사 승인: 선택한 직원 ID와 과거 급여·고용 조건을 유지하고 신청 계정을 연결해 재직 상태로 변경한다. 과거 급여 이력이 신청 계정에 공개되므로 동일인 확인이 필요하다.
- 별도 직원으로 신규 승인: 퇴사 기록을 유지하고 신청 정보로 새 직원을 등록한다. 급여 내역은 생성하지 않는다.

다른 계정에 연결된 기록은 재입사 대상으로 선택할 수 없다. 신청 계정에 이미 연결된 기록이 있으면 그 기록만 선택할 수 있으며 새 직원으로 중복 등록할 수 없다. 겹치는 재직 직원이 있으면 기존 승인 검증을 유지한다. 선택 후 정보가 바뀌면 서버가 다시 검사하고 실패 시 전체 작업을 롤백한다.

재입사는 기존 입사일·시급·월급·수습 조건을 자동으로 초기화하지 않는다. 승인 후 인건비에서 현재 조건을 검토한다. 과거 급여 행과 근무시간 이력은 수정하지 않는다.

## Supabase 적용

원격 DB 미적용 상태. 기존 20261019 직원 자동 연결 및 20261020 보완 SQL 적용을 전제로 한다.

1. 참여 알림을 아직 적용하지 않았다면 `supabase/migrations/20261021_member_request_notifications.sql`
2. `supabase/migrations/20261021_member_approval_choice.sql`

첫 번째 파일을 이미 실행했다면 두 번째 파일만 적용한다. 기존 함수를 삭제하거나 퇴사 직원을 삭제할 필요가 없다. 적용 후 앱을 새로고침한다. 네이티브 재빌드는 필요 없다.

## 검증

- `npm run typecheck`
- `npm test -- --runInBand --no-coverage`
- `npm run test:sql`

로컬 SQL은 축약 스키마의 PGlite 검증이며 원격 적용·계정·기기 검증을 대체하지 않는다. 실제 관리자 계정에서 퇴사 기록 선택 → 재입사/신규 승인 → 직원 목록·기존 급여 이력·참여 알림 읽음 상태를 확인한다.
