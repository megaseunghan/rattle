## PM/PL 완료 기준

현재 추적은51개 화면 ID(실제 라우트49개·예정 S45/S46 두 개)와 기존 공통/모달 흐름이다. S50/S51은 새 정정 작성/목록 독립 라우트, S49는 철회 후보로 재사용하지 않는다. 소스 매핑 통과와 행동 E2E 완료를 구분한다. 완료는 ① 기능별 정상·오류·빈 상태 ② 입력 경계 ③ 취소/중단 ④ 중복·지연 ⑤ 역할별 서버 권한 ⑥ 원천 데이터 검산이 대상 플랫폼에서 증거와 함께 통과한 상태다. 현재 목표 전체 E2E는 미완료다. 실제기기·시뮬레이터·웹 결과는 각각 기록한다. 코드 변경/버그 수정은 다음 작업으로 분리한다.

### S19 이전 제출 흐름 (이번 출시 전환 검증에서 제외)

사용자 확인: 출시 전이라 기존 수동 제출 자료가 없다(QR-A03 확정). 이전 WORK/S19 수동 제출 시나리오는 과거 계약 기록이며 현재 출시 전환/보존 설계의 선행 조건이 아니다. 개발 DB에는 새 QR 자동 기록 방식을 바로 적용한다. 새 PT 별도 제출 메뉴/폼은 제거하고, 일별 스냅샷·확인/월 급여/정산 상태 검증은 새 QR 사례로 수행한다. 이번 문서 작업은 DB 변경/전체 초기화·S19 코드 삭제를 실행하지 않는다.

### S42 추적 보완 기록 · 2026-10-29

코드 자체 대조로 S42와 HOME_CONFIG를 추가했다. 기존 시나리오 ID는 변경하지 않았다. 화면 테스트의 정상 단계·직원 제한은 mock 근거이며 오류/지연/원격 권한/실기기 검증 완료로 확대하지 않는다. 전용 QA 매장 저장을 포함하는 위 절차는 향후 승인된 테스트 범위에서 실행하며, 이번 문서 수정에서는 운영 자료를 변경하지 않았다.

## QR 출퇴근 1차 · E-S43~E-S46 (2026-11-17 추가, 모두 미실행)

근거는 [앱 화면 인수인계](QR-출퇴근-앱화면-인수인계-2026-11-16.md) 1~4·7장 우선, [설계안 현재 정책](QR-출퇴근-설계안-2026-11-16.md#qr-current-20261118)을 함께 따른다. 확정 디자인과 미확정 항목·역할별 수용 기준·QR-D01~D08은 [화면 명세의 QR 출퇴근 1차](전체화면-기능명세-2026-10-26.md#qr-attendance-phase1)를 따른다. 기존 화면/시나리오/공통 변형 ID는 변경하지 않았다.

이번 과제는 문서 등록·정적 검사만 수행한다. 아래 실제 E2E는 새 `QA-...` 실행 ID와 승인된 가상 매장 A/B·관리자·정규직·PT·가입 대기 계정을 정한 뒤 실행한다. 10/26 실행 ID·개발 DB 허가를 새 실행 승인으로 재사용하지 않는다. 실제 직원·기존 자료·레거시 attendance 테이블·급여·알림은 변경하지 않는다.

### 역할·매장별 C07 기준

기존 관리자/정규직/PT 중복 역할표는 [현재 역할 수용 기준](전체화면-기능명세-2026-10-26.md#qr-manager-model-20261117)으로 합쳤다. 사장/점장/직원/PT·대기·비로그인 매장폰·타매장·권한 상실 세션을 각각 실행한다. 본인/타인·공유 열람/관리 쓰기를 분리하고 점장 자기 정정 대상은 요청자와 별도로 판정한다.

### 오류 대응·증거와 미결 범위

- 인수인계 4장의 모든 오류를 화면별로 주입하고 [화면 명세 오류 대응표](전체화면-기능명세-2026-10-26.md#qr-attendance-errors)와 대조한다. QR_EXPIRED/INVALID, DEVICE_INACTIVE/NOT_FOUND, NOT_EMPLOYEE, SCANNER_INVALID, DEVICE/QR/CORRECTION_RATE_LIMIT, ADMIN/AUTH/EMPLOYEE_REQUIRED, REASON_REQUIRED/INPUT_INVALID/TARGET_INVALID, CORRECTION_PENDING/NOT_PENDING을 각각 확인한다(접두어 ATTENDANCE_). 원문 코드 노출 없음·다음 행동·초안/원본 상태를 증거로 남긴다.
- 날짜 귀속·flags·정정은 유효 기록과 원본·스냅샷·요청 상태를 대조한다. no_schedule/early_clock_in/late_clock_out/previous_open_over_16h/new_device별 확인 필요 표시를 검증한다. 등록·스캔·정정 후 급여/일별 근무/정산 확정 차이 0, 알림 0을 확인한다.
- 네이티브 S43/S45/S46은 동일 빌드·기기·배율에서 입력/스크롤/키보드/안전영역/뒤로/초안/터치를 확인한다. S44 카메라는 시뮬레이터로 통과 처리하지 않고 실기기 2대로 확인한다. 웹/별도 디자인 앱/mock·PGlite/실제 JWT·원격 DB/실기기 수신 증거를 구분한다.
- 사용자 확정: 오늘 기록 먼저, 별도 정정 화면·아래서 올라옴·손잡이 내려닫기, 기존 기록→변경 날짜시간→정정 사유, 중복 유형칸 제거, 기존 시각 초기값·12시간 휠. 날짜 선택/누락 추가·무효 진입 UI/강제 종료 초안은 미확정이다. 시안 통과를 실제 요청·권한·서버 복구 통과로 기록하지 않는다.
- 서버 후속: QR-D01 자기 승인, D03 야간 늦은 퇴근, D04 직원 삭제/user_id 변경, D05 삭제 차단·3년 보관, D06 자정 너머 정정·짝 날짜, D07 조회 RPC 충분성은 명세 결정표로 넘긴다. 결정·보정 전 해당 기대값을 임의로 만들어 통과하지 않는다. 신규 SQL은 새 파일로 검토하고 원격 적용은 별도 승인이다.

## E-S52/S44/S46 매장폰 등록·원격 해제 · 2026-11-18 (모두 행동 미실행)

근거는 [등록 QR 화면 명세](전체화면-기능명세-2026-10-26.md#scanner-pairing-20261118)와 [설계안](QR-출퇴근-설계안-2026-11-16.md)의 「서버 계약 · 로그인 없는 매장폰 등록」이다. 매장폰 관리자 로그인/등록 후 로그아웃/종료 재인증 사례는 아래로 대체한다. S52 소스 존재를 시안 승인/기능 통과로 보지 않는다.

| 사례 | 절차·판정 기준 |
|---|---|
| E-S52/E-S44 정상 | 사장/점장 자기 앱에서 해당 매장 QR 발급→매장폰은 로그인 없이 등록 QR 스캔→교환 ok:true 확인→토큰 보안 저장→직원 QR 스캔. 발급만으로 등록 완료 표시 없음·관리자 세션/급여 접근 없음·매장폰 로그인/종료/자체 해제 버튼 없음 |
| C01 반복·경합 | 발급 연타·같은 QR 여러 스캔/두 매장폰 동시 교환·S52 재발급 각각 검사. 한 번만 교환 성공·중복 생성 없음, 재발급 이전 미사용 QR 무효. 실제 다중 연결은 로컬 단일 PGlite 통과와 별도 증거 |
| C02 취소/뒤로 | 관리자 발급 전/후 뒤로·매장폰 등록 전/후 복귀 구분. 발급 취소/페이지 이탈을 이미 완료된 등록 해제로 처리하지 않음. 매장폰 종료 인증/로그인 UI로 복구하지 않음 |
