## 실제 확인 범위

iPhone 16e 시뮬레이터에서 홈, 재고, 인건비, 매입, 매입 입력·품목 선택, 매출, 마이페이지, 더보기, 알림 화면을 열어 배치를 확인했다. 품목 선택에서는 카테고리 글자가 보이고 필터가 적용되며 닫기 후 원래 화면으로 복귀하는 것을 확인했다.

그 밖의 화면은 코드로 검토했다. 로그인 재인증, 카메라 촬영·OCR 실행, 실제 급여 저장·정산 확정, 설정 저장은 이 디자인 확인에서 실행하지 않았다. 작은 화면·큰 글씨·Android의 모든 조합은 추가 확인 대상이다.

## 후속 수정: 시작 화면·홈 그래프·월급제 정책

- 시작 화면: 준비 완료 뒤 2.3초간 재생하던 도형 변형·바운스·영문 문구를 제거했다. 네이티브 시작 화면과 JS 로딩 화면은 같은 로고·크기·배경을 쓰며 준비 완료 후 150ms 페이드로 전환한다. 동작 줄이기 설정을 반영한다. iOS 개발 빌드를 갱신하고 로고에서 실제 화면으로 넘어가는 것을 시뮬레이터에서 확인했다. 실기기 릴리스 빌드의 체감 검증은 별도다.
- 매장 홈 그래프: 선택 월까지 최근 6개월을 유지한다. 실패한 월을 삭제하거나 0원으로 바꾸지 않고, 실제 0원과 조회 실패를 구분한다. 음수는 0선 아래에 표시한다. 월별 금액을 함께 표시하고 매장 전환·기간 변경 전의 늦은 응답이 현재 데이터를 덮지 않게 했다. 새로고침은 최신 데이터를 다시 읽는다.
- 앱바: 좌우 버튼 영역의 폭을 같게 맞추고 매장명은 화면 중심에 놓았다. 드롭다운 화살표는 제목 중심을 밀지 않도록 별도로 배치했다.
- 인건비: **월급제 정규직은 근무시간 입력이 필요 없다.** 정규직의 근무 분 미입력 행·경고·입력 버튼을 제거했다. 급여 자체의 미작성은 전 직원에게 확인하고, 시간 미입력은 파트타이머만 확인한다. 파트타이머 0분은 입력 완료다. 정규직에 이미 보관된 시간·이력은 삭제하지 않는다.
- 급여 명세서: 정규직에게 근무 분이 없으면 ‘미입력’ 문구를 표시하지 않는다. 과거 입력값이 있으면 보존된 값은 확인할 수 있다.

### DB 조회 확인 이력과 현재 상태

최초 확인에서는 연결된 Supabase에 인증키나 급여 데이터를 출력하지 않는 읽기 전용 요청으로 컬럼 존재 여부를 확인했고, `payroll.worked_minutes`에 대해 HTTP 400 / PostgreSQL `42703` / `column payroll.worked_minutes does not exist`가 반환됐다.

**2026-10-19 재확인에서는 상태가 달라졌다.** `worked_minutes`, `work_source`, `applied_hourly_wage`의 컬럼 조회가 HTTP 200으로 성공했고, 로그인된 iPhone 16e 시뮬레이터의 매장 홈과 통합 홈에서도 실제 집계 금액·최근 6개월 막대가 표시됐다. 통합 홈에서 음수인 달은 0선 아래 빨강 막대로 표시되는 것을 확인했다. 이 작업에서 원격 DB를 변경하지 않았으므로, 누가 어떤 SQL을 적용했는지는 확인하지 못했다. 이력 테이블의 비로그인 조회는 권한 거부였으며 로그인 사용자의 이력 조회·저장까지 검증한 결과는 아니다.

현재 DB의 개발·운영 구분과 파트타이머 전용 정산 함수의 적용 여부는 미확인이다. 마이그레이션을 무조건 재실행하지 말고 적용 이력을 먼저 확인한다. 순서는 README의 **DB 적용 및 검증 순서**를 따른다. 최초 전환에는 `20261016_manual_work_minutes.sql`, 기존 적용 DB의 정산 조건 갱신에는 `20261018_part_time_minutes_settlement.sql`이 준비돼 있다.

### 2026-10-19 통합 홈 마무리

- 차트에 고정된 표시 높이와 0선을 두고, 음수·양수·실제 0을 구분했다. 월별/연도별 탭의 비교 문구도 전월/전년으로 맞췄다.
- 손익·추세 조회가 실패해도 성공한 매장의 청소·스케줄은 유지한다. 매장별 운영 조회 실패를 0%나 휴무로 대체하지 않는다. 다시 시도와 당겨서 새로고침을 추가했다.
- 매장·기간·영업 마감 시각이 바뀌면 이전 범위의 결과를 숨기고, 늦게 도착한 응답을 버린다. 매장이 없는 상태의 영구 로딩 문구도 제거했다.
- 가로 매장 캐러셀이 세로 콘텐츠를 줄이지 않도록 페이지 높이를 측정해 반영했다. 다만 자동 조작으로 청소·스케줄 카드 끝까지 도달하는 과정은 확인하지 못했다. 실제 높이 잘림인지 시뮬레이터 입력 이벤트의 한계인지 확정하지 못했으므로, 하단 전체 스크롤 경로는 추가 확인 대상이다.
- iPhone 16e에서 정규직 카드에는 근무시간 입력이 없고, 파트타이머 카드에는 미입력·근무시간 입력이 표시되는 것을 확인했다. 실제 급여 저장이나 정산 확정은 실행하지 않았다.
- 최종 검사: TypeScript 타입 검사, Jest **16개 묶음·105개 테스트**, `git diff --check` 통과. iOS 개발 빌드 성공 및 실행 확인. Android·실기기 릴리스 빌드는 미확인이다.
- 코드 리뷰에서 데이터 오류 분리·범위 전환·차트·급여명세서 조건을 확인했다. 검토 중 발견한 무매장 로딩 문구를 수정했다.
