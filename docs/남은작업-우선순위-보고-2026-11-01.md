# Rattle 남은 작업 우선순위 보고 — 2026-11-01

## 결론

지금은 UI 장식 추가보다 **서버 적용/권한 확인 → 금액과 저장 상태 오류 수정 → 실제 업무 흐름 검증 → 배포본 일치 확인** 순서가 우선이다. 직원 확대 배포 전 P0와 P1을 먼저 닫는 것을 권한다.

최초 보고는 현재 로컬 코드와 저장소 문서를 읽어 작성했다. 1번은 후속 서버 읽기 전용 대조로 갱신했으며 해당 결과를 우선 따른다. 앱/운영 DB/스토어 콘솔을 새로 조작하거나 테스트를 재실행하지 않았다. 과거 기록, 현재 코드 확인, 미검증 위험을 구분한다.

- 현재 브랜치 `feature/operations-workflows`, HEAD `0d04e7860ed7b72af933854e5d347a7b8a23bb09` + 다수 미커밋/미추적 변경. 원격 최신 여부 미조회.
- 지난 UI 점검은 같은 iPhone 16 Pro의 42개 경로 진입 결과 관찰이며 모든 정상 상태/역할/쓰기 흐름 통과가 아니다. 최종 번들에서 42개 모두 재확인한 것도 아니다.
- 90 suites/537 tests 통과 및 후속 관련 12 tests 통과는 10/30 실행 기록이다. 현재 상태에서 다시 돌린 결과로 표현하지 않는다.
- 아래 U01~U34는 기존 휴리스틱 보고서 ID, DB-xx는 서버·DB 검토 ID다. 같은 문제를 중복 개발하지 않도록 묶었다. 대표 고위험 경로는 이번에 현재 코드를 다시 읽었고, 나머지는 과거 지적에 대한 재확인 작업으로 등록했다.

- 10/30 시뮬레이터 UI 번들은 테스트용이며 스토어에 그대로 올릴 산출물이 아니다. 출시 번들은 QA 로그인/브로커 토큰 제거와 채널·런타임 일치를 확인한다.

## 사용자 결정이 필요한 항목

1. 서버 적용 대조 후 SQL이 실제 누락된 경우 적용 실행 권한과 시점. 보고서만으로 원격 실행하지 않는다.
2. 파트타이머 재고 수정은 수량만인지, 이름/단가/삭제까지인지. 현재 정책과 제품 의도를 대조 후 불일치가 있으면 결정한다.
3. 무상 매입 0원 단가 수정 정책. 추천은 신규/수정 동일 규칙으로 맞추고 과거 거래 보존.
4. 정상 쓰기 E2E에 사용할 기존 테스트 매장/계정/가상 자료 범위. 채팅으로 비밀번호를 받지 않고 실제 직원 초대·운영 자료 변경은 별도 실행하지 않는다.

추천 착수 순서: **P0 1~4 확인 → P1 5~11 수정 → 전체 검색·입력 보호/숫자 검증 → 일별 근무 E2E → 동일 최종본 회귀 → 배포본 대조와 승인된 배포**. 장식/추가 모션은 이 뒤다.

## 현재 할 일에서 제외

종합평가·인센티브, 출퇴근 등록/GPS, 발주 화면, 매입 OCR, 이름 변경은 현 제품 범위에 추가하지 않는다. 서비스코드만으로 무번호 매장을 자동 연결하는 미완성 서버 절차는 기존 안내형 연결과 분리해 후순위다. 최종 DB 교체/환경 분리도 기존 결정대로 별도 결정 시점에 다룬다.
