# 매장 전환·조회 오류 수정

## 확인한 현상

- 상단에서 매장을 고르면 전체 매장 목록을 다시 조회한 뒤 전환해, 서버 응답이 늦을 때 이전 매장이 계속 표시됐다.
- 시뮬레이터에 비용 조회의 `Gateway Timeout` 미처리 오류가 남아 있었다. 연간 손익 화면은 조회 실패를 처리하지 않았고 여러 달의 DB 조회를 한꺼번에 시작했다.
- 사용자가 공유한 `getPayrollByMonth` 스택에는 오류 원문이 없어 당시 실패 원인은 확정하지 못했다. 인건비 탭과 급여 정산의 현재 조회는 시뮬레이터에서 정상 동작했다.

## 수정

- 불러온 접근 가능 매장 목록에서 선택해 서버 재조회 없이 전환한다. 목록에 없는 매장은 선택할 수 없다. 실제 데이터 접근 권한은 기존 DB 정책을 유지한다.
- 목록 조회 실패 시 기존 목록·역할을 유지한다. 저장된 매장이 없어졌으면 첫 접근 가능 매장으로 돌아간다.
- 오래된 목록 요청이나 로그아웃 이전 요청이 현재 선택을 덮어쓰지 않게 한다. 선택 저장 실패 시 기존 선택과 미리보기를 유지한다.
- 전환 실패를 짧게 안내하고 매장 목록 조회에는 재시도 동작을 제공한다.
- 매장별 탭 화면의 데이터·캐시를 분리하고 늦게 완료된 직원 조회가 새 매장 직원을 덮어쓰지 않게 한다.
- 연간 손익은 동시에 두 달까지만 조회한다. 조회 실패를 0원으로 바꾸지 않고 짧은 오류·재시도를 제공한다. 매장·연도를 바꾸면 이전 요청의 결과는 표시하지 않는다.

## 검증 및 반영 상태

- 타입 검사 통과, Jest 23개 묶음·129개 테스트 통과.
- 시뮬레이터: 전체 매장 → 테네스 행궁 → 심금 전환, 매장별 매출 변경, 인건비 탭·급여 정산 조회 확인.
- 실제 휴대폰 확인과 운영 앱 배포는 실행하지 않았다. 급여 작성·확정 등 원격 데이터 변경도 실행하지 않았다.
- 이번 수정은 SQL 변경이 없다. 기존 SQL은 사용자가 적용 완료했다고 알렸으며 원격 적용 이력은 직접 조회하지 않았다.
