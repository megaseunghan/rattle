# 래틀 스크린샷용 데모 매장

실행 파일: `supabase/operations/create-rattle-screenshot-store.sql`

1. SQL 파일의 `owner_email`에 **이미 가입한** Rattle 로그인 이메일을 입력한다. 새 데모용 이메일을 적어도 계정이 만들어지지는 않는다. 이메일을 모르면 `owner_store_name`의 `NULL`을 본인 소유 기존 매장 이름(예: `'심금'`)으로 바꾼다. 이 경우 해당 매장의 **소유자 계정**에 데모가 생성된다.
2. Supabase SQL Editor에서 파일 전체를 한 번 실행한다.
3. 앱을 새로고침하고 매장 전환에서 **래틀**을 선택한다.

기존 매장 자료를 수정하거나 지우지 않는다. 고정된 데모 ID로 중복 실행을 차단하고, 오류가 나면 트랜잭션 전체가 롤백된다. 계정/매장을 못 찾거나 중복 이름이면 구체적인 안내와 함께 중단한다. 원격 실행은 사용자가 담당하며, 작성만으로 생성 완료된 상태는 아니다.

## 구성

- 실행일 기준 직전 2개월과 이번 달 오늘까지의 수기 매출
- 정기 매입과 거래처 6곳, 품목별 금액/재고/레시피 연결
- 식자재·주류·비품 14종, 레시피 8개, 대기 발주 1건
- 가상 직원 5명(정규직 3·파트타이머 2), 입사일부터의 급여 조건, 주간 스케줄, 3개월 명세
- 고정비·공과금·마케팅·정비 비용
- 오픈 체크 완료, 마감 일부 진행, 주간 점검과 7일 체크 기록
- 매장 공통 홈 업무 버튼 구성

직원·거래처는 시연용 가상 이름이다. 실제 연락처·계좌·사업자번호·직원 로그인 계정은 만들지 않는다. 공제는 화면 시연용 수치이며 법정 정산 자료가 아니다. 기존 월 합계 급여 구조로 생성하므로 아직 적용 전인 일별 근무시간 기능의 서버 SQL과 독립적으로 실행할 수 있다.

## 촬영과 주의점

- 홈, 매입/비용, 재고, 레시피, 인건비, 손익, 체크리스트 화면에 적합하다.
- POS 실연동 상태나 직원 본인 계정 화면은 이 SQL로 만들지 않는다. 매출 화면은 수기 매출 모드다.
- 새 매장은 관리자 전체 합계에 포함된다. 실제 운영 보고 시 `래틀`을 제외한다. 앱의 자동 데모 제외 기능은 없다.
- 현재 재고는 과거 입고 이후 사용하고 남은 실사 수량으로 설정했다. 과거 입고량을 다시 더하지 않는다.
- 월별 검산 결과의 급여는 저장된 월 명세 기준이다. 진행 중인 달의 일할 누적과는 구분하며 앱의 카드 수수료 자동 계산도 별도다.

## 검증

2026-10-26 서버의 컬럼·제약조건을 읽기 전용으로 대조했다. 로컬 PGlite에 해당 컬럼과 CHECK, 급여 작성/제출 검증 트리거를 구성해 SQL 전체 실행, 품목/부모 매입 합계, 급여 공제 합계, 중복 실행 차단을 확인했다. 이 축약 검증은 운영 DB의 모든 RLS/트리거 및 실제 앱 화면 검증을 대체하지 않는다. 원격 생성은 실행하지 않았다.
