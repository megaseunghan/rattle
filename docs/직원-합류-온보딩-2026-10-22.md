# 직원 합류 온보딩

> **현재 상태 · 2026-10-23:** 온보딩 테이블·함수와 선행 승인·알림 함수가 원격에 있고 본문이 일치함을 확인했다. 이번에 해당 파일을 재실행하지 않았다. 아래 미적용 서술은 당시 기록이다. 최신 근거는 [SQL 원격 적용 확인](SQL-원격적용-확인-2026-10-23.md)을 따른다.

## 직원 입력 UX

직원은 한 화면에서 질문 하나에 답한다. 이름 → 휴대폰 → 사업자번호 → 근무 형태 → 해당 형태의 급여 질문 2개 → 입사일 → 은행 → 계좌번호 → 최종 확인의 10단계다. 파트타이머에게 월급·비과세를 묻지 않고 월급제 직원에게 시급·주시간을 묻지 않는다.

상단 진행률, 키보드 위의 다음 버튼, 질문 아래 오류 안내를 사용한다. 이전 질문으로 돌아가도 답을 유지한다. 마지막 요약에서 개별 답변을 수정할 수 있고, 고용형태를 바꾸면 새로운 급여 질문으로 안내한다. 입사일은 직접 입력 또는 기본 달력, 은행은 자주 사용하는 선택지 또는 직접 입력을 제공한다. 제출 실패 시 요약과 모든 답을 유지해 다시 시도할 수 있다. 제출 성공 뒤에는 관리자 확인 대기 상태를 보여준다.

관리자 화면은 기존대로 세부내역을 한 번에 비교·수정한다. 이번 질문별 UI 변경에는 새 SQL이나 서버 재배포가 필요하지 않다. 기존 온보딩 SQL이 적용되어 있어야 제출할 수 있다.

## 운영 흐름

1. 직원이 기존 매장 참여에서 이름·휴대폰·사업자번호를 입력한다.
2. 근무 형태를 선택하고 근무 조건 및 계좌 정보를 제출한다.
   - 파트타이머: 시급(원), 주 예정 근무시간(0~168 정수 시간).
   - 월급제 직원: 월 세전 기본급(비과세 포함 총액), 그 안의 비과세 금액.
   - 공통: 입사일, 은행, 본인 명의 급여 계좌번호.
3. 제출은 승인 대기 신청과 `store_join_profiles`에만 저장한다. 직원 생성, 급여 명세 생성, 기존 급여 수정은 하지 않는다.
4. 관리자가 멤버 관리 → 신청 확인에서 세부내역을 확인하고 수정한다. 겹치는 퇴사 기록이 있으면 기존 기록 연결 또는 새 직원 등록을 선택한다.
5. 관리자가 최종 합류를 확인하면 계정 연결·직원 조건·급여 조건 이력을 한 트랜잭션으로 반영한다. 그 전에는 변경 조건을 인건비 계산에 사용하지 않는다.

예전 신청에 온보딩 정보가 없으면 관리자가 직접 세부내역을 입력한 뒤 확정할 수 있다. 입력 계정은 `submitted_by`에 구분해 보관한다.

## 기존·재입사 직원

선택한 직원 ID와 이미 작성된 급여·근무시간 이력은 유지한다. 관리자가 확정한 고용형태·시급·주시간·월급·비과세·입사일·계좌는 현재 직원 정보에 반영하고, 급여 조건은 한국 시각의 오늘부터 새 이력으로 추가한다. 신규 직원은 확정한 입사일을 최초 급여 조건 적용일로 기록한다. 최종 합류만으로 월별 급여 명세를 만들거나 기존 명세 금액을 바꾸지 않는다. 기존 손익 집계의 현재 직원 상태·수습 조건 참조 방식 자체를 변경한 작업은 아니다.

다른 계정의 기록을 덮어쓰거나 여러 퇴사 기록 중 하나를 자동 선택하지 않는다. 이름·연락처 충돌 및 소속 매장 검사는 기존 서버 검증을 유지한다.

## 검토와 보안

제출 원본과 관리자가 확정한 수정본(`reviewed_profile`), 확정 계정·시각·버전을 보관한다. 계좌·급여 조건은 신청자 본인과 해당 매장 관리자만 조회할 수 있다. 클라이언트는 테이블에 직접 입력·수정·확정할 수 없고 RPC만 사용한다. 현재 버전과 다르면 승인하지 않는다. 기존 승인 RPC나 직접 상태 변경으로 새 온보딩 검토를 우회할 수 없다. 직원 생성·급여 조건 이력 중 하나라도 실패하면 신청 상태와 확정 기록까지 모두 롤백한다.

검토 중 직원 재제출이 있으면 관리자는 취소 후 신청 확인을 다시 열어 최신 버전을 확인한다. 제출 실패 시 화면의 입력값을 유지한다. 은행 계좌 실명·소유자 인증은 수행하지 않으므로 신청자와 관리자가 본인 명의인지 확인한다.

## Supabase 적용 — 아직 원격 미적용

기존 20261019 직원 자동 연결·급여 제출 및 20261020 보완 SQL이 적용되어 있어야 한다.

1. `20261021_member_approval_choice.sql`이 미적용이면 먼저 적용한다.
2. `20261022_employee_join_onboarding.sql`을 적용한다.

참여 알림 SQL은 기존 안내에 따라 별도로 적용한다. 홈 합계 SQL은 이 변경과 독립적이다. SQL을 먼저 적용한 뒤 앱을 갱신한다. 네이티브 모듈 변경은 없지만, 이미 설치한 Release 앱에는 새 화면이 자동 반영되지 않으므로 Release 재빌드·재설치가 필요하다.

## 검증

`npm run typecheck`, `npm test -- --runInBand --no-coverage`, `npm run test:sql`.

로컬 SQL은 축약 스키마의 PGlite 검증이며 원격 DB·실제 계정·기기 검증을 대체하지 않는다. 적용 후 실제 직원 제출 → 관리자 수정 → 최종 합류 → 고용형태·급여 조건·계좌 확인, 재입사 과거 명세 유지, 타 직원 계좌 비노출을 확인한다.
