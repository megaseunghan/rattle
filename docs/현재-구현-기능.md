# Rattle 현재 구현 기능

> 기준: 2026-10-17, 현재 작업 트리의 앱 화면·서비스·마이그레이션 코드. 이 문서는 **코드에 구현된 기능**을 설명한다. 운영 DB 적용, 외부 서비스 연동 성공, 실제 휴대폰 동작까지 확인했다는 뜻은 아니다.

## 1. 제품 범위와 현재 상태

Rattle은 여러 매장의 매출·매입·비용·인건비·재고를 모아 월별 손익을 보는 모바일 앱이다. 사장님은 매장별 화면과 전체 매장 대시보드를 사용하고, 승인된 직원은 역할에 맞는 화면을 사용한다.

| 구분 | 현재 방향 |
|---|---|
| 매출 | Toss Place POS 주문 동기화 또는 현금·카드 매출 수기 등록 |
| 지출 | 매입·비용 입력과 월별 손익 집계 |
| 인건비 | 직원 정보, 월 급여, 공제 검토, 월 총 근무 **분** 입력, 정산 확정 |
| 근무시간 | 파트타이머의 월 총 근무 분 입력·제출·관리자 확인 |
| 종합평가·인센티브 | 제품 범위에서 제외 |

화면 코드가 있는 것과 운영에 사용할 수 있는 것은 다르다. 특히 새 월 근무 분 기능은 `supabase/migrations/20261016_manual_work_minutes.sql` 적용 전에는 DB 컬럼과 이력 테이블이 없어 저장할 수 없다. 기존 DB의 마이그레이션 적용 여부와 실제 기기 검증은 이 문서를 작성하면서 확인하지 않았다.

## 2. 사용자, 진입과 화면 구조

- **로그인·매장 선택:** 카카오 로그인, 본인 소유 매장 등록, 사업자번호로 기존 매장 참여 신청, 승인된 매장 선택·전환이 있다. 마지막으로 선택한 매장은 기기에 저장한다. 관련 코드: `app/(auth)/`, `lib/contexts/AuthContext.tsx`, `app/settings/members.tsx`.
- **역할:** 사장님·관리자는 매장 관리와 전체 매장 대시보드에 접근한다. 일반 멤버와 연결된 파트타이머는 화면 범위가 다르다. 파트타이머의 하단 탭은 홈·재고로 줄고, 레시피 화면은 숨긴다. 관리자용 직원·파트타이머 화면 미리보기 기능도 있다. 관련 코드: `app/(tabs)/_layout.tsx`, `lib/hooks/useStorePermissions.ts`, `lib/components/DevRoleSwitcher.tsx`.
- **하단 이동:** 홈, 재고, 매입, 인건비, 매출을 좌우로 넘기거나 탭으로 이동한다. 설정은 별도 더보기 드로어다. 빠른 등록 버튼에서 매출·매입·재고·레시피·직원 등록으로 이동한다.
- **더보기:** 매장 전환, 마이페이지, 매장 정보, 멤버 관리, Toss POS 연동, 알림 설정, 청소 체크리스트, 비밀번호 변경, 약관·개인정보처리방침, 로그아웃·회원 탈퇴가 연결되어 있다. 표시 항목은 역할에 따라 달라진다. 관련 코드: `lib/components/MoreDrawer.tsx`.

### 홈과 통합 대시보드

- **매장 홈:** 선택한 매장의 월 매출·매입·인건비·비용·영업이익을 조회하고 기간별 추이를 표시한다. 재고 부족 건수, 알림함, 고정비 미입력·POS 미동기화·월마감 관련 안내, 업무 바로가기를 제공한다. 관련 코드: `app/(tabs)/index.tsx`, `lib/hooks/useDashboard.ts`, `lib/hooks/useHomeAlerts.ts`.
- **사장님 통합 대시보드:** 보유 매장의 월별·연도별 매출, 지출, 영업이익, 마진을 합산하고 이전 기간과 비교한다. 매장별 카드와 추이 차트, 이번 주 청소 진행률, 요일별 예정 스케줄도 표시한다. 매장 카드를 선택하면 해당 매장 홈으로 전환한다. 관련 코드: `app/admin/index.tsx`, `lib/services/adminDashboard.ts`.

## 3. 매출과 POS

| 기능 | 현재 동작 | 주요 코드 |
|---|---|---|
| Toss Place 연결 | 매장별 연동 상태와 서비스코드 입력 안내를 표시한다. POS가 연결된 매장의 가맹점 ID를 사용한다. | `app/settings/pos-sync.tsx`, `supabase/functions/toss-webhook/` |
| 주문 동기화 | `toss-proxy` Edge Function을 통해 주문 목록·상세와 카탈로그를 가져온다. 주문·품목은 DB RPC로 저장하고 카드·현금 금액도 기록한다. 날짜·월 조회와 자동 동기화 코드가 있다. | `lib/hooks/useTossSync.ts`, `lib/services/tossplace.ts`, `supabase/functions/toss-proxy/` |
| 매출 조회 | 월 달력과 날짜별 매출·주문 건수, 날짜 상세의 판매 품목·수량·금액·카테고리 필터를 제공한다. 매장 마감 시각을 영업일 경계로 사용한다. | `app/pos/index.tsx`, `app/pos/[date].tsx`, `lib/services/posAnalytics.ts` |
| 수기 매출 | 날짜별 현금·카드 매출, 할인액, 메모를 입력한다. 같은 날짜를 다시 저장하면 해당 일자의 수기 매출을 수정하며 목록에서 삭제할 수 있다. | `app/pos/new.tsx`, `lib/services/manualSales.ts` |

POS 매출은 연동 상태와 API 응답에 좌우된다. 카탈로그를 레시피로 가져오는 화면·서비스도 구현되어 있지만, 실제 POS 계정으로 연동과 동기화를 완료했는지는 별도 확인이 필요하다.

## 4. 매입·비용

2026-10-19 변경: 매입서 스캔·OCR 검토 화면을 제거했다. 신규 매입은 품목별로 직접 등록한다.

- **매입:** 월별 목록·합계·삭제, 거래처·날짜·유형과 품목별 수량·단가·소계 등록을 지원한다. 신규 등록은 품목별로 고정한다. 입력 도중 새 재고 품목을 추가하고 카테고리를 관리할 수 있다. 손익 집계에서는 품목이 있는 매입은 품목별 카테고리, 금액만 등록한 매입은 매입 자체의 카테고리를 사용한다. 관련 코드: `app/(tabs)/purchases.tsx`, `app/purchases/new.tsx`, `lib/services/purchases.ts`.
- **비용:** 월별 고정비·마케팅·시설보수·공과금 항목을 등록·수정·삭제한다. 고정비의 수정은 관리자 화면에서 제한한다. 특정 월에 고정비 입력이 없으면 손익 계산 시 직전 등록 월의 고정비를 이어받고, 화면에서 이어받은 항목을 해당 월에 복사할 수도 있다. 카드 수수료는 비용 입력과 별개로 손익 계산에서 카드 매출의 1.25%를 추정한다. 관련 코드: `lib/components/ExpensesPanel.tsx`, `lib/services/expenses.ts`, `lib/services/profitLoss.ts`.

전자세금계산서 **자동 수취** 화면·서비스는 확인되지 않았다. 현재 매입 기능을 자동 세금계산서 수집으로 설명하면 안 된다.

## 5. 재고·레시피·청소

**재고 → 레시피** 목록 상단의 **레시피 추가** 버튼으로 언제든 새 레시피를 등록할 수 있다.

- **재고:** 식자재명·카테고리·단위·현재 수량·품절 임박 기준·최근 단가를 등록·수정한다. 카테고리 필터, 부족 재고 우선 정렬, 잔여량 막대, 정상 재고율과 부족 건수를 보여준다. 재고 카테고리의 이름 변경·삭제 기능도 있다. 관련 코드: `app/(tabs)/stock.tsx`, `app/stock/`, `lib/services/ingredients.ts`.
- **레시피:** 판매가와 재료별 사용량을 입력하여 예상 원가와 마진율을 표시하고 레시피를 저장·수정·삭제한다. 식자재 단위 환산과 카테고리 관리를 지원한다. POS 카탈로그 품목을 선택해 레시피로 추가·업데이트하는 흐름이 있다. 파트타이머에게는 레시피 세그먼트가 숨겨진다. 관련 코드: `app/recipes/`, `lib/services/recipes.ts`, `lib/components/CatalogImportModal.tsx`.
- **청소 체크리스트:** 오픈·마감·요일별 항목을 만들고 순서를 바꾸며, 당일 완료 여부·완료자·시간을 기록한다. 사장님 대시보드에서 주간 진행률을 집계한다. 관련 코드: `app/cleaning/`, `lib/services/cleaning.ts`.

발주 생성·납품 처리 화면은 현재 `app/orders/`에 없다. 저장소의 과거 스키마·설명에 발주가 남아 있어도 현재 앱에서 사용할 수 있는 기능으로 분류하지 않는다.

## 6. 직원·파트타이머 월 근무 분·급여

### 직원 정보와 급여 이력

- 직원의 이름, 정규직·파트타이머 구분, 월 기본급 또는 시급, 주 근무시간, 비과세 금액, 부양가족 수, 입사일, 연락처, 은행·계좌번호를 관리한다. 승인된 매장 멤버 계정과 직원 레코드를 연결하면 본인 화면에서 일정·급여 명세서를 볼 수 있다.
- 시급·기본급 변경은 적용 시작일과 사유를 기록하는 임금 이력으로 관리한다. 정규직의 과거 월 손익을 계산할 때 해당 시점의 급여 이력을 사용한다.
- 직원 삭제·비활성화와 월 급여 내역의 수정·삭제 화면이 있다. 실제 권한은 화면 분기뿐 아니라 적용된 DB RLS에도 의존한다.
- 관련 코드: `app/(tabs)/payroll.tsx`, `lib/services/employees.ts`, `lib/services/wageHistory.ts`.

### 파트타이머 월 총 근무 분 입력

1. 인건비 화면에서 **월과 파트타이머**를 선택하고 **근무시간 입력**을 연다. 월급제 정규직은 근무 분 입력 없이 **급여 계산**으로 급여를 작성한다.
2. 휴게시간을 뺀 **해당 월 총 근무 분**을 정수로 적는다. `미입력`은 값이 없는 상태이고, 근무하지 않았다면 `0분`을 명시적으로 저장한다.
3. 해당 월 급여 계산에 사용할 **적용 시급(원)**을 함께 입력한다. 수습 조건이나 월중 시급 변경은 입력자가 반영하고 미리보기 세전 금액을 검산한다. 과거에 입력된 정규직 근무 분은 삭제하지 않고 선택 정보로 보존한다.
4. **입력 근거 또는 수정 사유**를 작성해 저장한다. 예: `10월 근무 집계표 기준, 휴게 600분 제외`.
5. 화면의 작성·수정 이력에서 변경 전후 분·세전 금액·메모·작성 계정을 확인한다.

파트타이머 세전 급여는 `총 근무 분 × 적용 시급 ÷ 60`을 원 단위 반올림해 계산한다. 저장 시 급여·공제가 갱신되고 정산 확정은 풀린다. 이미 열어 둔 급여가 다른 기기에서 바뀌었다면 `revision` 조건으로 덮어쓰기를 막는다. DB 마이그레이션은 `payroll_work_history`에 작성·수정·삭제 전후 상태와 계정을 기록하며, 기존 출퇴근 데이터는 삭제하지 않고 과거 파트타이머 월별 분을 이전하도록 작성되어 있다. 정산 시 근무 분 필수 조건은 파트타이머에만 적용한다. 관련 코드: `lib/components/WorkMinutesForm.tsx`, `lib/utils/workMinutes.ts`, `lib/services/payroll.ts`, `supabase/migrations/20261016_manual_work_minutes.sql`, `supabase/migrations/20261018_part_time_minutes_settlement.sql`.

### 급여 계산·검토·정산

- 정규직은 월급과 급여 이력을, 파트타이머는 저장한 월 근무 분·적용 시급을 계산 입력값으로 사용한다. 수습 감액, 비과세, 코드상 4대보험·소득세 계산 또는 3.3% 원천징수 분기, 부양가족 수를 반영하는 계산 코드가 있다. **계산 결과는 지급 전 실제 고지·계약 조건과 대조해야 하며, 코드의 비율을 법적 정답으로 보증하지 않는다.**
- 관리자·허용된 사용자는 계산된 공제 항목을 실제 고지액에 맞게 직접 수정하고 예상 실수령액을 확인한다. 공제 합계가 세전 급여를 넘지 않도록 검사한다. 수정하면 정산 확정이 해제된다.
- 월별 정산 리포트에서 직원별 세전·공제·실수령액과 계좌를 확인한다. 재직자의 급여가 없거나 파트타이머 급여의 월 근무 분이 미입력이면 전체 정산 확정을 막는다. 정규직 급여의 근무 분은 없어도 정산할 수 있고, 파트타이머의 `0분`은 입력 완료로 인정한다. 확정된 급여 명세서는 연결된 직원의 마이페이지에서 볼 수 있다.
- 관련 코드: `app/(tabs)/payroll.tsx`, `app/payroll/settlement.tsx`, `app/mypage/payslip.tsx`, `lib/services/payroll.ts`.

## 7. 손익계산서

매장·월을 기준으로 POS 완료 주문과 수기 매출을 합산하고, 매입·인건비·비용을 차감한다. 손익 화면은 월별 명세와 연도별 조회를 제공한다. 관련 코드: `app/profit-loss/index.tsx`, `lib/services/profitLoss.ts`.

| 항목 | 현재 집계 방식 |
|---|---|
| 매출 | POS 완료 주문 + 수기 매출. 카드와 현금·계좌이체 구분 |
| 매출이익 | 매출 − 매입 |
| 인건비 | 정규직 급여 이력 기반 월중 일할 누적 + 저장된 파트타이머 월 세전 급여 |
| 비용 | 해당 월 또는 직전 등록 월의 고정비 + 마케팅·시설보수·공과금 + 카드 매출의 1.25% 카드 수수료 추정 |
| 영업이익 | 매출이익 − 인건비 − 비용 |

매장별 `closing_time`을 POS 영업일 경계로 사용한다. 현재 코드의 `taxReserve`는 `0`이며, 별도의 법인세·부가세 납부액 계산 기능을 의미하지 않는다. 월 근무 분이 미입력인 파트타이머는 급여 저장액이 없으면 손익에 인건비가 반영되지 않을 수 있으므로 정산 전 누락 확인이 필요하다.

## 8. 일정·알림·계정 설정

- **반복 근무 일정:** 직원별 요일·예정 시작/종료 시각·휴무를 설정한다. 직원 변경 요청은 관리자 요청함에서 승인·거절한다. 승인된 일정은 대시보드의 주간 예정표에 반영된다. 이 화면의 시각은 **예정 스케줄**이며 실제 출퇴근 기록이나 급여용 실근무 분의 근거로 자동 사용되지 않는다. 관련 코드: `app/mypage/schedule.tsx`, `app/mypage/requests.tsx`, `lib/services/schedule.ts`.
- **앱 내 알림함:** 매장 알림 조회, 읽음·전체 읽음 처리, 재고·매출/손익 알림 설정을 제공한다. 과거 출퇴근 알림은 목록에서 제외한다. 설정 항목이 존재한다고 해서 각 알림의 자동 생성·외부 푸시 발송까지 검증됐다는 뜻은 아니다. 관련 코드: `app/notifications/`, `lib/services/notifications.ts`.
- **계정·매장:** 실명·연락처·비밀번호 변경, 매장명·주소·일 정산 시간 변경, 멤버 참여 승인·거절·제거, 회원 탈퇴 Edge Function이 있다. 관련 코드: `app/settings/`, `supabase/functions/delete-account/`.

## 9. 구현 범위와 확인이 남은 부분

| 항목 | 현재 판단 |
|---|---|
| 앱 화면·서비스 코드 | 위 기능의 구현 파일을 현재 작업 트리에서 확인 |
| 월 근무 분 DB 전환 | 마이그레이션 파일 작성됨. 검증·운영 DB 적용 여부 미확인 |
| 앱 내 출퇴근·GPS | 현재 화면·라우트에서 제거. 과거 데이터와 일부 이전용 SQL은 보존 |
| 종합평가·인센티브 | 개발 범위에서 제외 |
| 전자세금계산서 자동 수취·발주 화면 | 현재 앱 기능으로 확인되지 않음 |
| 실제 POS·카카오 로그인 | 코드 연결은 있음. 실계정·배포 Edge Function·기기에서 성공 여부 미확인 |
| 테스트 | 앞선 작업에서 타입 검사 및 Jest 93개 통과로 보고됨. 이 문서 작성 단계에서 재실행한 결과는 아님 |

운영 사용 전 우선순위는 ① 검증 DB에서 새 마이그레이션과 기존 급여 이전 대조 ② 운영 DB 적용 ③ 실제 휴대폰에서 로그인, 월 근무 분 저장·수정·충돌·이력·정산 해제 확인 ④ POS/매입과 월 손익 금액 대조다. 적용 절차는 [`README.md`](../README.md)의 **근무시간과 급여 작성** 항목을 참고한다.
