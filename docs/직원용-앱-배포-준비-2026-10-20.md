# Rattle 직원용 앱 배포 준비

확인일: 2026-10-20. 배포 대상은 우선 우리 매장 직원이다. 코드·설정과 공식 배포 문서를 확인했으며, 스토어 계정·인증서·원격 서비스의 실제 등록 상태는 확인하지 않았다. 앱 빌드·업로드·심사 제출은 실행하지 않았다.

## 추천 배포 방식

| 단계 | iPhone | Android | 완료 기준 |
|---|---|---|---|
| 실제 직원 테스트 | TestFlight 외부 테스터 초대 | Google Play 내부 테스트 | 개발 서버 없이 직원 휴대폰에 설치·로그인·업무 저장 가능 |
| 정식 배포 | Unlisted 앱 배포 검토 | Play 정식 배포 또는 조직 관리 기기라면 비공개 배포 검토 | 업데이트 가능한 정식 앱을 직원에게 안내 |

- 직원이라는 이유만으로 TestFlight의 ‘내부 테스터’에 해당하지 않는다. 내부 테스터는 App Store Connect 팀 권한이 있는 사람이다. 일반 매장 직원은 외부 테스터로 초대하며 첫 외부 테스트 빌드에는 베타 심사가 필요하다. [Apple TestFlight](https://developer.apple.com/testflight/)
- Unlisted 앱은 App Store 검색·추천에 노출되지 않고 직접 링크로 설치한다. 최종 배포용 앱의 심사와 별도 요청이 필요하다. 링크를 가진 누구나 설치할 수 있으므로 매장 접근은 로그인·참여 승인·DB 권한으로 제한한다. [Apple Unlisted 안내](https://developer.apple.com/support/unlisted-app-distribution/)
- 테스트 배포를 장기 운영 배포로 간주하지 않는다. 정식 배포 방식은 직원들의 기기 종류와 개인 기기 사용 여부를 확인해 확정한다.

## 현재 프로젝트에서 확인한 준비 상태

| 항목 | 확인 결과 | 필요한 작업 |
|---|---|---|
| 앱 식별자 | iOS·Android 모두 `com.seunghan.rattle` | 배포 계정에서 사용 가능·등록 상태 확인 후 확정 |
| 빌드 설정 | `eas.json`에 development·preview·production 프로필 있음 | Expo 프로젝트 연결·서명·production 환경변수 설정 |
| EAS 연결 | `app.json`에 EAS projectId 없음, iOS 자동 제출 식별값 비어 있음 | 계정에서 실제 프로젝트·App Store Connect 앱 연결 확인 |
| 로그인 | 로그인 화면은 카카오만 제공 | 출시 빌드의 로그인 복귀·취소·재로그인 확인, iOS 동등 로그인 수단 준비 |
| 테스트 버튼 | Root에서 `DevRoleSwitcher`를 개발 모드 조건 없이 표시 | 출시 빌드에서 테스트 보기 UI 제외 |
| 약관·개인정보처리방침 | 앱 문구에 초안 안내가 남음 | 실제 운영 주체·문의처·수집 항목·보관·삭제 기준 확정 |
| 웹 개인정보 문서 | 앱 문서와 수집 항목·삭제 안내가 다름 | 두 문서를 실제 처리 방식에 맞추고 공개 URL 운영 |
| 회원 탈퇴 | 메뉴·Edge Function·과거 삭제 RPC 소스 있음 | 배포·동작 확인, 새 근무시간 이력과 외래키·매장 공동 자료 처리 검토 |
| iPad | `supportsTablet: true` | 지원 유지 시 레이아웃·사용 흐름 확인, 첫 출시에 포함할지 결정 |
| 실제 업무 흐름 | 자동 검사와 일부 시뮬레이터 확인 완료 | 실제 관리자·파트타이머 계정으로 제출·승인·반영·재제출 확인 |

## 출시 전 우선 작업

1. 개발자 계정과 소유 명의를 확정한다.
   - Apple Developer Program: 연 USD 99, 지역별 실제 결제 금액은 가입 화면에서 확인한다. 개인 계정은 개인 법적 이름, 조직 계정은 요건을 충족한 법인 명의가 표시된다. 조직 가입은 D-U-N-S 등 확인이 필요하다. [Apple 가입 안내](https://developer.apple.com/programs/enroll/)
   - Android도 배포한다면 Google Play Console: 등록비 USD 25, 1회. 본인·조직 확인이 필요하다. [Google 가입 안내](https://support.google.com/googleplay/android-developer/answer/6112435)
2. 로그인·계정 삭제·개인정보 안내를 준비한다.
   - 카카오 같은 소셜 로그인으로 앱 계정을 만들면 Apple 4.8의 동등 로그인 수단 요건을 검토한다. Apple 로그인 추가를 우선 권장한다. 직원용이라는 사실만으로 기존 기업 계정 로그인 예외를 충족했다고 단정하지 않는다. [Apple 로그인 요건](https://developer.apple.com/app-store/review/guidelines/#login-services)
   - 심사자가 개인 카카오톡 인증이나 실제 직원 정보 없이 주요 기능을 확인할 수 있는 테스트 계정·매장을 준비한다. 심사 접근 방식은 Apple·Google 요건에 맞춘다. 실제 매출·직원·급여 자료를 심사 계정이나 스크린샷에 넣지 않는다. [Apple 심사 준비](https://developer.apple.com/help/app-review/before-submitting-for-review/complete-review)
   - 탈퇴는 화면 유무만으로 완료 판정하지 않는다. 폐기 가능한 테스트 계정에서 실제 삭제와 실패 복구를 검증한다. 운영 중인 직원 계정으로 탈퇴 실험을 하지 않는다. 보관해야 하는 업무 자료와 계정 삭제의 관계를 확정한다. [Apple 계정 삭제 요건](https://developer.apple.com/help/app-review/guideline-reference/5-1-1-account-deletion/)
   - Play 정식 배포 범위라면 앱 밖에서도 계정 삭제를 요청할 수 있는 웹 경로를 마련한다. 비공개·기업 관리 앱 예외는 실제 배포 형태에 따라 확인한다. [Google 삭제 요건](https://support.google.com/googleplay/android-developer/answer/13327111)
3. 출시용 설정을 완성한다.
   - 운영·테스트 대상 DB를 구분하고 빌드에 들어갈 Supabase URL·공개 키 및 연동 설정을 확인한다. 로컬 `.env`만 존재한다고 클라우드 빌드에 전달된 것으로 판단하지 않는다.
   - 서비스 역할 키·OAuth 비밀 키는 서버에 보관한다. `EXPO_PUBLIC_*`는 앱 이용자에게 노출될 수 있는 값이다.
   - 테스트용 역할 전환 UI를 출시 빌드에서 제외한다. 새 빌드에서 위치·카메라 등 제거한 권한이 남지 않았는지 확인한다.
   - 빌드 번호 증가·서명·배포 환경변수를 설정한다. [Expo 환경변수 안내](https://docs.expo.dev/eas/environment-variables/)
4. 실제 기기 테스트를 마친다.
   - 관리자: 매장 전환 → 직원 신청 승인 → 근무시간 확인 → 급여 반영.
   - 파트타이머: 참여 승인 → 본인 근무시간 제출 → 반려·재제출 → 처리 상태 확인.
   - 매입 유형 편집·품목별 매입 저장·재고 알림 읽음·레시피 추가.
   - 앱 종료 후 재실행, 로그인 취소·만료, 네트워크 끊김·복구, 서로 다른 계정의 접근 제한.
   - 배포 빌드가 개발 서버를 끈 상태에서도 실행되는지 확인한다.
5. 스토어 등록 자료를 준비하고 테스트 버전을 전달한다.
   - 앱 이름·설명·아이콘·실제 기능 스크린샷·지원 URL·개인정보 URL.
   - Apple App Privacy / Google Data safety, 연령 등급·콘텐츠 질문, 심사 계정·작업 순서.
   - 수집·공유 정보는 실제 코드와 사용하는 SDK까지 반영한다. [Apple 개인정보 표시](https://developer.apple.com/app-store/app-privacy-details/), [Google Data safety](https://support.google.com/googleplay/android-developer/answer/10787469)

## 실제 빌드·업로드 순서

계정 등록·Expo 프로젝트 연결·서명·환경변수 확인 이후 실행하는 예시다. 이 문서 작성 중에는 실행하지 않았다.

```sh
# iPhone: 출시용 빌드 생성 → App Store Connect 업로드
eas build --platform ios --profile production
eas submit --platform ios --profile production

# Android도 포함하는 경우
eas build --platform android --profile production
```

iOS 업로드가 곧 App Store 공개를 의미하지 않는다. App Store Connect → 해당 앱 → TestFlight에서 빌드 처리·테스터 그룹·테스트 정보를 확인하고 배포한다. 정식 공개 또는 Unlisted 배포에는 별도 심사·배포 절차가 있다. [Expo iOS 제출 안내](https://docs.expo.dev/submit/ios/)

Android는 Play Console에 앱을 만들고 첫 AAB를 수동 업로드한 뒤 내부 테스트 트랙과 테스터 목록을 설정한다. 이후 자동 제출을 구성할 수 있다. [Expo Android 제출 안내](https://docs.expo.dev/submit/android/)

새 개인 Play 계정으로 정식 프로덕션 접근을 신청하는 경우에는 별도 비공개 테스트 요건이 적용될 수 있다. 2023-11-13 이후 생성한 개인 계정은 최소 12명이 연속 14일 참여한 테스트가 요구된다. 내부 테스트만으로 이 요건을 충족했다고 판단하지 않는다. [Google 개인 계정 테스트 요건](https://support.google.com/googleplay/android-developer/answer/14151465)

## 담당과 다음 행동

- 사용자: 개발자 계정 보유 여부·명의, 직원의 iPhone/Android 사용 비율, 운영 주체·고객 문의 연락처 결정.
- 개발 작업: 테스트 버튼 제외, 로그인·탈퇴 흐름 준비, 문서·웹 URL 정합, EAS 연결·출시 빌드와 실기기 검증.
- 첫 완료 목표: 관리자 1명과 파트타이머 1명이 각자 휴대폰에서 앱을 설치해 제출 → 확인 → 급여 반영을 끝낸다.
