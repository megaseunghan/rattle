## 3. QR 생성 규칙 (직원 폰)
1. `register_attendance_device(p_label)`의 응답 `{device_id, status, secret}`을 받는다. `secret`은 base64 32바이트이고 **이때 한 번만** 내려온다.
2. 저장은 `expo-secure-store`의 `WHEN_UNLOCKED_THIS_DEVICE_ONLY`를 쓴다. 키 이름에 user_id와 device_id를 넣는다. 로그아웃·계정 전환 시 삭제하고, Android 자동 백업에서 제외한다. 출퇴근 기록과 위치는 기기에 저장하지 않는다.
3. QR 화면을 열거나 만료가 가까우면 `issue_attendance_qr(p_device_id)`로 `{nonce, expires_at}`을 받는다. nonce는 24자 hex, 유효 시간은 45초, 1회용이다. 미사용 nonce는 5개까지라 너무 자주 부르면 `ATTENDANCE_QR_RATE_LIMIT`이 난다.
4. 서명은 `sig = hex( HMAC_SHA256(secret_bytes, utf8("{device_id}.{nonce}"))[0..16] )`로 만든다. 16바이트이므로 32자 hex다(`@noble/hashes` 권장).
5. QR 문자열은 `rattle-punch:v1.{device_id}.{nonce}.{sig}`다. device_id는 소문자 UUID, 모든 hex도 소문자다. 서버는 이 형식을 정규식으로 엄격히 검사한다.
6. 갱신은 만료 전에 미리 새 nonce를 받는다(예: 30초마다). 화면 캡처 차단(`expo-screen-capture`)과 밝기 올림(`expo-brightness`)은 선택이다.
7. 기기 상태가 `pending`이면 QR을 만들지 않고 내부 상태 "관리자 승인 대기"를 구분하고 "사장님이나 점장님이 기기를 승인하면 QR을 보여줄 수 있어요."를 안내한다(화면 문구 제안). 기기가 해제됐거나 secret이 없어 재등록이 필요하면 새로 등록하며, 이 경우 관리자 승인이 필요하다.

**계약 갱신 안내(2026-11-18, task_5c8ce73a99b7):** 아래4장의 매장폰 등록 RPC·오류·복구 안내를 설계안 「서버 계약 · 로그인 없는 매장폰 등록」에 맞춰 갱신했다. 이전 관리자 직접 등록 표는 폐기된 이력이며 현재 구현 기준으로 사용하지 않는다. 새 SQL은 로컬 계약·원격 미적용 상태로, 문서 갱신이 앱 연동·실서버 검증을 뜻하지 않는다.

## 4. 서버 계약 (RPC)
권한 표기: auth = 로그인 사용자(`authenticated`), anon = 로그인 없음(스캐너).

| RPC | 권한 | 인자 | 반환 |
|---|---|---|---|
| `register_attendance_device` | auth, 활성 직원 | `p_label text` | `{device_id, status: 'active'\|'pending', secret}` |
| `issue_attendance_qr` | auth, 본인 활성 기기 | `p_device_id uuid` | `{nonce, expires_at}` |
| `approve_attendance_device` | auth, 관리자 | `p_device_id uuid` | void |
| `revoke_attendance_device` | auth, 본인 또는 관리자 | `p_device_id uuid, p_reason text` | void |
| `list_store_attendance_devices` | auth, 관리자 | `p_store_id uuid` | rows `device_id, employee_id, employee_name, label, status, requested_at, activated_at, first_punch_at` |
| `register_attendance_scanner` | **클라이언트 호출 차단**(관리자 포함) | 이전 `p_store_id uuid, p_label text` | 42501. 직접 호출하지 않고 아래 발급/교환 두 RPC로 대체 |
| `issue_attendance_scanner_registration` | auth, 사장/점장 **자기 앱 S52** | `p_store_id uuid, p_label text`(공백 제거1~40자) | `{registration_id, store_id, expires_at, registration_qr}` — 2분·1회용·매장 지정, 새 발급은 이전 미사용 QR 무효화 |
| `exchange_attendance_scanner_registration` | **anon, 로그인 없는 매장폰 S44** | `p_store_id uuid, p_registration_qr text`(전체 QR) | 성공 `{ok:true, scanner_id, store_id, token}`, 거절 `{ok:false, error_code}`. 반드시 `ok` 검사. token은 한 번만 반환·서버에는 해시만 저장 |

| `record_manual_attendance` | auth, 관리자 | `p_store_id, p_employee_id, p_kind('clock_in'\|'clock_out'), p_at timestamptz, p_reason` | punch id |
| `request_attendance_correction` | auth, 본인 또는 관리자 | `p_store_id, p_employee_id, p_action('add'\|'change'\|'void'), p_target_punch_id, p_kind, p_time, p_reason` | request id |
| `review_attendance_correction` | auth, 관리자 | `p_request_id, p_approve boolean, p_note` | 승인 시 새 punch id. 반려 시와 **대상 기록이 그사이 바뀌어 자동 반려된 경우 NULL** |
| `cancel_attendance_correction` | auth, 요청자 | `p_request_id` | void |

- 조회: 기록은 `attendance_effective_punches` 뷰(무효·대체된 원본 제외)로, 원본 이력은 `attendance_punches`로, 정정 요청은 `attendance_correction_requests`로 읽는다. RLS상 본인 기록과 관리자 매장 기록만 보인다. `attendance_scanners.token_hash`는 조회할 수 없다.
- 직접 INSERT/UPDATE 권한은 없다. 모든 쓰기는 RPC로 한다. DB 접근은 `lib/services/`에만 두고 도메인 훅으로 감싼다(AGENTS.md 컨벤션).
- **직원 출퇴근 QR 한정:** `punch_attendance`는 같은 QR을 다시 보내거나 60초 안에 연속 스캔하면 **새 기록 없이 기존 기록과 `duplicate: true`** 를 돌려준다. 같은 QR을 다시 보내면(60초가 지난 뒤라도) **처음 돌려준 기록**을 그대로 돌려준다(보정 마이그레이션 `20261116130000_qr_attendance_fixes.sql`). 단, 이 보장은 **서버가 nonce를 보관하는 동안만**이다. nonce는 만료(발급 45초) 후 1시간이 지나면 다음 QR 발급 때 정리되고, 그 뒤 재시도는 기록이 저장돼 있어도 `ATTENDANCE_QR_INVALID`가 난다. 처음 돌려준 기록이 삭제된 경우에도 다른 기록으로 바꿔 돌려주지 않고 `ATTENDANCE_QR_INVALID`로 거절한다(`20261117120000_qr_attendance_retry_guard.sql`). 그래서 응답 유실 뒤 재시도에서 `ATTENDANCE_QR_INVALID`·`ATTENDANCE_QR_EXPIRED`가 나도 **저장 실패로 확정하지 않고** 직원 기록 조회로 저장 여부를 확인한다.
- **매장폰 등록 QR은 별도 계약:** `exchange_attendance_scanner_registration`은 한 번 소비한 nonce로 토큰을 다시 반환하지 않는다. 교환 응답 유실·시간 초과·`ATTENDANCE_SCANNER_REGISTRATION_USED`는 최초 등록 실패로 단정하지 말고, 관리자 자기 앱의 매장폰 목록에서 생성 여부 확인 → 필요 시 S46 원격 해제 → S52 새 QR 발급으로 복구한다. 매장폰에는 로그인이나 종료를 요구하지 않는다.
- `flags` 값은 `no_schedule`(스케줄 없는 날 출근), `early_clock_in`(시작 10분 전보다 이름), `late_clock_out`(종료 10분 후보다 늦음), `previous_open_over_16h`(16시간 넘게 열린 근무 뒤의 출근), `new_device`(관리자 승인 기기의 첫 기록)다. 하나라도 있으면 S45 "확인 필요"에 올린다.
- 정정 요청 입력 제한: `add`는 kind·시각 필수, `change`는 시각 필수, `void`는 대상만 필요하다. 시각은 1년 전~현재+5분, 사유는 1~500자, 직원당 대기 요청은 10건까지다. 화면에서 먼저 검사한다.
- 날짜 귀속: 출근은 KST 날짜 기준이다. 퇴근은 16시간 안의 마지막 출근 날짜에 붙는다(`work_date`). 화면은 `work_date` 기준으로 묶는다.

## 5. 앱 구조·빌드 주의
- **스캐너 경로**는 로그인 없이 열려야 한다. `app/_layout.tsx`의 인증 리다이렉트에 예외를 둔다. 스캐너 토큰은 SecureStore에 저장한다. 매장폰은 등록 전부터 관리자 계정 로그인/JWT 없이 등록 QR을 교환한다. 토큰은 계정/급여 접근 권한을 주지 않는다. 매장폰에는 로그인/종료/자체 해제 버튼을 두지 않고 관리자 자기 앱 S46에서 원격 해제한다.
- 스캐너 anon 호출은 일반 supabase 클라이언트의 세션과 섞이지 않게 한다(세션 없는 상태에서 RPC 호출).
- 새 패키지는 `expo-camera`, `expo-keep-awake`, `react-native-qrcode-svg`, `@noble/hashes`(선택: `expo-screen-capture`, `expo-brightness`)다. 네이티브 모듈이 추가되므로 런타임 정책(`appVersion`)에 따라 **앱 버전을 1.0.0 → 1.1.0** 으로 올린다. 증빙(매입·비용 사진 첨부) 브랜치의 네이티브 모듈과 **한 번의 새 네이티브 빌드**로 묶는다.
- iOS 권한 문구는 카메라 하나만 둔다: "직원 출퇴근 QR을 스캔하려면 카메라가 필요해요"(문구 제안). **위치 권한 문구는 추가하지 않는다.**
- 시뮬레이터 Release 빌드는 `CODE_SIGN_IDENTITY=-`로 만든다(`CODE_SIGNING_ALLOWED=NO`면 SecureStore가 ERR_KEY_CHAIN으로 실패한다; `docs/EAS-업데이트-운영-2026-10-30.md`).
- 카메라 스캔은 시뮬레이터에서 실제로 확인할 수 없다. 실기기 2대(직원 폰과 매장폰) 확인을 별도 항목으로 보고한다.
- 개인정보처리방침(`app/legal/*`)에 출퇴근 기록(일시·매장·매장폰)과 출퇴근 기기 식별자를 수집 항목으로 추가한다. "출퇴근 기록을 새로 수집하지 않으며" 문구는 고친다. 위치정보 미처리는 유지한다. 초안은 `docs/개인정보처리방침-보완안-2026-11-14.md`에 있다.

## 9. 사용자 결정 반영 · 2026-11-17 (최신 정책, 원격 미적용)
