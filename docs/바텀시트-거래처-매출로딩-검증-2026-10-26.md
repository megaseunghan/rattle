# 바텀시트·거래처 필터·매출 로딩 수정

## 적용

- 투명 Modal 전체를 slide하던 구조를 공통 `SheetModal`로 교체했다. 배경은 고정 위치에서 페이드하고 카드만 측정 높이만큼 이동한다. 닫기 완료까지 내용을 보존하며 빠른 재개방과 시트 간 전환을 보호한다. 시스템 모션 줄이기 설정을 따른다.
- 적용 대상: 매장 선택, 매입/재고 카테고리 관리, 비용 입력, 매입 품목 수정, 매입 등록의 거래처/품목 선택, 레시피 재료 선택/카테고리 편집, 직원 등록·수정/급여 조건 이력, 영업시간 선택, 공통 BottomSheet.
- 중앙 표시인 멤버 승인 Modal은 fade로 변경했다. 이미 배경과 카드를 분리한 손익 상세, 가로 더보기 Drawer는 유지했다. 시스템 pageSheet인 카탈로그/일괄 분류와 불투명 전체 화면 근무시간 폼은 별도 구조다. 투명 slide Modal은 남아 있지 않다.
- 재고와 매입 카테고리 관리 버튼은 동일한 options 아이콘·44pt 터치 영역을 쓴다.
- 매입 목록의 유형 필터를 실제 `supplier` 거래처 필터로 변경했다. 선택한 월에 등록된 거래처만 중복 제거해 표시하고, 매입이 없으면 필터 전체를 숨긴다. 등록 폼의 기존 유형 메타데이터는 보존한다.
- POS 초기 진입은 저장된 자료를 먼저 읽고 동기화한다. 동기화/같은 기간 재조회 중 기존 금액과 달력을 유지하며 진행·실패 안내를 표시한다. 일반 직원의 조회 재시도는 저장된 자료만 읽는다.

## 검증

- TypeScript 및 `git diff --check` 통과. 전체 Jest 74 suites / 438 tests 통과. 코드 리뷰 승인.
- iPhone 16 Pro / iOS 26.3 Release 재빌드·설치 후 실제 React Native 화면으로 확인했다.
- 심금: `동기화 중` 상태에서 오늘 금액·월 합계·달력과 기존 자료 안내가 함께 표시됐다.
- 매장 선택 시트 전후 영상 확보. 수정 후 시작 프레임에서 화면 상단과 중간 배경이 동시에 어두워지고 카드만 아래에서 올라오는 것을 확인했다. 배경 샘플 밝기는 4.20초에 세 위치 모두 0.85로 일치했다. 프레임률 성능 보증 수치는 아니다.
- QA 매장: 10월 실제 거래처 1개 표시, 11월 매입 0건에서 거래처 숨김 확인. 매입·재고 카테고리 시트 열기/닫기, 소프트웨어 키보드 열린 상태에서 닫기, 품목 선택 → 카테고리 관리 → 품목 선택 복귀, 이전 단계의 거래처 입력 보존을 확인했다. 등록은 저장하지 않았다.
- 재고 필터에 저장된 식자재·주류·비품이 로딩 후 표시되는 것을 확인했다.
- 이번 최종 설치본에서 모든 개별 시트를 각각 조작한 것은 아니다. 급여/레시피/비용/영업시간 개별 흐름, Android, 실제 직원 계정과 실기기 손가락 조작은 미검증이다. 공통 구현 검증을 개별 화면의 직접 검증으로 간주하지 않는다.
