# 탈퇴 함수 배포 확인 — 2026-10-21

## 확인한 차이

앱의 Supabase URL과 CLI 연결 프로젝트는 `galrnwpiaedtahoupbgo`로 일치했다. 실제 배포된 `delete-account` 버전 10은 4월 코드였으며, `delete_user_data` RPC 호출 뒤 Auth 사용자를 삭제하는 구형 흐름이었다. 현재 로컬 SQL은 공용 자료 삭제를 막기 위해 해당 RPC 실행을 차단한다. 실제 실패 요청의 로그는 확보하지 않았으므로 해당 요청의 오류 코드까지 확정한 것은 아니다.

## 실제 실행

현재 로컬 `delete-account/index.ts`, `handler.ts`, 공유 Apple 해제·계정 연결 해제 코드를 대상 프로젝트에 배포했다.

- 배포 명령: `npx --no-install supabase functions deploy delete-account --project-ref galrnwpiaedtahoupbgo`
- 배포 결과: 버전 11, ACTIVE, `verify_jwt=true`
- 서버 배포 시각: 2026-10-21T09:43:24.257Z (UTC)
- OPTIONS: HTTP 200
- 배포 후 GET: HTTP 405 (새 핸들러의 삭제하지 않는 메서드 검사)
- 익명 자격으로 읽기 전용 `assert_account_deletable` 호출: HTTP 401 / PostgreSQL 42501. 함수 존재와 익명 실행 거절은 확인했으나, 인증 계정의 소유권 검사나 Auth 삭제 트리거 정의를 직접 대조한 검증은 아니다.
- 관련 로컬 Jest 2개 묶음, 14개 테스트 통과.

이번 작업은 서버 함수 배포이며 새 SQL 적용과 앱 코드 변경은 하지 않았다. 실제 계정 삭제·외부 연결 해제 요청은 보내지 않았다. 이후 사용자가 Google 계정에서 회원탈퇴에 성공했다고 안내했다. Apple·카카오 계정과 다른 데이터 조합의 탈퇴까지 검증한 결과는 아니다. 서버 수정이므로 기존 Release 앱을 다시 빌드할 필요는 없다.
