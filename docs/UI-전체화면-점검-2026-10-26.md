# 전체 화면 UI 점검 · 2026-10-26

## 범위와 판정 방법

UI/UX Pro Max와 기존 DESIGN.md를 기준으로 빌드된 React Native 앱을 직접 열어 확인했다. 기존 화면 경로는 `_layout` 제외 40개이며, 이번에 잘못된 주소 복구 화면 1개를 추가했다. 아래의 ‘확인’은 명시된 상태를 관찰했다는 뜻이며 모든 권한·오류·저장 흐름의 통과를 뜻하지 않는다.

주 대상은 iPhone 16 Pro / iOS 26.3 / Release 1.0.0(1). 현재 로그인은 관리자이지만 선택 매장의 소유자 및 연결된 파트타이머가 아니다. 사용자는 별도 검증 계정이 없다고 확인했다. 운영 계정의 권한·직원 연결을 바꾸지 않았다.

운영 매입·급여·매장 생성·신청 제출·정산 확정·삭제를 실행하지 않았다. 임시 매입 및 합류 신청 입력은 저장 없이 폐기했다. 매출 화면 진입 시 앱의 기존 자동 POS 동기화는 실행됐다. ‘원격 쓰기가 전혀 없었다’는 의미는 아니다. 새 SQL은 없다.

## 이번 수정

1. **수기 매출 키보드**: KeyboardAvoidingView 안에 스크롤과 고정 등록 버튼을 배치했다. 메모 포커스 및 키보드로 인한 레이아웃 변경 시 끝으로 스크롤한다. 금액·메모 입력에 접근성 이름을 제공한다.
2. **달력 가림**: 매출 탭의 FAB를 하단 72pt 전용 공간에 배치한다. 하단 영역에서 좌우 드래그와 빠른 등록 기능을 유지하며 다른 탭의 저장 위치를 보존한다. 날짜 선택 및 선택일 합계까지 스크롤한 화면에서 겹침이 해소됐다.
3. **레시피 원가 상태**: 재료 없음·단가 없음은 0원/100%로 표시하지 않고 확인 필요로 표시한다. 목록·상세·입력 미리보기에 적용했다. 실제 0원 단가는 계산하며 음수 마진은 0으로 잘라 표시하지 않는다. 미확인은 이익색 대신 중립색을 쓴다. DB 원본·단가를 변경하지 않았다.
4. **접근성**: 재료 선택 모달의 부모 Pressable이 전체 내용을 하나로 묶지 않게 했다. 닫기와 품목 각각이 AX 요소로 노출되는 것을 확인했다. 레시피 뒤로가기 이름과 합류 최종 요약의 항목·입력값·수정 동작 이름을 보완했다. VoiceOver 실제 음성 낭독 시험과는 다르다.
5. **잘못된 주소 복구**: 기본 Unmatched Route의 Sitemap에서 `SystemInfo`의 `origin` 참조 예외로 Release 앱이 종료되는 로그를 확인했다. 사용자용 `+not-found` 화면을 추가하고 인증·매장 상태에 따라 로그인/매장 선택/홈으로 복귀하도록 했다. 인증 로딩 중 복귀를 막는다.

## 최종 설치본과 재확인

- 최종 Release bundle SHA-256: `cc2681e3665768011c2cd15e6c52a39b997f6395a58e47efa2dc1deafd9c8757`. iPhone 16 Pro 및 별도 비로그인 iPhone 16e 시뮬레이터에 설치했다.
- 16 Pro에서 메모에 포커스한 뒤 소프트웨어 키보드를 열었을 때 메모 입력칸 전체와 등록 버튼이 모두 키보드 위에 보인다. 첫 재빌드에서 자동 스크롤이 부족한 것을 확인하고 추가 보완 후 재확인했다.
- 매출 탭에서 날짜 선택 후 아래 합계까지 실제 스크롤했다. 달력·합계와 FAB의 전용 하단 영역이 겹치지 않는다.

- 합류 요약의 입력값 포함 접근성 이름은 자동 테스트로 검증했다. 수정 후 요약의 VoiceOver 및 네이티브 재진입 검증은 남아 있다.
