선행 함수 25개를 로컬의 최신 정의와 원격 본문으로 비교했다. 이는 해당 파일들의 과거 실행 시각이나 마이그레이션 이력표를 확인했다는 뜻은 아니다. 후속 SQL이 앞선 함수를 교체하므로 구형 파일을 다시 실행하면 안 된다.

## 데이터·권한 확인

- 기존 매장 4곳은 모두 `all_staff` 유지. 새 매장의 `financial_share_scope` 기본값은 `none`.
- 금융 원천 테이블 6개의 RLS 활성화와 restrictive 공유 정책, 금융 알림 restrictive 정책 확인.
- 집계·POS·매입 함수 8개에 공유 권한 검사 확인. 홈 집계는 급여 조건 누락을 보존하는 v2 함수 사용.
- 익명 역할은 매장 생성·공유 설정 변경 함수 실행 불가. 인증 역할의 생성 함수 실행 권한은 유지하며 함수 내부에서 본인 여부를 검사한다.
- 읽기 전용 트랜잭션에서 소유자 claim의 손익 접근 허용 및 2026-10 집계 1행 반환 확인. 인증 주체 없는 claim의 손익 접근·원천 매출·원천 매입 차단 확인. 이는 실제 직원 계정의 로그인 흐름 전체 검증을 대신하지 않는다.
- 적용 전후 매장 **4건**, 직원 **12건**, 급여 **14건**, 급여 조건 이력 **11건**으로 동일. 급여와 급여 조건 이력은 정렬된 전체 행 내용의 지문까지 동일하다. 금액·과거 적용일을 추정해 보정하지 않았다.

## toss-proxy 배포

기존 운영 버전 17은 인증 검사가 없는 구형 코드였다. 원격 소스를 별도로 보관한 뒤 현재 권한 검사 구현을 **버전 18, ACTIVE**로 배포했다.

- 기존 게이트웨이 설정 `verify_jwt=false` 유지. 함수 내부에서 `getUser(token)`과 매장별 공유·승인 소속을 검사한다. 인증을 생략한다는 뜻이 아니다.
- 허용된 Toss GET 경로·쿼리만 프록시하며, 리다이렉트 차단·20초 timeout 유지.
- 실제 HTTP 확인: GET **405**, 익명 POST **401**, 잘못된 JWT의 POST **401**.
- 로컬 프록시 경계 테스트 **16개 통과**, SQL 가상 스키마 검증 전체 통과. 실제 인증 계정의 Toss 원자료 조회는 이번 배포 검사에서 수행하지 않았다.

## 보관 및 남은 범위

변경 전 함수·정책·컬럼·인덱스·트리거·View 정의, 적용 전후 검사 결과와 구형 프록시 코드는 Git 제외된 로컬 `docs/private/sql-deployment-2026-10-23/`에 보관했다. 이는 전체 DB 데이터 백업이나 실제 복원 검사를 뜻하지 않는다.

이번 작업분에서 사용자가 추가로 수동 실행할 SQL은 없다. 매장 생성·공유 범위 변경·직원 최종 합류 같은 실제 업무 자료 쓰기는 시험하지 않았다. 실계정의 세 정책·고용형태별 흐름과 TestFlight/실물 iPhone 확인은 별도다. 앱 재설치가 이번 서버 적용으로 자동 수행되지는 않는다.
