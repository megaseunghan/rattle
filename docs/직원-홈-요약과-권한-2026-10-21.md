# 직원 홈 요약과 권한

> **현재 상태 · 2026-10-23:** 현재 홈 집계는 매장별 공유 정책으로 제한되며, 기존 매장 all_staff·새 매장 none이다. 2026-10-23 원격 적용을 확인했다. 아래 전체 구성원 공유 설명은 당시 기준이다. 최신 근거는 [SQL 원격 적용 확인](SQL-원격적용-확인-2026-10-23.md)을 따른다.

## 변경

승인된 매장 구성원은 고용형태와 관계없이 소속 매장의 홈에서 매출·매입·인건비·비용·영업이익과 최근 6개월 추세를 조회한다. 관리자와 직원 홈은 동일한 집계 RPC를 사용한다. 상세 손익과 개인 급여 조회 권한은 확대하지 않는다.

`get_home_financial_summary`는 서버에서 계산한 월별 합계 7개 필드(대상 월 포함)만 반환한다. 직원 이름·계정·급여·공제 내역은 반환하지 않는다. 직원별 테이블의 RLS는 유지한다. 승인 대기·비소속 계정과 익명 사용자는 조회할 수 없다.

합계는 현재 구현의 손익 기준을 따른다. 매출은 POS 동기화분과 수기 매출, 매입은 해당 월 매입액이다. 정규직 인건비는 재직자의 급여 이력을 일할 계산하고, 파트타이머는 퇴사자를 포함해 저장된 월 급여 금액을 사용한다. 비용은 유효 고정비(직전 등록 월 이어받기)와 마케팅·시설보수·공과금·카드 수수료 1.25%를 포함한다. 영업이익 = 매출 - 매입 - 인건비 - 비용이다. 진행 중인 달은 누적/입력 기준이며 정산 완료 금액을 의미하지 않는다.

영업일과 월은 한국 시각을 사용한다. POS 월 경계는 기존 손익과 동일하게 해당 월 1일 마감시각부터 다음 월 1일 마감시각까지이며, 진행 월은 현재 시각까지 조회한다. 기존 손익의 재직/퇴사 정규직 및 수습 판단 방식을 변경하지 않는다.

## 권한 비교

| 기능 | 사장·관리자 | 일반 직원 |
|---|---|---|
| 소속 매장 홈 요약·추세 | 가능 | 가능(파트타이머 포함) |
| 상세 손익·손익 정산 화면 | 가능 | 불가 |
| 직원 정보·개별 급여·급여 이력 조회 | 매장 전체 | 본인만 |
| 직원 등록·수정·퇴사·급여 작성·공제·정산 | 가능 | 불가 |
| 월별 근무시간 제출 | 확인·반려·급여 반영 | 연결된 파트타이머 본인 제출 |
| 매입·재고 운영 입력 | 가능 | 기존 운영 권한 유지 |
| 비용 입력·수정·삭제 | 고정비·변동비 | 변동비 가능, 고정비 변경 불가 |
| 레시피 | 관리 가능 | 일반 직원 가능, 파트타이머 메뉴 제한 |
| 참여 승인·멤버 관리·POS/매장/알림 설정 | 가능 | 불가 |
| 매장 소유권 이전 | 소유자 본인만 | 불가 |

관리자는 소유자 외에 `admin` 역할을 받은 매장 멤버를 포함한다. 파트타이머는 기존대로 홈·재고 중심의 간소화 메뉴를 사용하지만 이번 홈 합계는 동일하게 볼 수 있다. 메뉴 제한과 DB에서 강제하는 권한은 구분하며, 기존 메뉴 제한을 새로운 서버 제한으로 보고하지 않는다. 실제 서버의 다른 도메인 권한은 기존 마이그레이션 적용 상태에 영향을 받는다.

## 적용

원격 Supabase에는 아직 적용하지 않았다. 기존 20261019 및 20261020 마이그레이션 이후 아래 파일을 실행한다.

1. `supabase/migrations/20261021_home_financial_summary.sql`

이전 참여 알림·퇴사 직원 선택 승인 마이그레이션과 독립적이다. 해당 변경도 미적용 상태라면 각 안내 파일에 따라 별도로 적용한다. 이번 파일을 적용하고 앱을 새로고침한다. 네이티브 재빌드는 필요 없다.

## 검증

`npm run typecheck`, `npm test -- --runInBand --no-coverage`, `npm run test:sql`로 확인한다. SQL 테스트는 사장·직원 합계 동일, 급여 인상 일할, 퇴사 파트 급여, 고정비 이어받기, 수기 매출·카드 수수료, 승인 대기·타 매장 차단과 타인 급여 비공개 유지를 확인한다. 축약 스키마의 로컬 PGlite 검증이며 실제 서버·계정·기기 검증을 대체하지 않는다.
