# 급여 계산 바로잡기 (의도 확정본)

**확정:** 2026-11-27, 사용자 확인 (grilling Q1~Q21, 세무사·노무사 관점 검토 2회 후). 진행 순서는 A(매장 만들기) 시안 다음.
**짝 문서:** `매장-만들기-마저-채우기.md` (A)

## 목표 (Why)

- 앱의 급여·손익 계산은 실제 지급과 다를 수 있는 **예상값**이다. 이를 화면에서 분명히 한다.
- 세무·노무 기준과 어긋난 계산을 바로잡는다.
- 2027년 1월 급여부터 계산이 막히지 않게 한다(`lib/services/payroll.ts`가 2026년만 허용).

## 정한 것

- 수습: 사장님이 수습으로 표시한 직원에게만, 입사일부터 매장(또는 직원별) 수습 기간 동안 적용. 판정은 오늘이 아니라 계산 대상 월 기준. 수습 중 퇴사 80%는 앱 공통 규칙이 아니므로 제거.
- 소득 구분: 근로자(기본) / 일용근로자 / 프리랜서(3.3%). 합류하는 멤버가 고르고 사장·점장이 합류 승인 때 확인. 근무시간으로 3.3%를 자동 결정하지 않는다. 근무시간이 비어 있으면 공제하지 않고 입력을 안내한다.
- 최저임금: 미달이면 저장 때 경고(막지 않음).
- 주휴수당: 시급에 주휴 포함/별도를 고름. 별도면 주 15시간 이상인 주에 예상 주휴수당 표시.
- '예상' 표시: 명세서·정산·손익에서 확정처럼 보이는 문구를 예상으로 바꾼다. 직원 명세서는 정산 전 여부를 구분한다. 우리는 세무사처럼 확정해 주지 않는다.
- 손익: 인건비 아래 '사업주 부담 4대보험(예상)' 추가. 퇴직금 적립은 넣지 않는다.
- 보험·세액: 국민연금 상·하한을 적용 기간별 값으로, 장기요양은 법정 산식(건강보험료 기준)으로, 간이세액표는 2026.3.1 개정 반영, 2027년 기준을 미리 넣는다(고시 원문 확인값만, 미확인은 '확인 필요'로 막기).
- 기록 내려받기: 설정과 매장 삭제 확인 화면 두 곳에서 급여·근무 기록 CSV(세무사 전달용). 매장 삭제 후 우리 쪽 자료는 삭제 유지(개인정보처리방침과 같음).

## 하지 않을 것 (Out of scope)

- 연장·야간·휴일 가산 자동 계산, 연차·퇴직금 계산, 원천세 신고 연동, PDF 임금대장.
- QR 출퇴근 휴게시간 차감(보류).
- 특정 회사(사용자 재직 회사)의 수습 규칙을 앱 공통으로 두는 것.

## 확인 필요

- 2026·2027년 요율·상하한·최저임금의 고시 원문, 최저임금법 5조2항 원문.
- 77만 원 미만 구간 처리(현재 계산 실패), 자녀 수 차감(별표2 제3호) 반영 범위.
- 정산 확정 급여의 하드 삭제 차단 여부. 계좌번호 암호화는 2026-11-27 구현(적용 범위는 전문가 확인 권장).
- 근거 검토: 세무사·노무사 관점 검토 2회(2026-11-27, 에이전트 자체·독립 검토). 전문가 확인 아님.

## 계획 확인 중 추가 결정 (2026-11-27, 사용자 확인)

- 기존 자료(개발 중이라 단순하게): 기존 직원은 모두 '근로자'로 채운다. `is_probation=true` 직원은 입사일부터 61일을 수습 기간으로 넣고, 표시 없는 직원은 100%로 계산한다.
- 일용근로자 공제 범위: 일별 소득세(일 15만 원 공제·6%·55% 감면·1,000원 미만 미징수) + 지방소득세 10% + 고용보험 근로자분. 국민연금·건강보험은 '확인 필요' 안내.
- 일용근로자 입력 구조: 계정 없이 사장·점장이 입력한다(야미옥 Notion 「파출부 급여」 구조 참고). 매장별 일용근로자 명단(이름·연락처·은행·계좌·평일/주말 기본 일당)과 하루 한 건 근무 기록(근무일·일당·추가수당·메모·지급상태·지급일). 주말은 날짜로 자동 판단하고 고칠 수 있다(공휴일 판단 없음). 근무일이 속한 달 손익 인건비에 포함한다.
- 직원 합류의 '계약' 선택지에서 '일용근로자'를 뺀다(근로자 / 프리랜서 3.3% / 잘 모르겠어요). A 시안 확정 변경.
- 주민등록번호·외국인등록번호·비자는 앱에 저장하지 않는다. 신고용 자료는 CSV로 세무사에게 넘긴다.
- 산재 업종 요율: 요율 DB(업종·적용 기간·출처·확인 상태)를 만들고 「마저 채우기」 4대보험 묶음에서 고른다(매장 만들기 아님). 고르기 전 손익에는 '산재보험 미포함'. 업종별 값은 고시 원문 확인 후 넣는다.
- 화면 입력은 (가): 이번 B에서는 현재 직원 폼·합류 승인 화면에 최소 필드만 더하고, 새 디자인은 A에서 한다.

## 교차검증 후 결정 (2026-11-27, 사용자 확인)

- 사업주 부담 4대보험(예상)을 영업이익에서 뺀다. 서버 `get_financial_summaries_v2`와 앱 `profitLoss.ts`가 같은 식이다. 고용안정 요율이 없는 달은 영업이익을 비운다. 그 달 명세를 아직 작성하지 않은 직원은 추정에서 빠지며, 화면에서 그 인원을 안내한다.
- 일용 소득세는 지급할 때 계산한다. 하루 기록에는 하루 산출세액만 저장하고, 1,000원 미만 미징수와 10원 버림은 지급 묶음(`daily_labor_payments`) 합계로 정한다. 화면 안내 문구가 있다. 지급된 기록은 금액 수정·삭제를 막고, 고치려면 지급을 취소한다.
- 계좌번호를 암호화한다. Vault 키 `rattle_account_number_key`가 없으면 SQL 적용 때 새로 만든다(삭제·교체 금지). 화면에는 끝 4자리만 보인다. 전체 번호는 `reveal_account_number`로 받는다(직원: 사장·점장·본인 / 일용: 사장·점장 / 합류 신청: 사장·점장·신청자).
- 파트타이머 일별 근무에도 수습 90%를 근무일별로 넣는다(서버 트리거, 새 기록만). 이미 저장된 기록은 바꾸지 않는다.
- ~~하지 않음: 수습 직원 최저임금 미달 경고(H2)~~ → 2026-11-27 변경(아래 「수습 비율」).

## 수습 비율 (2026-11-27 사용자 결정, A 세션 전달)

- 고정 90%를 매장 기본값(`stores.default_probation_rate`, 기본 0.9)과 직원별 비율(`employees.probation_rate`)로 바꾼다. 보기와 입력 화면은 A가 맡는다: 매장 만들기 수습 기간 아래 90%(기본)/95%/직접 입력, 합류 승인 '수습 적용' 시트. 90% 미만은 직접 입력으로만 넣을 수 있고 막지 않는다.
- 직원 비율이 비어 있으면 저장할 때 DB가 매장 기본값으로 채운다. 이후 매장 기본값을 바꿔도 이미 정한 직원 비율은 바뀌지 않는다(B 판단). 기존 수습 직원은 0.9로 채운다.
- 계산: 앱 `lib/payroll/probation.ts` `probationRateOf`, 서버 정규직 일할 추정·일별 근무 트리거에 같은 비율을 쓴다. 보정 마이그레이션은 `20261127130000_probation_rate.sql`(원격 적용본 md5 가드)이다.
- H2 변경: 정한 비율대로 계산하고 막지 않는다. 결과가 최저임금의 90%보다 적으면 회색 안내를 띄운다: "최저임금의 90%보다 적어요. 수습이어도 이보다 적게 줄 수 없어요." 판단 함수는 `isBelowProbationFloor`, 문구는 `PROBATION_FLOOR_NOTICE`. 합류 승인 수습 시트와 직원 명세서에 붙이는 작업은 A 화면 작업에서 한다. 1년 미만 계약·단순노무 참고 안내는 그대로 둔다.

## 수습 기간 = 시작일부터 3개월 (2026-11-27 사용자 결정, A 세션 전달)

- '90일'이 아니라 달력 3개월로 센다(입사일에 따라 89~92일). 마지막 날은 N개월 뒤 같은 날의 전날이다. 그 달에 같은 날이 없으면 그 달 말일로 한다(예: 6/1 → 8/31, 12/1 + 3개월 → 2/28, 1/31 + 1개월 → 2/28·윤년 2/29).
- 매장 기본 수습 기간은 없음/1/2/3개월만 둔다. `stores.default_probation_days` 열을 없앴다(원격 사용 0건). 앱의 일 단위 기간(`kind: 'days'`, `MAX_PROBATION_DAYS`)도 없앴다.
- 직원 수습 마지막 날은 시작일(없으면 입사일) ~ `maxProbationEnd(시작일)` 안이어야 한다. 서버 트리거가 범위 밖 값을 막는다(`PROBATION_END_OUT_OF_RANGE`). 앱은 "수습 마지막 날은 입사일부터 3개월 안에서 골라 주세요."로 안내한다.
- 수습 비율 입력은 1~100%다(100% = 줄이지 않음). DB는 0 초과 1 이하를 받는다.
- 기존 자료 이전 규칙(입사일 포함 61일)은 항상 3개월 안이다. 원격에는 수습 마지막 날이 있는 직원이 0명이다.
- 반영 파일: 보정 마이그레이션 `20261127130000_probation_rate.sql`(원격 미적용), `lib/payroll/probation.ts`, `lib/services/employees.ts`.

## 일용근로자 등록·지급 상태 기록 (2026-11-27 사용자 결정, A 세션 전달)

- 일용근로자는 합류코드로 받지 않는다. 매장이 S54 급여대장에서 직접 추가한다(`daily_laborers`, 기존 구조 유지). 일반 직원은 합류 신청으로만 들어온다. 합류 계약 보기와 직원 소득 구분에서 '일용근로자'를 뺀다. 화면은 A가 맡는다.
- 앱은 돈을 보내지 않고 지급 상태만 기록한다. 근무 기록은 '지급 대기'로 쌓이고, 골라서 '지급 완료로 바꾸기'를 누르면 지급일·지급 방법(계좌이체/현금)·공제(소득세·지방소득세·고용보험)를 적는다.

- '지급하기'·'지급 처리'처럼 송금하는 것 같은 말은 쓰지 않는다. 화면과 내보내기 문구를 '지급 대기·지급 완료'로 바꿨다.
- 반영: 보정 마이그레이션 `20261127131000_daily_labor_payment_method.sql`(원격 미적용, 원격 지급 기록 0건), `lib/services/dailyLaborers.ts`, `app/payroll/daily-laborers.tsx`(임시 화면).
