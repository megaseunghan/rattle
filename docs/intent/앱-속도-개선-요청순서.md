# 앱 속도 개선 — 요청 순서 줄이기 (의도)

- 확정: 사용자, 2026-11-24 (grilling, Q1~Q16 전부 추천안 승인)
- 근거 측정: `docs/workspaces/앱-속도-측정-요청순서-2026-11-24.md` (시뮬레이터 + 실기기 iPhone 16 Pro, 6절·10절 후보)
- 선행 의도: `docs/intent/앱-속도-측정-요청순서.md`

## 목표 (Why)

앱 시작·홈·탭 진입 때 "앞 요청이 끝나야 다음 요청이 나가는" 순차 겹수와 불필요한 요청 수를 줄여 체감 대기를 줄인다. 서버(Nano) 실행 시간 자체는 이번 범위가 아니다.

## 완료 기준 (Success)

- 주 기준은 **겹수·요청 수**. 시간은 같은 실기기에서 전후 비교만(참고).
- 홈(앱 시작 → 홈): 5겹 → **3겹 이하**.
- 매입·재고·매출 첫 진입: **1겹**. 인건비 첫 진입: 1겹 목표, 2겹 허용.
- 중복 요청(스케줄 2회, 출퇴근 취소 1회, 매입 카테고리 2회, 매출 재진입 2회) 제거.
- 재진입·홈 복귀: 받은 지 30초 안 된 자료는 다시 받지 않는다(④단계).
- 단계마다 실기기(측정용 앱 Rattle Perf, 같은 테스트 관리자 계정·매장)에서 같은 방법으로 다시 재서 전후 비교.
- 직원·파트타이머 QA 계정으로 시뮬레이터에서 홈 화면·권한 회귀 확인(숫자 측정은 관리자만).

## 단계와 방법 (확정 결정)

단계마다 PR 1개, 순서 ①→②→③→④→⑤. PR 생성·병합은 그때마다 사용자에게 묻는다. 각 단계는 main에서 새 브랜치·worktree.

1. **① 홈 순서 줄이기 (앱만)**
   - Q7: 일별 조회의 `summary.isSuccess`·`scheduleIdleTask` 대기 제거. `assert_store_finance_access`를 일별 RPC 6개와 **동시에** 호출하고, assert가 실패하면 함께 받은 결과는 버린다(화면은 지금처럼 막힘). 재측정 때 손익 요약 응답 시간을 함께 보고, 눈에 띄게 늘면 유휴 대기만 되살린다.
   - Q8: 홈 출퇴근·스케줄은 권한 응답(`get_my_store_access`)의 본인 `employee_id`로 바로 시작(관리자 미리보기는 미리보기 직원 ID 유지). `getEmployees`의 시급 조회는 직원 조회와 동시에(가능 여부는 구현 때 확인).
2. **② 공통 정리 (앱만)**
   - Q9: 원격 개발 DB의 PostgREST max rows를 **읽기 전용**으로 확인해 500 이상이면 `readAllRows`를 "500 미만이면 종료"로 바꾼다. 경계 테스트(500·499행) 추가. 운영 DB 분리 때 같은 설정 확인을 남긴다.
   - Q10: 마운트 effect + focus effect 이중 호출만 하나로 줄인다(스케줄·출퇴근·매입 카테고리·매출). React Query 이관은 ④에서.
3. **③ 재고·매출 탭 (앱만)**
   - Q11: 앱 시작 때 받은 매장 정보에 POS 연결 여부가 있으면 그 값으로 수기 매출을 바로 조회(1겹). 없으면 첫 진입 2겹 유지. "동시에 보내고 버리기"는 쓰지 않는다.
   - Q12: 레시피 조회에 `recipe_costs`를 함께 담는다(2겹 → 1겹). 원가 없는 레시피는 지금처럼 오류. 개발 DB 읽기 전용 조회로 먼저 확인.
4. **④ 재진입 캐시 (앱만)**
   - Q13: 탭 재진입 때 30초 안 된 자료는 재요청하지 않음(재고 60초는 유지). 당겨서 새로고침은 항상 재요청. 저장 후 cancel → invalidate, 신원 변경 시 `clearQueryData()` 규칙 유지. 직접 만든 조회 훅(`useAttendanceToday`, `useCategoryTaxonomy`, `usePurchaseTypes`, `usePurchases` 등)을 React Query로 옮긴다. 손익처럼 오래된 값이 문제 될 화면은 구현 때 따로 표시해 사용자에게 묻는다.
5. **⑤ 서버 변경 (마이그레이션 + DBA 관점 검토, 원격 적용은 별도 승인)**
   - Q14 (a): `get_home_daily_sources`에 관리자 검사를 넣고 앱의 assert 호출을 없앤다(①의 노출 틈 막기).
   - Q14 (b): 부트스트랩에 권한·직원 ID를 합쳐 권한 요청 1겹 제거.
