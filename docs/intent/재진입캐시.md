# 의도: 앱 속도 ④단계 재진입 캐시 (2026-11-24 사용자 확정)

## 목표(Why)

탭 재진입이나 홈 복귀 때 같은 자료를 매번 다시 요청하지 않게 해서 Supabase Nano 서버의 동시 요청 경쟁을 줄인다. 실측(2026-11-24, iPhone 16 Pro)에서 홈 복귀는 9~10건, 매입·인건비·매출 탭 재진입은 각각 5·7·5건이었다. 요청 수는 줄이되 내가 저장한 값은 바로 보이고, 남이 바꾼 값은 자료별로 정한 시간 안에 보여야 한다.

## 완료 기준

- 무조건 다시 받기(`useFocusEffect` 안의 `refetch()`)를 없앤다. 캐시 없는 useState 훅을 기존 키 체계(`'rattle'` → scope → storeId → domain)의 useQuery로 옮긴다.
- 자료별 재사용 시간표를 적용한다. 시간표는 `docs/앱속도-재진입캐시-TanStack전략-2026-11-24.md` 0장을 따른다.
- 같은 실기기 측정으로 재진입 요청 수가 줄었는지 확인한다. 시뮬레이터 확인 뒤 기존 iOS `preview` 채널로 EAS Update를 발행한다.
- 모든 변경은 한 PR로 낸다.

## 하지 않을 것(Out of scope)

- "n분 전 기준"·"업데이트 중" 같은 새 화면 표시
- 확정 직전 재확인과 값이 다를 때 확정을 멈추는 장치
- P3 훅(손익 상세 `useProfitLoss`, 스케줄, 알림 등) 전환
- `subscribed` 옵션, `onlineManager`, 서버 변경 시각 RPC, Supabase Realtime
- 로컬 DB, 금액 persist
- `AuthContext`의 앱 복귀 `loadStores`(보안 목적), 매장폰 스캐너 주기
- 원격 DB 조회·변경. 실제 기록 기반 히트맵 조사는 릴리즈 뒤 별도 작업으로 하고, 그때 허락을 받는다.
