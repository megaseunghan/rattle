# Notion 「Rattle 개발 문서」 목차 개편 (의도 확정본)

**확정:** 2026-11-21, 사용자 명시적 "예" (interview-me)
**대상 문서:** Notion 「Rattle 개발 문서」 https://app.notion.com/p/40fef865970a8144a470dc60ea8ee663

## 목표 (Why)

여러 세션을 동시에 돌리면서 사용자 검토 없이 What만 쌓였고, 앱 방향이 흔들렸다. 지금 개발 문서는 날짜별 작업 일지라서 현재 정책과 진행 상태를 찾을 수 없다.

개발 문서를 **목차 페이지**로 바꾼다. 맨 위에 상위 목표와 큰 Why(RATTLE-DIRECTION-20261116-v1)를 둔다. 그 아래에서 기능마다 기획부터 출시까지 어디까지 왔는지 한눈에 보이게 하고, 각 기능 페이지로 연결한다.

**이 문서를 쓰는 사람과 용도**
- AI: 작업을 시작하기 전에 이 개발 문서를 먼저 읽고 기준으로 삼는다.
- 사용자: 아래 세 가지에 쓴다.
  1. 정책 확인: 새 변경이 기존 정책과 부딪히는지 본다.
  2. 다음에 맡길 일을 고른다.
  3. 기능별로 어디까지 완성됐는지 확인한다.

## 구조

- **목차 (상위 페이지):** 상위 목표·Why, 기능 목록 표(기능 / 현재 단계 / 막힌 곳·다음 할 일), 공통 정책 링크, 맨 아래 「과거 기록」 링크.
- **기능 페이지:** Why, 하지 않을 것, 정책, 영향 받는 기능 링크, 부딪힐 수 있는 정책 ⚠️, 단계별 증거, 확인 필요.
  - 시범 형식: 「QR 출퇴근 · 기능 기준 기록」
- **공통 정책 페이지:** 역할·열람 설정, 급여 지급 기준처럼 여러 기능에 걸친 정책을 따로 둔다. 기능 페이지와 서로 링크해 그물처럼 연결한다. Obsidian에서 하려던 그래프를 Notion에서 만드는 것이다. Obsidian을 쓰지 않는 이유는 사용자가 사용법에 익숙하지 않아서다.
- **단계:** `기획 → 정책 확정 → 디자인 확정 → 구현 → 구현 화면과 디자인 대조 → 실기기 확인 → QA → 출시`
  - 출시 = 스토어 정식 공개. iOS(App Store)와 Android(Google Play)를 각각 표시한다.
  - preview EAS 발행은 출시가 아니다.

## 정책 작성 규칙

- AI가 초안을 쓰고 사용자가 확정한다. 정책 칸에는 사용자가 확정한 문장만 둔다. AI 추정·해석·미결정은 「확인 필요」에 둔다.
- 사용자가 이해하지 못하거나 모순을 놓칠 위험을 줄이기 위해, 정책마다 아래 형식을 쓴다.
  - 정책 문장
  - 예시 (누가·언제·무엇을 하면·화면에 무엇이 보이는지). 권한·돈·기록 삭제처럼 헷갈리기 쉬운 정책에 붙인다.
  - 영향 받는 기능
  - 부딪힐 수 있는 기존 정책 ⚠️. AI가 확인 요청 전에 먼저 찾아서 짚는다.

## 증거 규칙

- 사용자가 직접 볼 수 있는 증거가 없는 단계는 완료로 표시하지 않는다.
  - 디자인 확정 = 확정 시안 링크
  - 구현 = PR 링크
  - 구현 화면 대조·실기기 확인 = 캡처
- AI의 "검증 통과" 문장만으로는 증거가 아니다. 예: QR 출퇴근은 실기기 확인 기록은 있으나, 사용자가 볼 수 있는 실기기 캡처가 없다.

## 성공 기준

- 목차 한 페이지만 보고 사용자가 아래를 판단할 수 있다.
  - 어떤 기능이 출시까지 갔는가
  - 어디서 막혔는가
  - 내가 정해야 할 것은 무엇인가
- 정책 확인이 형식적으로 끝나지 않는다. 사용자가 이해할 수 있고, 모순은 AI가 먼저 짚는다.
- 완료로 표시된 단계는 증거가 링크되어 있다.
- AI 세션이 이 문서를 읽고 작업을 시작한다.

## 하지 않을 것 (Out of scope)

- 앱 코드·DB·배포를 변경하지 않는다. 문서 개편만 한다.
- 날짜별 기록(11/06~11/19 약 35개 섹션)을 지우지 않는다. 「과거 기록(AI 근거 보관용)」 한 페이지로 원문 그대로 옮긴다. 사용자는 보지 않는다.
- 과거 기록 내용을 기능 페이지로 하나하나 옮겨 적지 않는다. 아직 유효한 결정만 뽑아 정책 칸에 넣고, 근거 날짜를 링크한다.
- 지금 없는 실기기 캡처를 이번 작업에서 새로 찍지 않는다. 「증거 없음」으로 표시한다.
- 01~06 작업소별 하위 페이지는 기능 페이지로 바뀐 뒤 과거 기록으로 보낸다. 바로 삭제하지 않는다.
