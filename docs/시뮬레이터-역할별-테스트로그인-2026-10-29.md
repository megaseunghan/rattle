# 역할별 시뮬레이터 테스트 로그인

요청: 관리자·직원·파트타이머 각각 독립된 시뮬레이터에서 실제 계정으로 래틀 데모 매장을 사용한다. S02 로그인 화면에 테스트 전용 버튼을 추가했다. 관리자 미리보기와 달리 실제 Supabase JWT/RLS를 사용한다.

## 구성

| 역할 | 시뮬레이터 | 연결 |
|---|---|---|
| 관리자 | Rattle QA 관리자 | 래틀 매장의 승인된 관리자 멤버 |
| 직원 | Rattle QA 직원 | 가상 직원 김하늘의 기존 기록 |
| 파트타이머 | Rattle QA 파트타이머 | 가상 직원 정지우의 기존 기록 |

기존 매장 소유자를 교체하지 않는다. 테스트 계정 세 개는 래틀 매장에만 소속된다. 기존 급여·급여조건을 추가하거나 수정하지 않고 직원 레코드의 계정 연결만 지정한다. 준비 SQL은 같은 트랜잭션에서 변경 전후 급여와 조건 이력 해시를 비교하며, 다르면 롤백한다. 이 구성은 신규 참여 신청/최종 합류 E2E를 실행한 증거는 아니다.

## 실행

저장소 루트에서 실행한다. 최초 계정 준비는 Supabase CLI에 로그인되어 있어야 한다.

```sh
node scripts/qa/provision.mjs /absolute/path/to/supabase
node scripts/qa/broker.mjs
```

다른 터미널에서:

```sh
node scripts/qa/simulators.mjs
node scripts/qa/build-ios.mjs
node scripts/qa/simulators.mjs --install
node scripts/qa/verify.mjs
```

`build-ios.mjs`는 QA 환경값을 명시해서 iOS 시뮬레이터 Release 빌드를 만든다. `simulators.mjs --install`은 이름이 일치하는 기기를 재사용하고, 시뮬레이터 사본의 iOS 빌드번호를 역할별로 지정한 뒤 재서명한다. 첫 실행은 빌드번호에 맞는 계정으로 자동 로그인한다. 자동 로그인 완료 여부를 로컬 저장하므로 로그아웃 후에는 세 역할 버튼을 직접 선택한다. 이름이 같은 기기를 임의 삭제/초기화하지 않는다. 세션은 일반 로그인과 동일하게 각 시뮬레이터의 SecureStore에 보관된다.

## 경계

- 테스트 버튼은 명시적인 QA 빌드 환경값, iOS, 시뮬레이터 조건이 모두 맞을 때만 표시/동작한다. 일반 빌드와 실기기에서는 사용할 수 없다.
- `.qa/accounts.json`의 테스트 비밀번호는 Mac에만 남고 앱 번들에는 포함되지 않는다. `.qa/`는 Git 제외이며 계정 파일은 권한 600이다.
- 로그인 broker는 `127.0.0.1:18765`에만 바인딩한다. 임의 포트/외부 호스트를 받지 않는다. 무작위 capability 헤더를 요구하고 브라우저 Origin 요청을 거절한다. 선택한 계정의 서버 회원 상태·역할·고용형태를 검증한 뒤 세션을 전달한다.
- Supabase 관리자 키는 준비 스크립트의 메모리에서만 사용한다. 앱이나 broker 구성 파일에 저장하지 않는다.
- broker가 종료돼도 이미 로그인된 앱의 일반 세션 갱신은 Supabase를 통해 진행된다. 로그아웃 후 간편 로그인은 broker를 다시 실행해야 한다.
- 실제 매장 데이터 변경·직원 초대 발송·push·배포는 이 작업에 포함하지 않는다.

## 확인 기록

- 기준: `feature/operations-workflows`, HEAD `1c2281c`에 참여코드 변경과 이번 QA 로그인 변경이 더해진 미커밋 상태.
- 원격 준비 실행: 지정한 데모 매장과 가상 직원에만 계정 연결, 급여/급여조건 해시 보존 통과. 새 스키마 마이그레이션은 없다.
- 실제 계정 API 검사: 세 계정 로그인, 각 계정의 래틀 매장 격리 통과. 직원·파트타이머의 본인 직원 정보/급여만 조회, 관리자 초대 RPC 거절 통과.
- broker: 인증 헤더 없는 요청 및 브라우저 Origin 요청 거절 통과.
- 코드 검토: 보안/권한/오류/범위/비밀정보의 자체 검토. 독립 리뷰로 표시하지 않는다.
- TypeScript 검사 및 로그인 컴포넌트/서비스 테스트 14개 통과.
- 이번 설치본은 2026-10-29 16:47에 실행 확인한 네이티브 Release 바이너리를 복사하고, 현재 JavaScript를 Expo export:embed → Hermes로 재빌드한 뒤 역할별 앱을 재서명했다. 네이티브 의존성 변경은 없다. codesign --verify --deep --strict와 계정 비밀번호 번들 미포함 검사를 통과했다. 전체 네이티브 재컴파일 성공으로 보고하지 않는다.
