# 손익 상세 모션 · UI/UX Pro Max 검증

## 진단과 범위

사용자가 손익 카드가 올라올 때 화면이 어두워지는 동작이 부자연스럽다고 제보했다. 실제 Release 앱의 월별 손익 상세를 수정 전후 비교했다. 이번 검증은 이 상세창의 모션·비율 가독성에 한정하며 앱 전체 모션이 검증됐다는 뜻은 아니다.

원인은 투명 `Modal`의 `animationType="slide"`였다. 카드와 어두운 배경 전체가 한 화면으로 아래에서 올라와, 배경의 가로 경계가 화면을 위로 쓸고 지나갔다. 영상 프레임에서도 상단은 밝고 하단은 어두운 경계가 이동하는 것을 확인했다.

UI/UX Pro Max 로컬 데이터 검색 결과 중 `Reduced Motion`, `Excessive Motion`과 React Native `Run on UI thread` 기준을 적용했다. `modal animation reduced motion` stack 검색은 결과가 없어 `animations`로 한 번 재검색했다. 반환된 RN 데이터의 버전 설명은 설치된 RN 0.83.2와 달라 최신 버전 근거로 사용하지 않았다. 실제 설치된 Reanimated 4.2.1/Worklets의 타입·API와 빌드 결과를 대조했다. 기존 디자인 시스템을 새로 생성하지 않았다.

## 수정

| 요소 | 수정 후 |
|---|---|
| 배경 | 제자리에 고정. 불투명도만 180ms에 걸쳐 증가하고 닫을 때 160ms에 감소 |
| 카드 | 실측 카드 높이를 기준으로 300ms 진입, 200ms 퇴장. 진입은 감속, 퇴장은 가속 |
| 배경 농도 | 상세창 전용 `Colors.overlayDetail`, 45% → 28%. 다른 모달 토큰은 유지 |
| 수명 | `onShow`와 실제 카드 레이아웃 확인 뒤 진입. 닫힘 완료 뒤에만 내용을 해제하고 연속 닫기 요청은 무시 |
| 실행 | Reanimated UI 스레드에서 opacity/translateY 처리. `ReduceMotion.System` 적용 |
| 스크롤 | 중첩 터치 영역 없이 기존 최대 높이·flexShrink·하단 안전영역 유지 |
| 비율 글자 | 11→12pt. 그룹 비율은 gray400→gray600, 하위 비율은 gray300→gray500 |

흰 배경 기준 계산한 비율 글자 대비는 기존 2.54:1·1.47:1에서 각각 7.56:1·4.83:1로 개선됐다. 이는 해당 텍스트/배경 조합 계산이며 화면 전체의 접근성 인증은 아니다.

## 검증

- 같은 iPhone 16 Pro 시뮬레이터 / iOS 26.3 / 동일 창 배율의 빌드된 React Native Release 앱에서 9월 상세를 전후 녹화했다. Safari 시안으로 대체하지 않았다.
- 기존 영상 10.20s 프레임에서 수평 경계가 화면을 이동한다. 수정 후 6.30s·6.40s 프레임에서는 화면 전체가 같은 자리에서 어두워지고 카드만 이동한다. 프레임 사이 시간은 영상 위치이며 새 모션의 지연 시간이나 정밀 성능 측정값은 아니다.
- 실제 9월·10월 상세 열기, 닫기 버튼, 배경 터치 닫기, 다른 월 재진입, 본문 스와이프 후 마지막 영업이익 행과 금액/미확인 문구가 잘리지 않음을 확인했다.
- `npm run typecheck`, `git diff --check`, 관련 `ProfitLossScreen` 테스트 **7개 통과**. 테스트는 닫힘 완료까지 내용 유지·닫기 연타 방지·다른 월 재진입·권한·매장 범위 등을 확인한다. Reanimated는 테스트용 구현으로 대체하며 실제 모션 품질은 네이티브 영상으로 확인했다.
- 코드 리뷰에서 새 차단 결함 없음.
- iOS 동작 줄이기는 시스템 설정을 따르도록 구현하고 설정 전달을 테스트했다. OS 설정을 실제로 켜고 끈 네이티브 검증, VoiceOver 낭독, 다른 기기 크기·가로 화면·Android 검증은 수행하지 않았다.
