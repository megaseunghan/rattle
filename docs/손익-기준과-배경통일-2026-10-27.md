## 확인과 변경

- 캡처 당시 설치본은 작성된 정규직 월 명세 전체를 상세 손익에 사용하고 홈은 현재일까지 누적했다. 10월 27일 기준 정규직 9,200,000원 × 27/31(직원별 원 단위 반올림) + 저장된 파트 급여 1,224,000원 = 9,236,903원. 전체 월 명세 합계는 10,424,000원. 차이 1,187,097원.
- 작업 시작 시 소스에는 이미 `accruedRegularPayroll`을 상세와 직원관리에 사용하는 선행 변경이 있었다. 선행 변경을 이번에 새로 구현했다고 보지 않는다. 이번에 날짜 기준을 한국 날짜로 통일하고 연간 조회 시작 시각을 월별 조회에 전달해 조회 중 날짜 변경도 일관되게 처리했다.
- 연결 해제된 현재월 정규직 명세도 같은 일할 규칙을 적용하고, 미래월의 저장된 파트 급여는 발생 인건비에 합산하지 않는다. 과거월은 명세 `gross` 보존. 저장 명세·급여 조건 원본을 변경하지 않는다.
- 최신 선행 SQL `20261027010000_wage_effective_baselines.sql`의 누적 규칙과 대조했다. 이번 신규 SQL/원격 적용 없음. 이전 작업에서 이 SQL과 `20261027011000_daily_work_snapshots.sql`은 원격 미적용으로 기록돼 있으므로 새 스냅샷·일별 저장 경로는 별도 적용이 필요하다.
- 배경: 직원관리, 재고/레시피 탭, 독립 레시피 목록, 매출, 체크리스트 목록·편집, 마이페이지, 전체매장 대시보드, 상세 손익에 기존 `GlassBackdrop` 재사용. 목록·입력·모달 표면은 불투명 유지. 지정 화면 헤더는 배경이 이어지도록 투명 처리한다.
- 재고/레시피 탭 큰 제목은 두 하위 탭을 볼 수 있는 역할에 `재고 및 레시피`, 재고만 가능한 파트타이머는 `재고`다. 하단 탭 명칭은 짧은 `재고` 유지.

- 후속 사용자 요청: 상단의 빈 근무시간 제출 안내를 제거하고 세후 예상액 고지 한 문장으로 교체. 기존 월 합계 제출이 있을 때의 검토·반영 버튼과 조회 오류/재시도는 유지.

- 추가 후속 요청: `StoreAppBar`를 공통화해 홈·재고·매입·인건비·매출에 같은 더보기/매장전환/알림/마이페이지를 제공한다. 기존 홈 safearea와 비홈 top edge를 보존하고, 비활성 header 접근성을 숨긴다. 매장선택은 기존 가드를 재사용하며 알림 타이머/요청은 공유된다.
