# 전체 매장 대시보드 개선 · S09 / E-S09

사용자 결정: 전체 매장에서는 재무 집계만 보고, 개별 매장을 선택했을 때 스케줄·청소를 표시한다. 매장이 늘어도 세로 카드 목록을 반복하지 않는다.

- 고정된 상단 칩으로 전체 매장/개별 매장을 전환한다. 칩은 가로로 탐색하며 6곳부터 검색을 제공한다. 합계·전기 비교·추세는 같은 선택 범위를 따른다. 칩 선택 자체는 AuthContext의 실제 매장을 바꾸지 않는다.
- 영업이익 금액은 유지하고 하나의 도넛으로 매입·비용·인건비·남은 영업이익을 나눈다. 중앙 매출이나 아래 네 항목을 누르면 세부 카드가 열린다. 전체가 흑자면 매출을 분모로, 적자면 전체 지출 구성을 분모로 하며 손실률은 음수로 표시한다. 매출과 지출을 더해서 하나의 전체로 만들지 않는다. 미확인/음수 비용/금액 불일치는 회색 빈 도넛과 확인 안내로 남긴다.
- 매출: 현금/카드/결제수단 미분류. 매입: 저장 당시 품목 분류별/매입 거래처별 전환. 비용: 이월 유효 고정비·마케팅·시설보수·공과금·예상 카드수수료. 인건비: 기존 손익 규칙의 직원/파트타이머 세전 금액. 미확인 인건비는 null로 보존한다.
- 상세 카드는 항목 선택 후에만 조회한다. 기존 관리자 권한 검증을 거치는 월별 상세를 재사용하고 연간/다매장은 동시 2개로 제한한다. 계정·권한·매장·마감시각·월별 캐시를 쓰고 저장 후 financial 도메인 무효화를 따른다. 최대 4항목씩 넘기며 누락 결제수단·분류 차액을 임의 배정하지 않는다. 요약과 상세가 1원 이상 다르면 차이와 새로고침 안내를 표시한다.
- 전체 매장에서는 스케줄·청소·운영 카드와 해당 조회를 생략한다. 개별 매장에서는 요일별 인원 막대, 선택 요일의 이름·근무시간, 최대 4명 단위 명단을 표시한다. 실제 실근무나 출퇴근 기록이 아니라 예정 근무다. 개별 스케줄 관리와 손익 상세는 선택한 매장으로 전환한 뒤 연다.
- 급여 확인 필요 목록은 한 번에 최대 3곳을 노출하고 나머지는 매장 칩으로 확인한다. 청소/스케줄 실패와 미등록을 구분한다.
