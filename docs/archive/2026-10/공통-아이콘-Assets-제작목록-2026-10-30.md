## 5. 별도 관리할 공식 자산

- Rattle 워드마크·심볼: 브랜드 원본으로 별도 보관. 일반 업무 아이콘과 구분한다.
- Google·Apple·Kakao 로그인: 각 서비스의 공식 브랜드 자산과 제공 규칙에 맞춰 사용한다. Rattle의 입체 스타일로 다시 그리지 않는다.
- Toss POS: 일반 단말기 아이콘과 공식 서비스 로고를 구분한다.

## 6. 권장 제작 순서와 납품

1. 업무용 1차 12종의 스타일 검토 보드 → 선정 참조로 개별 파일 제작.
2. 조작용 핵심 32개 의미를 한 SVG 규격으로 제작. 상태와 터치 영역은 실제 UI에서 검증.
3. 상태 일러스트 8종, 이후 업무 2차·보조 아이콘은 화면 적용 필요에 따라 제작.

한 번에 모든 자산을 PNG로 만들지 않는다. 작은 16~24pt 조작 아이콘은 선명한 벡터로, 입체 일러스트는 48~80pt 이상의 보조 시각물로 구분한다. 실제 표시 크기에서 형태·여백·시각적 무게를 비교하고 접근성 이름은 UI 코드에 둔다.

```text
assets/icons/                 # 제작 및 앱 코드 연결 완료
  navigation/                # 공통 SVG 원본
  business/                  # 업무용 투명 이미지
  status/                    # 상태·빈 화면 이미지
  brand/                     # Rattle 원본
  providers/                 # 공식 로그인·연동 자산
```

등록/수정/부족/선택 상태 때문에 같은 업무 아이콘을 여러 개 중복 제작하기보다 기본 아이콘과 UI 배지·색·라벨을 조합한다. 발주·GPS 출퇴근·인센티브·평가·OCR 등 현재 제품 범위 밖 기능의 자산은 이번 제작에서 제외한다.

## 7. 일괄 제작 결과 — 2026-10-30

- 사용자 참조 보드의 하단 **안 3** 기준: 업무 PNG 16종 + 상태 PNG 8종 = **24종**.
- 공통·보조 SVG 56종 + checkbox/radio 선택 변형 2종 = **58개**. 신규 자산 총 **82개**.
- [납품 안내](../../../assets/icons/README.md), [갤러리](../../../assets/icons/preview.html), [전체 보드](../../../assets/icons/preview-board.png), [파일 목록](../../../assets/icons/catalog.json).
- PNG 원본 24개는 `originals/`에 보존했다. 승인받은 로컬 가공은 알파 0~2/255 픽셀만 정리했고 형태·크기·본체 색은 유지했다.
- PNG 투명도·파일 누락·클리핑 및 SVG 규격 검사 통과. 흰색·블루 배경에 합성해 전체 PNG를 검토했다. 11개의 최소 여백 10% 미만 경고는 남겨 두었고 본체가 잘린 파일은 없었다.
- 공식 자산은 기존 Rattle 앱 아이콘 2개와 Google G 1개만 사본으로 보관했다. 새 Rattle 워드마크·심볼 및 Apple/Kakao/Toss 공식 원본 제작·수집은 하지 않았다.
- 앱 코드 연결을 완료했다. 아래 8절의 검증 범위와 실제 설치본·TestFlight 미실행을 구분한다.

## 8. 앱 화면 적용 — 2026-10-30

- 상단 바·하단 탭·더보기·공통 버튼·등록/수정·설정 등 기존 Ionicons를 사용하던 54개 파일을 `AppIcon` 공통 컴포넌트에 연결했다. 제작된 의미는 SVG로, 제작하지 않은 심볼은 기존 라이브러리로 렌더링한다. 공식 로그인 자산은 유지했다.
- 홈 오픈·영업·마감 카드에 64pt 입체 이미지, 직원/본인 급여 카드에 56pt 이미지를 적용했다. 재고·레시피·직원·매출의 빈 화면과 공통 빈 화면에 72pt 일러스트를 연결했다. 재고 조회 실패는 `load-error`, 추가 조회 중은 이미지 없음으로 구분했다.
- 모든 24개 일러스트는 명시적 이름으로 재사용 가능한 `Illustration`에 등록했다. 아직 해당 상태/큰 이미지 슬롯이 없는 화면에 나머지 자산을 억지로 노출하지 않는다.
- 앱용 256×256 PNG 파생본을 `assets/icons/runtime/`에 생성했다. 총 17,149,047바이트에서 975,743바이트로 줄였고 고해상도 원본은 보존했다. 80pt @3x까지 사용할 수 있다.
- 업무·권한·라우트·알림 배지·탭 활성 색/표시·입력 처리 계약은 유지한다. 체크박스의 선택/미선택은 서로 다른 SVG를 사용한다.
- 검증 기준: `feature/operations-workflows` / `0d04e7860ed7b72af933854e5d347a7b8a23bb09` + 기존 미커밋 작업 + 이번 아이콘 변경. 기존 상단 바/EAS 등의 변경은 보존했다. 원격 최신 상태를 조회하지 않았다.
- TypeScript 검사 및 전체 Jest 90 suites / 537 tests 통과. DailyWorkPanel 테스트에서 act 경고가 출력됐으나 실패는 없었다. 후속 체크박스·런타임 이미지 경로 변경 후 관련 2 suites / 5 tests와 typecheck를 다시 통과했다. 최종 iOS Metro/Hermes export도 통과했으며, 번들 검사는 네이티브 화면 확인을 대신하지 않는다.
- 독립 코드 검토: 선택 체크박스 표시 회귀를 수정한 뒤 미해결 CRITICAL/HIGH/MEDIUM 없음. 24개 런타임 PNG 경로·256px 규격·원본 불변도 확인했다.
