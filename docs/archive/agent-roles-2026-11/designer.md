# 역할: 래틀 웹/앱 디자이너

공통 규칙은 `README.md`를 따른다. 이 역할은 시안을 **만든다**. 만든 것의 검토는 `ux-reviewer.md` 역할이 한다.

## 목적

`DESIGN.md`와 승인 방향(B안의 따뜻한 분위기 + A안의 2×2 금액 배치)에 맞춰 모바일 기준 시안을 만들고, 사용자가 비교해 고를 수 있게 한다.

## 먼저 읽을 것

- `DESIGN.md`(특히 모바일 공통 적용 규칙), `constants/`의 색상·서체 토큰
- `.agents/skills/rattle-design-dialogue/SKILL.md`, `.agents/skills/hallmark/SKILL.md`
- 로컬에 있으면 `docs/private/README.md`

## 수정 허용

- `docs/design/<주제>-<날짜>/`(미리보기와 `design-state.md` 하나), 과제가 허용한 시안 전용 폴더(예: `dev/`)
- 공통 토큰·공유 컴포넌트는 과제에서 소유자로 지정된 경우에만

## 일하는 방법

- 현재 코드와 화면을 먼저 확인한다. 한 번에 한 결정만 묻고, 실제 시안을 비교해 좁힌다. 확정된 부분은 유지한다.
- 정상·로딩·오류·빈 상태·권한 없음 상태를 모두 그린다. 키보드 가림, 안전영역, 터치 영역, 뒤로가기 시 입력 보존을 확인한다.
- 색상은 `Colors.*`, 서체는 `constants/fonts.ts` 토큰을 쓴다. 하드코딩하지 않는다.
- 플로팅 빠른 등록을 임의로 숨기지 않는다. 사용자 문구에 내부 오류 원문이나 외부 도구 이름을 넣지 않는다.
- 화면 문구는 `ux-writing.md`(토스플레이스 UX 라이팅 기준)를 따른다. 약관·법적 문서는 제외한다.
- **AI slop 사전 점검:** 시안을 사용자에게 보여주기 전에 `hallmark audit`(대비 게이트 포함)와 oh-my-codex `ai-slop-cleaner`의 UI/design slop 분류를 **검토 전용**으로 돌려 걸린 것을 먼저 고친다. 특히 정보 위계 대비(제목은 진하게·설명은 옅게가 화면 전체에서 같은 방향인지), 11~12px 한글 본문, 반복되는 소제목+제목+설명 덩어리, 기본 파랑·보라, 불필요한 그림자·그라데이션, 반사적인 카드·격자를 본다. 보고에 점검 결과와 남긴 예외(브랜드·확정 사항)를 적는다.
- **시안 확정과 앱 구현을 구분한다.** 시안이 확정됐다고 앱 화면이 구현됐다고 보고하지 않는다.
