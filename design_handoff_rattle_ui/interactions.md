# Interactions, State & Data

프로토타입은 정적이므로, 아래는 실제 구현 시 붙여야 할 동작 정의입니다.

## 1. 역할과 권한

| 역할 | 접근 가능 | 금액 정보 | 탭 구성 |
| --- | --- | --- | --- |
| 사장님 (owner) | 전 화면 + 다매장 합산 | 전체 | 대시보드(00) 중심, 매장 전환·알림 |
| 직원/매니저 (staff) | 단일 매장 전체 | 전체 | 홈·재고·매입·근태·매출 (5탭) |
| 파트타이머 (parttime) | 홈·근태·청소·재고 | **전부 숨김** | 홈·근태·청소·재고 (4탭) |

권한 체크는 화면 진입 시점이 아니라 **컴포넌트 렌더 시점**에도 적용해야 합니다(같은 재고 화면에서 파트타이머는 단가 필드가 사라짐 — 화면 34).

## 2. 내비게이션 플로우

### 인증 → 온보딩
```
37 카카오 로그인
 ├ 기존 계정 → 소속 매장 있음 → 역할별 홈 (00 / 01 / 31)
 └ 최초 로그인(자동 회원가입)
     ├ 직원으로 참여  → 39 매장 코드 입력 ─────────→ 01 또는 31
     └ 사장님으로 시작 → 40 신규 매장 등록
                          → 43 포스 사용 여부
                             ├ 사용    → 44 서비스코드 안내 (연동 대기)
                             │           ├ 웹훅 도착   → 45 자동입력 확인 → 00
                             │           └ 10분 초과   → 48 실패
                             │                            ├ 다시 시도 → 44
                             │                            └ 직접 입력 → 17
                             └ 미사용  → 17 매장 정보·영업시간 수동 입력 → 00
                          [매출 첫 동기화 완료 감지] → 46 튜토리얼 코치마크 (1회)
```

### 메인 플로우
- 홈(01) → 탭바로 재고(02) / 매입(06) / 근태 / 매출(10) 이동
- FAB → 26 바텀시트 → 04 / 05 / 08 / 09 / 11 / 13
- 홈 좌측 메뉴 → 16 설정, 우측 프로필 → 21 마이페이지
- 홈 상단 매장명 탭 → 19 매장 선택(바텀시트)
- 00 알림 벨 → 38, 12 인건비 → 42 정산 리포트, 18 멤버 관리 → 50 초대 코드
- 24 근태 기록의 개별 항목 → 51 정정 요청
- 31 "스케줄 설정 ›" → 34-1

## 3. 화면별 상태

| 화면 | 상태 | 비고 |
| --- | --- | --- |
| 00 대시보드 | `period: 'month' \| 'year'` | 세그먼트 탭. 전환 시 모든 증감 라벨 `전월 대비`↔`전년 대비`, 수치도 재조회 |
| 01/31 홈 | `now: Date` (1초 또는 1분 간격 갱신), `clockedIn: boolean` | 출퇴근 상태에 따라 버튼 라벨/색 전환 |
| 02/03 재고 | `tab: 'stock' \| 'recipe'` | |
| 04/08/09 폼 | 필드 값 + `categories[]` + `categoryWarning: boolean` | 품목 하나에 카테고리 설정 시 전체 필수 → 경고 표시 및 저장 차단 |
| 06 매입·비용 | `tab: 'purchase' \| 'expense'` | |
| 13 직원 추가 | `employmentType`, `isProbation`, `wageType`, `probationRange`, `deductionRate: number` | 수습 ON일 때만 기간·감액률 슬라이더 노출 |
| 19 매장 선택 | `currentStoreId` | 전환 시 전역 매장 컨텍스트 교체 → 모든 화면 재조회 |
| 22/34-1 스케줄 | `schedule: {[weekday]: {enabled, start, end}}`, `pendingApproval: boolean` | 저장 시 사장님 승인 대기 상태로 전환 |
| 27/33 체크리스트 | `tab: 'open' \| 'close' \| 'weekday'`, `done: {[itemId]: {by, at} \| false}` | 체크 시 사용자명 + 현재 시각 기록. 프로토타입은 localStorage, 실제는 서버 |
| 38 알림 | `filter: 'all'\|'attendance'\|'stock'\|'revenue'`, `readIds: Set` | "모두 읽음" 일괄 처리 |
| 42 정산 | `settlements[]` (각 `status: 'done'\|'pending'`) | "전체 정산 확정" → 모두 done + 명세서 생성 |
| 44 연동 대기 | `status: 'waiting'\|'connected'\|'timeout'` | 폴링 또는 realtime 구독. 10분 타임아웃 |
| 51 정정 요청 | `target: 'clockIn'\|'clockOut'\|'both'`, `newTime`, `reason`, `photo?` | 사유 미입력 시 제출 차단 |
| 52 알림 설정 | 항목별 boolean 6개 | **매장 단위** 저장 (매장 전환 시 해당 매장 값 로드) |

## 4. 애니메이션 / 트랜지션

프로토타입에 있는 것:
- 화면 진입: `fadeUp` — `opacity 0 → 1`, `translateY(18px) → 0`, 0.5s ease-out (목업 전용 데모 애니메이션. 실제 앱에서는 화면 전환 애니메이션으로 대체)
- 44 연동 대기 점: 1s ease-in-out alternate 무한 반복 펄스

실제 앱에 필요한 것:
- 바텀시트(19, 26): 하단에서 슬라이드 업 250~300ms ease-out, 배경 오버레이 페이드
- 코치마크(46): 카드 페이드+스케일 인, 단계 전환은 크로스 페이드
- 토글: 노브 이동 150ms
- 세그먼트 탭: 활성 배경 슬라이드 200ms
- 체크박스 체크: 스케일 팝 120ms
- 출퇴근 성공: 성공 피드백(햅틱 + 토스트)

## 7. 데이터 요구사항

### 사장님 대시보드 (00)
매장별 + 합산 손익, 기간(월/연) 파라미터, 이전 기간 값(증감률 계산용, 전월·전년 동월·전년).
```
{ period, stores: [{ id, name, revenue, expense, operatingProfit, marginRate }],
  total: { revenue, expense, operatingProfit, marginRate },
  prev: { ...same }, prevYear: { ...same },
  attendance: { normal, late, absent, issues: [...] },
  cleaning: [{ storeId, done, total }] }
```
증감률 계산: `(current - prev) / |prev| * 100`. 마진율은 퍼센트포인트 차(`%p`).

### 급여 정산 (42)
직원별 근무시간 집계, 기본급/시급, 공제 항목, **은행명·계좌번호**, 정산 상태.

### 근태
출퇴근 시각, GPS 좌표와 매장 기준점 거리(허용 반경 내 여부), 지각/미출근 판정(스케줄 대비), 정정 요청 이력.

### 알림 (38, 52)
이벤트 종류(근태/재고/매출), 매장, 발생 시각, 읽음 여부. 알림 설정은 매장 단위 6개 플래그.

### 토스 포스 웹훅
`onboarding-toss-pos.md` 참고.

## 8. 반응형

프로토타입은 390px 고정. 실제 앱은:
- 좌우 여백 22px 유지, 콘텐츠는 폭에 맞춰 flex
- 3열 그리드(바로가기, 근태 요약)는 좁은 화면에서 최소 폭 확보 후 2열로 wrap
- 큰 금액 텍스트는 폭 초과 시 축소(`adjustsFontSizeToFit` / `numberOfLines={1}`)
- 캘린더 7열 그리드는 셀 정사각 비율 유지
